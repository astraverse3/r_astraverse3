## 계기

브라우저 확인(C0-a·b·d)에서 사용자가 둘을 짚었다.

1. 톤백 규격 머리가 `톤백 1,000kg`로 뜬다 — 1행 그룹에 이미 `톤백`이 있으니 `1,000kg`만 있으면 된다.
2. 확정해 둔 표기 규칙(`수령인 ｜ 세로선 ｜ 발주처(연한색)`)이 화면에 없다 — 아직 `←발주처` 옛 표기였다.

C0-c는 계획서에 확정만 되어 있고 구현은 이번이 처음이다.

## 주요 결정

- **규칙은 하나, 채널은 순서만** — `nameTiersOf`가 `primary`로 앞뒤를 정하고, 뒤가 없거나 앞과 같으면 한 줄.
  서울급식(`발주처 ｜ 수령인`)은 예외 분기가 아니라 같은 함수의 결과다.
- **앞 값 104px 고정 + `flex-none`**, 뒤 값 `min-w-0 truncate` — 구분선이 모든 행에서 같은 x에 선다.
  `W_NAME 184`는 그대로. 뒤 값에 남는 폭은 약 60px라 긴 발주처는 잘리고 `title`로 전체를 보여준다.
- **구분선 색은 Tailwind 토큰**(`border-slate-300` ≈ `#cbd5e1`, `text-slate-500` ≈ `#64748b`)으로 — 핸드오프의 hex를 인라인으로 박지 않았다.
- **`constantSide`는 선언만** — §6 업로드 검증(백로그)이 읽을 자리. 지금 읽는 곳 없음.
- 톤백 라벨: `packageType` 대신 중량만. 「톤백」은 1행 `packagingName`이 이미 보여준다.

## 추가 — 「여유」 행 정렬 (같은 날, 사용자 결정)

서울급식의 `여유` 행이 가나다 중간(ㅇ)에 끼는 게 어색해 맨 아래로 보내 달라는 요청.
핸드오프 §4-b가 「맨 아래 고정 같은 장식은 버렸다」고 했지만 실무 기준으로 **번복**.

- **채널 예외가 아니라 값 규칙** — 「여유」는 서울급식 속성이 아니라 여분 물량이라는 값의 속성.
  발주처 자리(서울급식)든 수령인 자리(발주처 상수 채널)든 올 수 있어 `isSpareRow`는 양쪽을 본다.
- **이름 정렬 둘(발주처별·수령인 가나다)에서만 맨 아래.** 최신·작업필요는 시간·상태 기준이라 그대로 —
  여유 행에 재고부족이 떴는데 맨 아래로 숨으면 안 된다. (4개 전부 통일은 사용자가 거절)
- `lib/purchase-channel.ts` `SPARE_NAMES = ['여유','여분']` + `isSpareRow()` — 뒤에 §6 상수 검증이 같은 상수를 재사용한다.
- 테스트 3건 추가(`purchase-order-matrix.test.ts`), 265/265.

## 추가 2 — 정렬 4종 → 3종 (같은 날, 사용자 지적)

「최신·작업필요가 안 되는 듯」 + 「한 시트는 발주일·상차일이 같은데 최신이 무슨 의미?」

- **최신 삭제.** 정렬 키 `createdAt`이 시트 안에서 전부 같다(업로드 트랜잭션 한 번). 동률 처리인
  수령인 가나다와 똑같이 떠서 「안 되는 것」처럼 보인 게 맞다. `createdAt`은 lib 입력·행·액션 select에서 제거.
- **작업필요 = 행 상태 심각도순.** 전엔 「완료 아니면 true」 boolean이라 차감 전엔 전 행이 동률.
  화면에만 있던 행 상태 우선순위(`rowStatusOf`)를 lib `ROW_STATUS_ORDER`로 올리고 `MatrixRow.status` 신설.
  화면 상태 점·범례·정렬이 전부 같은 순서를 본다(화면 `ROW_STATUS` 배열 → 라벨·색만 남긴 `ROW_STATUS_META`).
- `needsWork`는 `status !== COMPLETED`로 유지 — 헤더 「N수령인이 작업 필요」 집계용.
- 여유 행 규칙은 그대로(이름 정렬 둘에서만 맨 아래).
- 테스트: 심각도순 5상태 픽스처 + 동상태 가나다 2건 신설, 최신 1건 삭제. 265/265.
