## 2. 주요 결정

1. **선택 모드는 폰 목록 진입일 때만** — 판정은 `ids.length > 1`(목록 푸터는 5건 이상, 택배 펼침 일괄차감은 1건).
   데스크탑 선택 바·건상세 일괄차감은 `gatePick=false`로 **명시**한다.
2. 🔴 **체크를 바꾸면 서버에 다시 묻는다** — FIFO라 한 건을 빼면 재고가 뒤 건으로 간다.
   - 늦게 온 옛 응답은 effect cleanup(`alive`)이 버린다
   - 「지금 체크 상태로 계산한 값인가」를 **키 비교로 파생**(`fresh`) — 아니면 옛 값을 흐리게, 확정 막음
   - 🔴 확정은 **그 미리보기를 만든 건 목록 + 지문** 한 쌍(`result.ids`)으로 보낸다
3. **일괄 대상 없는 건은 체크박스 없이 사유만**, 그러나 서버엔 **그대로 보낸다** — 그 매칭실패가 아래 배너·목록에 계속 보이게.
4. 곁에서 잡은 것: 재고 변경으로 뜬 「다시 계산했습니다」 배너가 따로 된 상태라 **새로 계산해도 눌러앉았다** → 결과에 붙여 새 계산 때 저절로 꺼지게.
5. 문구 — 푸터 `셀 단위로 차감 취소` → `품목 단위로`(폰엔 셀이 없다, M1-5로 카드 취소 경로가 생겼다) ·
   매칭실패 목록 안내 폰 `행을 누르면 그 건으로 이동`.
6. 시안의 매칭실패 행별 「재매칭」 버튼은 **안 만듦** — 재매칭은 묶음 단위라 행별 버튼은 거짓말이다.
7. 🔴 **행에서 kg을 뺐다**(1차 확인에서 사용자 지적). 처음엔 행마다 주문 기준 남은 kg(`10kg`·`21kg`)을 적었는데,
   택배_260818의 작업필요 13건·16품목이 **전부 가용 0**이라 차감 예정이 `0kg`인 화면에서 행은 kg을 말하고 있었다 —
   「0kg 계산이 틀렸다」로 읽혔다(계산은 맞았다). 행 kg을 FIFO 결과로 다시 셈하면 합계와 두 벌이 되므로
   **kg은 위 합계 한 곳**, 행은 서버 미리보기의 부족 목록으로 낸 **상태만**(`gateStateOf` → `재고없음`/`일부 부족`, 정상은 표시 없음).
   다시 계산 중에는 상태를 거둔다(옛 상태를 새 선택에 붙이지 않게).

## 4. 확인이 필요한 사항 (브라우저)

1. 폰 택배 목록 → `작업필요 n건 검토` → 발주처별로 묶여 **전부 체크**
2. 한 건 해제 → 흐려지고 잠시 뒤 **차감 예정 kg·구성이 다시 계산**
3. 「그룹 해제」 → 그 발주처 전부 해제 → 「그룹 선택」으로 복귀
4. 전부 해제 → 「선택된 건이 없습니다」 · 확정 비활성
5. 몇 건 해제한 채 확정 → **체크한 건만** 차감(해제한 건은 목록에 작업필요로 남음)
6. 톤백만 있는 건 — 체크박스 없이 사유
7. 데스크탑 매트릭스 선택 → 게이트: **목록 없이** 예전 그대로 · 폰 건상세·택배 펼침 일괄차감도 목록 없음

⚠️ 알고 둔 차이: 폰 목록이 「발주처별」 정렬이면 그룹을 **건수 많은 순**으로 세우는데, 게이트는 **들어온 순서**(행 정렬 순)로 묶는다. 그룹 순서만 다를 수 있다.
⚠️ `matrix-client.tsx` 597 → 635줄, `review-gate-dialog.tsx` 389 → 510줄(800 상한 안).
