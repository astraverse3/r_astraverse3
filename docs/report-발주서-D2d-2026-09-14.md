## 주요 결정 (계획서 그대로 + 구현에서 정한 것)

- **F 완료 판정은 자루 개수 그대로, 초과 차단만 푼다.** 985kg 자루를 통째 낸 셀이 영원히 「부분」이 되는 걸 피한다. `guard:'open'`은 서버가 라인의 `unitWeightKg`로만 켠다 — 클라이언트 `bulk` 플래그를 믿지 않는다.
- **G 넘치는 자루는 마지막 라인에.** 2자루/라인1 → 라인1에 2 · 2자루/라인2 → 1씩 · 3자루(한 행)/라인2 → 1+2(같은 packageId는 한 건으로 합쳐 `applyAllocations` 왕복을 아낀다).
- **H 쪼개기 = `createRepack` 그대로.** `results` 둘 다 `packageType:'톤백'`·`packagingId:null` → 서버가 톤백 포장지를 강제하고 같은 SKU로 돌아온다. `confirmDialog`로 「되돌리기 없음」을 먼저 알린다. 결과 행 id가 안 돌아와서 **재조회 후 「그 중량·`repackId` 최신」으로 찾아 자동 체크** — 못 찾으면 체크 없이 목록만 갱신.
- **후보 정렬 기준 = 남은 요구 kg**(요구 − 기차감). 이미 넘겼으면 0 근처(작은 자루 우선).
- **차이 표시 임계 ±1%**(§40 예시). 색만 바꾼다. 587+450 두 자루(+37, +3.7%)도 확정된다.
- 팝오버 껍데기(Popover·Head)는 D2c 것을 그대로 쓴다. `tonbag-popover.tsx` ↔ `cell-allocation-popover.tsx`가 서로 import(TonbagBody / CancelButton·ActiveCell)한다 — 함수 선언이라 ES 모듈 순환에 문제없지만, 다음 팝오버(D2e)가 붙을 때 공용 조각을 `cell-popover-parts.tsx`로 빼는 게 낫다.
