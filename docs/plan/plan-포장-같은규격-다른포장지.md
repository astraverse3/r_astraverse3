# 계획서 — 포장 다이얼로그: 같은 규격 · 다른 포장지 줄 (백로그 §98)

작성: 2026-10-02

## 목표

도정 포장 다이얼로그에서 **규격은 같고 포장지만 다른 줄**(예: 10kg 일반 포대 30개 + 10kg 한살림 포대 20개)을 등록할 수 있게 한다.

## 원인

`app/(dashboard)/milling/add-packaging-dialog.tsx` `addToGroup`(436행):

```ts
const existingIndex = outputs.findIndex(o => o.packageType === label && o.stockId === stockId)
if (existingIndex !== -1) { /* 새 줄 대신 개수 +1 */ }
```

규격 버튼을 다시 누르면 같은 재고·같은 규격 줄의 **개수만 늘린다**. 줄마다 포장지를 고르게 된 건 2026-06-17(`c7b03d5`)인데,
그 전부터 있던 「규격으로 합치기」가 포장지를 안 보고 그대로 남았다.

서버(`updatePackagingLogs` — 행 id 기반 diff)와 DB(`MillingOutputPackage` 유일 제약 없음)는 같은 규격 두 줄을 막지 않는다. **화면만 고치면 된다.**

## 바꿀 동작 (추천안)

| 상황 | 지금 | 바꾼 뒤 |
|---|---|---|
| 그 규격 줄이 없을 때 규격 버튼 | 새 줄 + 기본 포장지 추천 | 그대로 |
| 그 규격 줄이 **이미 있을 때** 규격 버튼 | 그 줄 개수 +1 | **새 줄을 하나 더** — 포장지는 비워 둔다(「포장지 선택」). 다른 포장지를 쓰려고 누른 거라 기본값을 채우지 않는다 |
| 개수 늘리기 | 규격 버튼 다시 누르기 · 줄의 ± · 개수칸 | 줄의 ± · 개수칸 (둘 다 이미 있다) |
| 저장 | — | 같은 재고·규격·**포장지**가 두 줄이고 그중 **새 줄**이 있으면 막는다: 「10kg 줄 두 개가 포장지까지 같아요. 한 줄로 합쳐 주세요.」 |

- 톤백·잔량은 지금도 누를 때마다 새 줄이다(자루·자투리마다 무게가 다름) — 손대지 않고, 겹침 검사에서도 뺀다.
- 겹침 검사는 **화면만** 한다. 같은 포장지 두 줄은 SKU가 깨지는 게 아니라 지저분할 뿐이라(§54 「포장지 없음」과 다르다) 서버까지 막을 이유가 없다.
- **이미 저장된 줄끼리** 겹친 건 막지 않는다 — 둘 다 차감이 붙어 있으면 합칠 방법이 없어 저장이 영영 막힌다.

### 다른 안 (안 고른 이유)

- B. 규격 버튼은 무조건 새 줄 + 기본 포장지 추천 → 같은 포장지 두 줄 실수가 매번 난다.
- C. 줄마다 「같은 규격 한 줄 더」 버튼 → 모바일 줄이 이미 꽉 찼다(§87 T3 B안).

## 단계

1. `duplicatePackagingLines` + 테스트 (먼저 실패하는 테스트)
2. 다이얼로그 `addToGroup` 분기 · 추천 함수 분리 · 첫 빈 줄만 채우기
3. `collectValidOutputs`에 겹침 검사 (포장지 없음 검사 다음)
4. `npx tsc --noEmit` · `npx eslint .`(0/0 유지) · `npx vitest run`
5. 사용자 화면 확인 — 10kg 누르고 → 10kg 다시 누르면 「포장지 선택」 빈 줄이 생기는지 · 다른 포장지 골라 저장 → 제품재고에 두 줄 · 같은 포장지 고르면 저장이 막히는지 (PC·모바일)

## 확인할 것

- 규격 버튼을 **연타해서 개수를 세던** 사람이 있으면 이제 빈 줄이 늘어난다(저장 땐 「개수 없는 줄」이 아니라 「포장지 선택」으로 막힘). 현장에서 그렇게 쓰는지 사용자 확인 필요.
