# M1-5 — 폰 라인 탭 → FIFO 배분 바텀시트

상위 계획: `plan-발주서판매처리-M1.md` §M1-5 · 시안: `docs/handoff/발주서판매처리/모바일-건별리스트-핸드오프.md` §6,
`건처리-건별리스트-모바일.html` ⑥

## 1. 목표

폰에서 **라인 카드를 누르면** 그 품목의 배분 화면이 바텀시트로 뜬다.

🔴 **왜 지금인가** — 폰에는 셀이 없어(`hidden sm:contents`) 셀 팝오버로 가는 길이 0개다. 그래서 지금 폰에서는
- 톤백 건을 처리할 방법이 없다(푸터·게이트가 「PC에서 자루를 고르세요」로 떠넘긴다)
- **차감 취소도 할 수 없다**(완료 셀 팝오버의 「차감 취소」가 유일한 경로)
- 일괄차감이 추천한 FIFO를 손볼 수 없다

## 2. 코드 대조 결과 (구현 전)

| 시안·계획서 | 현재 코드 | 처리 |
|---|---|---|
| Body(`TonbagBody`·`UnmatchedBody`) 재사용 | 이미 분리돼 있다 | ✅ 그대로 |
| 「다른 로트 추가」 버튼 | 후보를 **전부** 이미 보여 준다 | ❌ 시안이 낡음 — 안 만든다 |
| 로트번호 `260805-11-…7741` 말줄임 | **일부러 줄바꿈**(잘리면 로트·생산자를 못 읽는다) | ❌ 현행 유지 |
| 부족 안내를 **상단** amber 띠로 | 버튼 바로 위(푸터)에 있다 | 현행 유지 — 버튼 옆이 결정하는 자리 |
| 버튼 `59개 부분 차감` | `이 셀 차감 확정 · n개` | 시트에서만 바꾼다 — **폰엔 「셀」이 없다** |
| 수량 버튼 44×44 | `h-6 w-6`(24px) | 시트에서만 44 |
| 🔴 (시안에 없음) | **셀 하나 = 라인 여럿**일 수 있다(`buildRow`가 같은 규격을 합친다) | §3-B |
| 🔴 (시안에 없음) | 건상세가 이미 `Sheet`다 → **시트 위에 시트**(중첩 모달) | §3-C |

## 3. 결정

### A. 시트냐 팝오버냐 = **진입점이 정한다** (추천)

- 매트릭스 **셀** 탭 → 지금 팝오버 그대로(데스크탑 전용 경로라 변화 0)
- **라인 카드** 탭 → 바텀시트. `ActiveCell.anchor`가 `null`이면 시트다
- 브레이크포인트를 JS에 복제하지 않는다(전례: `offsetParent` 판정). 폭을 재지 않으니 SSR 걱정도 없다
- 부수효과: **데스크탑 건상세 패널의 카드도 눌린다.** 시트는 `sm:`에서 패널 폭(468px)으로 오른쪽 아래에 붙여
  패널 안에서 올라오는 모양이 되게 한다 — 데스크탑에서 전체 폭 시트가 뜨는 일은 없다
- ⚠️ 대안: 데스크탑 패널 카드는 누를 수 없게 막기 → 막으려면 결국 폭을 재야 해서 비추천

### B. 카드 탭은 **그 라인 하나**(`[itemId]`)를 연다 (추천)

셀 전체(`cell.itemIds`)를 열면 같은 규격 라인이 둘인 건에서 **카드 숫자(라인 하나)와 시트 숫자(합계)가 달라진다.**
서버 액션(`getCellAllocation`·`getBulkCellOptions`·`confirmCell`·`cancelCell`)은 원래 `itemIds[]`를 받으므로
배열 길이만 1이 된다 — **서버 변경 0**.

### C. 중첩 모달 — 게이트 때와 같은 한 쌍으로 막는다

[[modal_close_order_outside_click]]의 교훈 그대로다.
1. 건상세 `blockOutsideClose={gateOpen || active !== null}` — 시트 안을 누른 게 패널의 「바깥 클릭」이 되지 않게
2. **닫기는 `setTimeout 0`으로 미룬다** — 시트의 X를 누르자마자 `active`를 지우면 가드가 그 자리에서 풀리고,
   같은 click이 패널까지 올라와 패널이 닫힌다(터치일 때 Radix가 판정을 click으로 미룬다)
3. ⚠️ 「차감 취소」 확인창(`confirmDialog`)이 **세 번째 층**이 된다 — 실기기 확인 항목에 넣는다

### D. 문구 — PC로 떠넘기던 두 곳

- 건상세 푸터 `톤백은 PC에서 자루 선택` / `톤백은 셀에서 자루 선택` → **`톤백은 품목을 눌러 자루 선택`** 한 벌
  (이제 폰·데스크탑 둘 다 카드가 눌리므로 CSS 분기가 필요 없다)
- 게이트 `PC에서 자루를 고르세요.` → 폰 **`품목을 눌러 자루를 고르세요.`** (데스크탑 `셀을 눌러 처리하세요.` 유지)

## 5. 단계

1. 팝오버 파일에 시트 분기 + 컨텍스트 (톤백 본문 포함)
2. 카드 `onOpen` + 두 진입점 연결 + 가드·지연
3. 문구 2곳
4. `tsc` · `eslint` · `test` → 브라우저 확인 요청

## 6. 확인 항목 (사용자 브라우저 · 실기기)

1. 폰 건상세 → 일반 라인 탭 → 시트, `−/+` 44px, 확정 → **패널은 열린 채** 숫자 갱신
2. 폰 건상세 → **톤백** 라인 → 자루 선택 → 확정 (시아스)
3. 폰 완료 라인 → 시트 → 「차감 취소」 → 확인창 → 복원 · 🔴 **확인창에서 「취소」를 눌렀을 때 시트·패널이 안 닫히는지**
4. 시트 X / 딤 탭 / 아래로 쓸기 — **셋 다** 시트만 닫히고 건상세는 남는지(「닫는 방법에 따라 다르다」가 지문)
5. 택배 펼침 카드 탭 → 시트
6. 후보 많은 라인 — 시트 안에서 목록만 스크롤되고 **푸터 버튼이 보이는지**
7. 데스크탑: 셀 팝오버 그대로 · 패널 카드 탭 → 패널 폭 시트
8. 매칭실패 라인 탭 → 안내 시트
