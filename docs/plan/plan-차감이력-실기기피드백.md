## 목표

1. 되돌리기 버튼이 행에서 차지하는 몫을 줄인다.
2. 잘린 사유·거래처를 **모바일에서 읽을 수 있게** 한다.
3. 재포장 행에서 **안내 문구를 걷어내고 그 자리에 「무엇이 나왔는지」를 넣는다.**

---

## ③-6이 핵심이다 — 왜 지금 문구가 잘못됐나

지금 재포장 행은 이렇게 나온다:

```
26-09-08  [재포장]  2개                          🔒
작업자 문희준
재포장으로 나간 차감은 취소할 수 없어요. 되돌리려면 재포장으로
만든 재고를 다시 재포장해 원래 규격으로 합쳐주세요.
```

- **같은 문구가 재포장 행마다 반복된다.** 스크린샷에서 두 행이 연달아 같은 두 줄을 뿌리고 있다.
- 이 문구는 **「왜 버튼이 없나」에 대한 답**이다. 한 번 알면 두 번째부터는 자리만 차지한다.
- 정작 **「그래서 뭐가 됐는데?」** 는 이 화면 어디에도 없다. 20kg 2개가 빠져나가 무엇이 됐는지
  알려면 사용자가 재포장 화면을 따로 열어야 한다.

### 데이터는 이미 있다 (신규 스키마·마이그레이션 불필요)

```
PackageMovement.repackId ──> Repack.results : MillingOutputPackage[]
                                  └ packageType · count · weightPerUnit
                             Repack.sources : PackageMovement[]   ← 병합 여부 판정용
```

`prisma/schema.prisma:472` (`repackId`) · `:508` (`results`). **조회만 추가하면 된다.**

### 표시할 문구

```
26-09-08  [재포장]  2개                          🔒
→ 10kg × 4 · 잔량 3kg × 1        작업자 문희준
```

- 규격 표기는 `describeDeduction`(`lib/package-guard.ts:63`)의 어법을 따라 `규격 × 개수`.
- 결과가 3종을 넘으면 `외 N종`으로 접는다(행 높이를 지킨다).
- 🔴 **병합 재포장 주의** — 소스가 여러 행이면 `results`는 「이 행이 만든 것」이 아니라
  **「그 재포장 작업 전체의 결과」** 다. 그때는 앞에 `합쳐서 →` 를 붙여 오해를 막는다
  (`Repack.sources.length > 1`로 판정).

### 안내 문구는 어디로 가나

- **자물쇠 아이콘은 남긴다** — 되돌릴 수 없다는 신호 자체는 필요하다.
- 문구는 **자물쇠를 눌렀을 때**만 뜬다(탭 → 그 행 아래 한 줄로 펼침, 다시 누르면 닫힘). **확정(2026-09-09 사용자 선택).**
  데스크탑은 지금처럼 `title` 툴팁도 함께 남는다.
- 발주서 차감(`ORDER_CANCEL_BLOCKED`)도 같은 규칙으로 통일한다.

## ③-2 — 잘린 글자를 볼 방법이 없다

지금 사유·거래처 줄은 `truncate` 한 줄이고, 전체는 **`title` 속성에만** 있다.
`title`은 마우스 호버로 뜨는 물건이라 **모바일에선 열 수가 없다.** ①(차감)에서 로트를
자르지 않기로 한 것과 같은 문제다.

**처방(확정)**: 모바일에선 **자르지 않는다.** 데스크탑은 컬럼 정렬이 우선이라 한 줄 `truncate` + `title` 유지.

> ⚠️ **처음 계획은 `line-clamp-2` + 탭 펼침이었다. 구현 직전에 바꿨다.**
> 「넘칠 때만 펼침 버튼을 보인다」를 하려면 `scrollHeight > clientHeight` **DOM 측정**이 필요하고,
> 그 결과를 state에 넣는 순간 이 저장소가 쓰는 `react-hooks/set-state-in-effect` 룰에 걸린다.
> 측정을 포기하면 안 넘치는 행에도 펼침 힌트가 붙어 더 지저분해진다.
> **①에서 이미 답을 냈다 — 「자르느니 줄을 늘린다」.** 같은 화면에서 규칙이 둘일 이유가 없다.
> `note`는 최대 500자지만 실제 값은 거래처 + 짧은 메모이고, 다이얼로그 본문은 어차피 스크롤된다.

## ③-1 — 되돌리기 버튼 크기

현재 `h-8` + 아이콘 + 「되돌리기」 4글자 ≈ **90px**. 행 가로의 약 28%다.

**A안 = 확정(2026-09-09 사용자 선택)** — 모바일만 아이콘 버튼(`h-8 w-8`), 데스크탑은 지금대로 라벨 유지.
- 막힌 행의 자물쇠(`h-8 w-8`)와 **좌우 폭이 정확히 같아져** 행 끝이 가지런해진다.
- 되돌리기는 **누르면 확인 다이얼로그가 뜨는** 동작이라(`confirmDialog`) 오탭 위험이 낮다.

**B안** — 라벨은 두되 작게(`h-7`, 글자 11px, 아이콘 축소) ≈ 72px.
- 발견성은 지키지만 20px 남짓밖에 못 줄인다.

> 🔴 **A안은 「되돌리기가 있다」는 사실의 발견성을 낮춘다.** 아이콘만 남으면 처음 보는 사람은
> 무슨 버튼인지 모른다. 실제로 얼마나 자주 쓰는 기능인지에 따라 답이 갈리므로 **확인이 필요하다.**

### ⚠️ 성능 — N+1을 만들지 않는다

`listMovements`는 한 패키지의 이력만 조회하므로 행이 많아야 수십 개다.
그래도 행마다 `Repack`을 따로 읽으면 왕복이 늘어난다
(🔴 [[project_order_sales_feature]]의 **「루프 안 왕복은 20회가 한계」** 교훈).

→ `repackId`를 모아 **`findMany({ where: { id: { in: [...] } }, include: { results, _count: sources } })` 한 번**으로 읽고 메모리에서 붙인다. **왕복 2회 고정.**
