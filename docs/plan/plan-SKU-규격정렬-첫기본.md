# 계획서 — 제품유형 규격순 정렬 · 첫 SKU 자동 기본 (백로그 §88 · §89)

작성 2026-09-30

## 목표

1. **§88** 제품유형(SKU) 관리 화면의 목록을 **규격순**으로 세운다. 지금은 규격이 문자열 정렬이라 `10kg · 1kg · 20kg · 3kg · 500g · 5kg · 톤백`처럼 뒤죽박죽이다
   - 같은 결함이 포장 다이얼로그의 **규격별 합계 밴드**에도 있다(§21 ⑥ — 고정 목록에 없는 907g 같은 SKU 규격이 순위 99로 잔량 **뒤**에 붙는다). 같은 비교 함수 한 벌로 같이 푼다
2. **§89** 관리 화면에서 SKU를 새로 만들 때, 그 (품종+도정+규격)에 **활성 기본이 없으면 자동으로 기본**으로 만든다. 도정 포장 저장 경로(`findOrCreateProductType`의 `promoteDefaultIfNone`)와 규칙을 맞춘다

## 정렬 규칙 (결정)

**톤백 → 무게 내림차순(20kg … 1kg · 907g · 500g) → 무게를 못 읽는 규격(가나다) → 잔량**

- 포장 다이얼로그의 규격 버튼(`PACKAGE_TEMPLATES`)과 같은 방향이다. 화면마다 방향이 다르면 또 「뭔지 모르겠다」가 된다
- 무게는 `lib/package-spec.ts` `specWeightKg` 한 벌로 읽는다(907g → 0.907). 따로 만들지 않는다

관리 화면 전체 순서: **품종(가나다) → 도정구분(가나다) → 규격(위 규칙) → 기본 먼저 → 포장지명(가나다)**. 서버 `orderBy`는 그대로 두고 화면에서 정렬한다(규격 무게는 DB가 모른다).

## 하지 않는 것

- **수정(id 있음)** 은 안 건드린다 — 사용자가 기본을 일부러 끈 경우를 되돌리면 안 된다
- 활성 기본이 있는 조합에 새 SKU를 넣으면 지금처럼 기본 아님(사용자가 다른 포장지를 추가한 것)
- 서버 `listProductTypes`의 `orderBy`, 포장 다이얼로그의 규격 **버튼** 순서(`mergeSpecButtons`)는 그대로
