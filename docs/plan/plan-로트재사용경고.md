## 0. 조사 결과

로트 = `YYMMDD-품목코드-인증번호-개인번호`. 같은 농가·품종·인증이면 **앞 6자리(입고일)만 다르다** → 사흘에 나눠 들어오면 로트가 셋.
제품 로트도 포장할 때 `stock.incomingDate`로 다시 계산한다(`milling.ts:404`·`:688`·포장 다이얼로그). 그래서 **입고일이 곧 로트**다.

### 왜 A안(입고일을 첫 로트 날짜로)으로 가도 되나 — 사용자 지적

- 벼 등록 화면의 칸 이름이 이미 **「입고일자 (Lot 기준)」**([add-stock-dialog.tsx:232](../../app/(dashboard)/raw-stocks/add-stock-dialog.tsx#L232))다. 설계부터 로트 기준일이다
- 입력한 시각은 `Stock.createdAt`에 자동으로 따로 남는다
- 벼의 `incomingDate`는 **통계·검색 조건에 안 쓰인다** — 로트 계산과 목록·엑셀 표시뿐. 5/20 보고서 §6.1의 「입고 통계가 몰린다」 걱정은 벼엔 해당이 없다
- ⚠️ 단 `createdAt` = 「입력한 시각」이지 「벼가 들어온 날」은 아니다. 엑셀 가져오기·늦게 입력한 건은 둘이 다르다(알고 가는 한계)

→ **DB 변경 없음.** 로트 계산 7곳도 안 건드린다. 등록할 때 입고일만 첫 로트 날짜로 맞추면 끝.

## 1. 규칙

- **「같은 로트 후보」**: 같은 생산연도 · 같은 생산자 · 같은 품종이고 **로트 뒷자리(품목코드-인증번호-개인번호)가 같은** 기존 벼 원물
  - 뒷자리로 비교하면 인증(작목반)이 바뀐 경우가 자동으로 걸러진다. 관행(로트 없음)은 대상 아님
- **「첫 로트」**: 후보 중 입고일이 가장 이른 것
- **안내하는 때**: 후보가 있고 **새 입고일이 첫 로트보다 늦을 때.** 같은 날이면 이미 같은 로트. 더 이르면(소급 입력) 새 로트로 둔다

## 2. 결정할 것 (추천 먼저)

### ① 안내 방식 — 등록은 **톤백 한 개씩 저장하고 창이 닫힌다**

| | **Y. 입고일자 칸 바로 아래 안내 (추천)** | X. 저장 누를 때 경고창 |
|---|---|---|
| 모양 | 생산자·품종을 고르면 칸 아래에 「이 농가 IPS 26년산 로트가 이미 있어요 — 첫 입고 10/20 (3건) **[10/20으로 맞추기]**」 | 저장 시 「같은 로트로 묶을까요? [같은 로트로] [새 로트로]」 |
| 장점 | 저장 전에 보이고, 눌러서 맞추면 끝. 톤백 20개면 20번 누르긴 해도 **창이 안 가로막는다** | 놓칠 수 없다 |
| 단점 | 안 보고 저장하면 새 로트가 생긴다 | **톤백마다 창이 뜬다** — 20개면 20번. 반복되면 습관적으로 넘기게 된다 |

(둘을 섞을 수도 있다 — Y로 안내하고, 맞추지 않은 채 저장하면 X로 한 번 더. 필요하면 말해줘)

### ② 엑셀 가져오기 — 행마다 물을 수 없다

- **추천 — 자동으로 첫 로트 날짜에 맞추고, 미리보기에 「첫 로트에 맞춤 N건」을 보여준다.** 미리보기 → 확정 흐름이 이미 있다. 파일 안에서 같은 농가·품종이 여러 날짜면 파일+DB 중 가장 이른 날로
- 대안: 가져오기는 지금처럼 파일 날짜 그대로(이번 범위 밖)
