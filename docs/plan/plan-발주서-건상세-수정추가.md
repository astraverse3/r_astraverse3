## 범위 — 2단계로 나눈다

### 1단계: 수정·취소 (작다)

- **건 상세 머리에 「고치기」 토글**을 둔다. 켜면 줄 카드마다 수량 입력칸과 「품목 취소」가 나온다.
  - 줄 카드를 누르면 배분 시트가 열리는 동작(M1-5)과 겹치지 않게, 평소에는 지금 그대로 두고 고칠 때만 모드를 바꾼다.
- **수량 수정** `updateOrderItemQty(itemId, qty)`
  - `qty < 차감된 수`면 거부한다: 「N개 차감됨 — 먼저 차감을 취소하세요」
  - `qty = 0`은 품목 취소와 같다(차감이 0일 때만).
- **품목 취소**: 그 건의 마지막 품목이면 **건 취소로 처리**한다(빈 건이 남지 않게). 확인창에서 그렇다고 알린다.
- **건 취소** `cancelOrder(orderId)`: 건 상세 푸터 ⋮ → 「이 건 취소」. 차감이 하나라도 있으면 막는다.
  - 기존 `deletePurchaseOrder`를 고쳐서 쓴다(`orderCount` 감소를 같은 트랜잭션에).
- **같이 맞춰야 할 저장값 2개**(같은 트랜잭션에서):
  - `PurchaseOrder.status` — 줄 집계의 파생값 → `recalcOrderStatus`
  - `PurchaseOrderUpload.orderCount` — 건 수 → 건 취소면 −1
- **경합**: 쓰는 순간 그 줄의 차감 합을 다시 세서 조건을 확인한다(누가 막 차감했으면 거부).
- **갱신**: 성공하면 `router.refresh()` — 서버가 새 입력을 내려주고 매트릭스·건 목록·검토 게이트가 그 값으로 다시 맞춰진다(기존 「prop 변화 감지」 패턴, `matrix-client.tsx:88`). 1~1.5초. 드문 작업이라 패치 경로를 따로 짓지 않는다.
- **감사로그**: 이전 값 → 새 값, 발주처·수령인·품목.

### 2단계: 추가 (중간)

- **품목 추가**(건 상세의 「+ 품목 추가」) `addOrderItem(orderId, productTypeId, qty)`
  - 고르는 건 **등록된 활성 SKU 목록**(품종 이름으로 거르는 검색 목록 — 「서농22호 현미 5kg PP마대」). 품종→도정→규격→포장지 단계 셀렉트는 쓰지 않는다(D2e 결정 P: 단마다 막다른 골목이 생긴다).
  - 저장할 원본 값(`rawItemName`·`packageType`·`rawPackaging`)은 SKU에서 만들고, **매처로 다시 돌려 그 SKU가 나오는지 검증**한다. 안 나오면 거부한다(SKU를 정하는 경로는 매처 하나 — 오늘 머리글 수정과 같은 원칙). 그래야 나중에 재매칭을 눌러도 줄이 엉뚱하게 움직이지 않는다.
  - 그 건에 같은 SKU 줄이 이미 있으면 거부하고 「수량을 고치세요」라고 안내한다(같은 칸에 두 줄이 생기지 않게).
  - 처음 보는 규격이면 매트릭스에 **열이 저절로 생긴다**(매트릭스는 줄 목록으로 다시 그려진다).
- **주문(수령인) 추가**: 매트릭스 머리·폰 건 목록 머리의 「+ 주문 추가」 → 발주처·수령인·**첫 품목과 수량까지 한 번에** 받는다(빈 건이 생기지 않게). `orderCount` +1.
  - 수령인 칸이 없는 채널(시아스형, 수령인 = 발주처)은 수령인 기본값을 발주처로 한다.
- 톤백(자루중량 축)은 2단계에서도 뺀다.

## 폰 — 택배는 건 상세가 없다

폰에서 **택배만** 건 상세를 열지 않고 목록 안에서 펼친다(`lib/purchase-channel.ts` `detail: 'inline'`). 그래서 택배는 펼친 줄 아래에 **「고치기」 버튼을 두고, 누르면 그 건의 건 상세를 연다**. 고치는 곳은 건 상세 하나로 유지한다. PC는 모든 채널에서 매트릭스 이름 칸을 누르면 건 상세가 열린다.

## 일으킬 수 있는 문제와 막는 법

| 위험 | 막는 법 |
|---|---|
| 차감된 것보다 수량을 줄임 → 판매 기록이 주문보다 많아짐 | 서버가 거부. 차감 취소부터 |
| 저장된 파생값(`status`·`orderCount`)이 어긋남 → 시트 목록 진행률·건수가 틀림 | 같은 트랜잭션에서 다시 계산. `deletePurchaseOrder`의 기존 누락도 같이 고친다 |
| 동시 작업(한 사람은 차감, 한 사람은 수량 수정) | 쓰는 순간 차감 합을 다시 세서 조건 확인 |
| 원본 엑셀과 DB가 달라짐 | 감사로그 + 「시트 내보내기」 엑셀이 DB 기준 증빙. 시트를 지우고 같은 엑셀을 다시 올리면 수정 전으로 돌아간다(안내) |
| 9/1 포장 입력 소실 같은 「낡은 화면이 통째로 저장」 | 해당 없음 — 줄 하나씩 서버에 보내는 액션이라 다른 줄을 지우지 않는다 |
| 추가한 품목을 매처가 못 읽음 | 저장 전에 거부(드물다 — 품종명 + DB 도정값으로 이름을 만든다) |
