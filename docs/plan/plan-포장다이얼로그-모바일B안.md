작성 2026-09-30

## 목표

도정 포장 다이얼로그(`add-packaging-dialog.tsx`)의 **모바일(`sm` 미만) 화면을 누르기 쉽게** 만든다. 지금은 스테퍼 버튼·삭제 버튼이 22px, 규격 버튼이 28px이고 글자는 9~11px이다.

- 근거: 디자이너 작업지시 `docs/handoff/점검-2026-09/작업지시-3-디자인결정.md` T3, 시안 `시안/design-audit-parts.jsx`의 `PackB`(편집)·`PackRO`(마감됨·조회 전용)
- 사용자 방침(9/30): 시안은 **의도만 차용**한다. 빠진 경우와 세부 수치는 현재 코드를 기준으로 우리가 채운다
- 🔴 **표시층만 바꾼다.** 이 다이얼로그는 9/1 포장 소실 사고의 무대다. 상태·저장·diff·baseline·재조회(P3~P5)·충돌 합치기는 **한 줄도 안 건드린다.** 핸들러(`updateCount`·`setCount`·`setWeight`·`setPackaging`·`removePackage`)는 그대로 두고, 새 행이 그 핸들러를 받아 쓴다

## 바뀌는 모습 (모바일)

**① 규격 버튼**: 28px·11px → **36px·13px**, 간격 4 → 6px. 「기타」는 점선 외곽선(지금과 같음)

**② 편집 행**: 1행 `[규격+포장지 셀] [스테퍼] [중량] [삭제]`
- **규격+포장지 셀**: 40px 높이 외곽선 박스에 2줄. 윗줄은 규격(13px semibold), 아랫줄은 포장지명(11px slate-500, 말줄임) + ▾. **셀 전체가 포장지 선택**이다
- 스테퍼: − / 숫자 / + 각 40px, 숫자는 16px mono bold
- 중량 50px(13px mono bold, kg 생략. 단위는 헤더에 적는다), 삭제 40×40
- 빈 경우 (시안에 없음, §87 사용자 답):

| 규격 | 셀 아랫줄 | 스테퍼 자리 | 중량 자리 |
|---|---|---|---|
| 일반 | 포장지명 ▾ (없으면 rose 「포장지 선택」 — §54) | 스테퍼 | 합계 표시 |
| 톤백 | 「톤백」 고정, 트리거 없음 | 스테퍼 | **kg 입력칸**(16px) — 자루마다 1,004~1,005kg처럼 달라서 지금도 입력칸이다 |
| 잔량 | 「포장지 없음」, 트리거 없음, 윗줄 yellow-800 | **kg 입력칸**(16px) — 수량이 늘 1이다 | 합계 표시 |
| 불러오는 중·추천 대기 | 회전 아이콘(지금과 같음) | 스테퍼 | 합계 |

**③ 읽기 전용 행** (마감됨 또는 권한 없음): 3열 `[규격 뱃지 + 포장지명 1fr] [수량 52] [중량 56]`, 36px, 누를 곳 없음

**④ 컬럼 헤더**: 모바일에도 헤더 한 줄을 새로 둔다(편집 「규격 · 포장지 / 수량 / 중량(kg)」). 11px slate-500

## 🟡 정할 것 (추천안 먼저)

1. **PC도 같이 바꿀 범위** — 작업지시는 「PC는 유지」다. 추천은 이렇게 나누는 거야:
   - **모바일만**: ①②③④(규격 버튼·행·헤더)
   - **PC도 같이**: ⑤ 중 **조회 전용 총량 표시와 「🔒 마감됨」 뱃지**(기능 공백이라 PC에도 없다. 버튼 크기는 모바일만 키운다) · ⑥ 합계 밴드(한 컴포넌트를 둘이 같이 쓰고 색·글자만 바뀐다) · PC 헤더 9px → 11px(백로그 §34가 같이 풀린다)
2. **글자 크기 표기** — 타입 토큰(`text-caption` 등, T2)은 사용자가 「다시 얘기하자」고 한 상태다. 추천: 이번엔 **지금 코드처럼 `text-[11px]` 식**으로 쓰고, T2 때 한꺼번에 바꾼다
3. **셀 전체를 포장지 선택으로 만드는 방법** — 추천: **네이티브 `<select>`를 셀 위에 투명하게 덮는다.** 폰에서 OS 선택창이 떠서 지금과 같고, 저장 값도 같은 `setPackaging`으로 들어간다. ⚠️ 메모리 「hit-area 오버레이가 클릭을 삼킨다」는 **덮개가 다른 핸들러를 가릴 때** 문제다. 여기서는 덮개가 곧 컨트롤이고 셀 안에 다른 버튼이 없다. 대안인 Radix Select는 새 의존 동작이 생겨서 권하지 않는다

### 🔴 CSS로 가르면 생기는 함정 — 같은 행이 DOM에 두 벌 있다

- 규격 버튼을 누른 뒤 새 행 입력칸에 포커스를 주는 코드는 `querySelector('[data-count-index=…]')`로 **첫 번째**를 잡는다. 두 벌이면 **숨은 쪽을 잡아서 포커스가 안 간다** → `querySelectorAll`로 받아 **보이는 것**(`offsetParent !== null`)을 고른다
- 충돌로 합쳐 들어온 줄의 강조(`incomingIds`)는 두 행 모두에 준다

## 확인 (390px 실기기 또는 개발자도구 — 네가 확인)

1. 편집: 규격 버튼 36px, 스테퍼·삭제·셀이 40px, **가로 스크롤 없음**
2. 🔴 **셀 폭**: 계산으로는 390px에서 셀이 **약 74px**(다이얼로그 여백 32 + 내부 32 + 행 16을 빼면 310, 거기서 스테퍼 128·중량 50·삭제 40·간격 18을 뺀다). 360px 폰은 약 44px라 빡빡하다. 좁으면 **글자를 줄이지 않고** 간격·여백·스테퍼 숫자 폭(48→40)에서 뺀다(메모리 「모바일 카드 폰트 키우지 말 것」). 실측은 `clientWidth`/`scrollWidth`로 한 줄
3. 톤백·잔량 kg 입력, 「포장지 선택」(미지정) 표시, 불러오는 중 회전 아이콘
4. 세 상태: 편집 / 마감됨(뱃지·마감 해제) / 조회 전용(총량 보임)
5. 여러 생산자 배치: 그룹마다 규격 버튼·소계
6. 규격 버튼 → 새 행 수량칸으로 포커스가 가는지 (위 함정)
7. **PC(1280px)는 그대로**인지 (1번 결정에서 PC로 넣은 것 빼고)
8. 규격 5개를 넣었을 때 하단 바가 가려지지 않는지

### 지시서와 다르게 하는 것 (코드 대조 결과)

> ✅ **지시서 14:30 개정판이 아래 1·2·3을 전부 그대로 반영했다** — 지금은 지시서와 어긋나는 곳이 없다. 개정판에 추가된 것: 하단 바가 넘치면 **초기화를 아이콘만 있는 40×40 버튼으로** 먼저 줄인다(글자 축소 금지)

1. **C2의 iOS 자동 확대 처리 컴포넌트는 지금 안 만든다 → ② D4와 한 쌍으로 미룬다.** 지시서는 「D4에서 `maximumScale`을 지웠으니」가 전제인데, **D4는 아직 안 했다.** `app/layout.tsx:35-36`에 `maximumScale: 1` · `userScalable: false`가 그대로 있어서, 지금은 14px 입력칸에서도 iOS가 확대하지 않는다(핀치도 막혀 있다). 지금 넣으면 아무 효과가 없고 확인할 방법도 없다. **§86 D4 항목에 「iOS 확대 처리 컴포넌트 필수」로 적어 둔다**
2. **잔량 kg 입력칸은 스테퍼 자리(108px)에 둔다.** 지시서는 「입력칸(톤백·잔량): 칸 폭 64px」라 중량 칸에 두는 것처럼 읽힌다. 하지만 잔량 스테퍼 자리를 kg 입력으로 쓰기로 한 건 §87에서 **사용자가 정한 것**이다(잔량은 수량이 늘 1). 108px이라 잘릴 일도 없다. 입력칸 높이·글자만 C안(36px·14px)을 따른다
3. **하단 바 `px-4`는 안 준다.** 다이얼로그 본문이 이미 `px-4`라 한 번 더 주면 두 번 들여써진다. 시안 틀(SheetShell)은 바가 가장자리까지 닿는 구조라 거기에 맞춘 값이다. 세로 `py-2.5`만 따른다

### 폭 계산 (390px, 다이얼로그 본문 약 310px)
- 편집 행: 고정 칸 108 + 64 + 28 + 간격 12 = 212 → **셀 약 98px**(B안 74px)
- 톤백 입력: 「12345」 14px mono bold 약 42px + 좌우 여백 12 = 54 < 64 ✓

### 지시서와 다르게 / 보태서 하는 것

1. **`minmax(0,1fr)` 대신 `1fr` + 칸에 `min-w-0`** — Tailwind 임의값에 콤마가 들어가면 CSS가 안 생긴다(모바일 C안 때와 같은 이유). 효과는 같다
2. **「stone 0건」 확인 기준 때문에 모바일 공용 부분도 색이 조금 바뀐다.** 지시서는 「모바일 코드 불변」이면서 `add-packaging-dialog.tsx`에서 `stone-` 0건을 요구한다. 그런데 그룹 헤더·빈 목록 안내·「규격 선택」 라벨·기타 직접입력·소계는 **모바일과 PC가 같이 쓰는** 코드다(stone 20곳). → **색(stone → slate)만 공통으로 바꾸고, 글자 크기·배치 변경은 `sm:`으로 PC에만** 준다. stone과 slate는 거의 같은 회색이라 모바일은 눈에 띄는 변화가 거의 없다. 모바일 C안 행(`PackagingRowMobile`·`PackagingRowReadOnlyMobile`)과 모바일 하단 바는 이미 slate라 손대지 않는다
3. **확인용 긴 포장지명 「친환경 무농약 10kg 지대(신)」은 실제로 없다**(포장지 11개 조회, 9/30). 포장지 칸은 약 142px이고 select는 원래 말줄임된다. 실제로 가장 긴 「땅끝에서보냅니다」(13px 약 104px + 화살표)는 들어간다
4. 지시서 표의 「현재 — 잔량: 숫자 1만 표시」는 편집 화면과 다르다(지금 PC 편집 행은 잔량에도 스테퍼가 있다). 제안 쪽(스테퍼 자리 = kg 입력)은 그대로 따른다
