## 2. 산출물 모양

통일양식 + 옛 공장 발주서(`docs/resources/#01. 공장 발주서 (2026).xls`)의 「농가명」 줄 자리를 되살린다.

```
행1  26/08/18 (화)\n서울급식   | 유기농 새청무 (병합)      | 유기농 찹쌀 …
행2  농가명                    | 박태일 | 박태일 | 김OO 외 1 | …
행3  로트번호                  | 2601-… | 2601-… | 2601-… 외 1 | …
행4  포장지                    | (원본 그대로, 빈칸은 빈칸)
행5  중량                      | 1kg | 5kg | 10kg | …        ← 톤백은 자루중량(1,000kg), 포장지=톤백
행6  소계                      | 주문 합계
행7  (발주처) | (수령인)
행8~ 은평구   | 행복플러스 | 31 | 6 | 91 | …                ← 셀 값 = 주문 수량(숫자 유지 → 소계 검산 가능)
…
(빈 줄)
미완료 N칸(있을 때만) · 내보낸 시각 · 내보낸 사람 · 「원본에서 주문 0인 행·열은 저장되지 않아 빠져 있습니다」
```

### 2.1 열 = 원본 열 (SKU 열 아님)
- 열 키 = `rawItemName | rawPackaging | packageType | unitWeightKg` — 영업이 쓴 원본 이름 그대로. 매트릭스 화면은 SKU 기준으로 묶지만(`columnKeyOf`), 증빙은 **원본 발주서와 대조**하는 게 목적이라 원본 기준이 맞다. 재매칭으로 SKU가 바뀌어도 열이 흔들리지 않는다.
- ~~열 순서: 각 건의 품목 id 순서를 합쳐 위상정렬로 원본 열 순서를 되살린다.~~ **구현 중 폐기(2026-09-28)** — 실DB 대조에서 택배 25열이 원본과 달랐다. 수령인마다 1~2품목만 주문해 열끼리 앞뒤 단서가 거의 없고, 주문 0인 칸은 저장도 안 된다. DB만으로는 원본 순서를 못 되살린다.
- **열 순서 = 매트릭스 화면 순서**(사용자 결정 「순서보다 규칙이 있으면 된다」). 원본 열은 자기 SKU 열 자리에 서고, 한 SKU 열에 원본 열이 둘이면 처음 나온 순. 화면 규칙은 §2.4
- 행 순서: 건 id 순(= 원본 행 순서, `createManyAndReturn`).

### 2.4 매트릭스 화면의 열 규칙 (참고 — 2026-09-28 실측)
- 열은 **품목 그룹 = 품종·도정·실제 포장지(SKU)** 로 묶이고, 그룹은 **위 행부터 처음 주문된 순**으로 선다(`buildColumns`)
- 원본 포장지가 빈칸이면 규격마다 **기본 포장지가 다르다**(택배 천지향 10kg=「천지향」, 5kg·1kg=「땅끝에서보냅니다」) → 같은 품종이라도 다른 그룹이 돼 떨어진다

### 2.2 농가명·로트번호 줄
- 출처: 그 열의 품목들에 붙은 `PackageMovement` → `MillingOutputPackage`
  - 생산자 = `package.stock.farmer.name` · 로트 = `package.lotNo ?? package.stock.lotNo`
  - 매입 잡곡(`source=PURCHASED`) = 로트 없음 → 농가명 칸 `매입·{purchaseVendor}`, 로트 칸 `매입`(구현 때 변경 — 빈칸이면 「외 N」과 섞일 때 대표가 빈 글자가 된다). 🔴 묶음 키는 lotNo가 아니라 packageId(null끼리 뭉치지 않게)
- 한 열에 하나면 그대로. **2개 이상이면 `박태일 외 1`** (차감 개수가 많은 쪽을 대표로)
  - 실측 2026-09-28: 차감 들어간 시트 5장 · 열 41개 중 **섞인 열 1개**(서울급식), 품목 96개 중 로트 2개로 나뉜 것 2개
- 섞인 열에서는 **각 셀에 메모(코멘트)**를 단다 — `박태일 2601-xxxx 20개 · 김OO 2601-yyyy 11개`. 「외 1」로 뭉개진 내역이 증빙에서 사라지지 않게.
- 차감 0인 열은 빈칸.

### 2.3 셀
- 값 = 주문 수량(숫자). 빈 셀 = 주문 없음(원본과 같다).
- 상태 = `cellStatusOf` 단일 원천(매칭실패·재고부족·부분·대기·완료) — 새 판정 만들지 않는다. 재고부족은 **내보낸 시점 가용** 기준.
- 색은 칠하지 않는다(Q3). 드문 미완료 셀만 **메모**로 남긴다 — 완료 셀은 아무것도 달지 않는다
  - 부분: `부분 — 차감 80 / 주문 112` · 대기: `대기 — 차감 0` · 재고부족: `재고부족 — 가용 3` · 매칭실패: `매칭실패 — SKU 없음`
- 미완료 셀이 있으면 하단에 `미완료 N칸` 한 줄 — 메모를 하나씩 찾지 않아도 있다는 걸 알게
