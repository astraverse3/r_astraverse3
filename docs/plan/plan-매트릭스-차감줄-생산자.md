# 발주서 매트릭스 — 「이미 차감」 줄에 생산자 표시

작성 2026-10-01

## 발단

사용자: 「매트릭스 로트에 생산자 이름 표시 (로트는 바로 비교가 안 돼서..)」

확인해 보니 셀 창의 **재고 후보 줄**에는 이미 `도정 9/17 · 윤영식 · 가용 5`처럼 생산자가 나온다. 생산자가 없는 건 위쪽 **「이미 차감」 줄**(로트 · 날짜만)이다. 사용자가 「이미 차감 줄에도 넣는 게 좋겠지?」라고 해서 그 줄에 넣는다.

## 왜

후보 줄은 생산자로 읽는데 차감 줄은 로트 번호로만 나온다. 그러면 「아까 누구 걸로 뺐더라」를 대조하려면 긴 로트 번호를 눈으로 비교해야 한다. 같은 사람을 두 줄이 같은 말로 부르게 맞춘다.

## 변경 범위

| 파일 | 내용 |
|---|---|
| `app/actions/purchase-order-matrix.ts` | `CellAllocated`·`BulkAllocated`에 `producer` 추가 · 두 movement 조회 `package` select에 `source`·`purchaseVendor`·`stock.farmer.name` 추가 · 생산자 계산을 `producerOf()` 하나로(지금 후보 쪽 2곳에 같은 식이 있다 → 4곳이 같은 함수를 쓰게) |
| `app/(dashboard)/sales/purchase/[uploadId]/cell-allocation-popover.tsx` | 「이미 차감」 줄: `로트 · 날짜` → `로트 · 날짜 · 생산자` |
| `app/(dashboard)/sales/purchase/[uploadId]/tonbag-popover.tsx` | 「이미 차감/차감 완료」 줄: `로트 · 단중 × 개수` → `로트 · 생산자 · 단중 × 개수` |

## 표시

- 지금 그 줄은 한 줄에 `truncate`라서 길면 잘린다. 생산자가 잘리면 넣는 의미가 없다. 그래서 생산자를 로트보다 **앞쪽**에 둘지 검토했다. 하지만 후보 줄과 순서(로트 → 생산자)를 맞추는 게 대조에 낫다고 봤다. 대신 **잘리는 쪽은 로트**가 되게 한다: 로트만 `truncate`로 처리하고 생산자는 `shrink-0`으로 둔다.
- 생산자 규칙은 후보와 같다. 도정산이면 농가명, 매입이면 매입처, 없으면 「—」.
