# 계획서 — 제품재고 기본 정렬을 「오래된순」으로

- 작성일: 2026-09-08
- 요청: **오래된 재고부터 처리해야 하니 목록도 오래된 것부터 나오게** 한다
- 성격: 기본값 1개 변경. 정렬 로직 자체는 **이미 구현돼 있어 건드리지 않는다**

---

## 1. 목표

제품재고 목록(`/packages`)의 기본 정렬을 **`weight_desc`(재고량 많은순) → `oldest`(오래된순)**.

**벼·잡곡 두 탭 모두** 바뀐다 — 같은 `page.tsx`·`getPackages`를 쓴다. 선입선출은 두 탭에
동일하게 적용되는 원칙이라 의도에 맞다고 본다. (다르게 가야 하면 알려줘)

## 2. 「오래된」의 기준 — 확인 완료

`app/actions/packages.ts:179` 기준으로 화면 날짜(`date`)는
**매입 = 입고일(`incomingDate`) / 도정산 = 포장 등록일(`createdAt`)** 이다.
DB `orderBy`는 1차 정렬일 뿐이고 **최종 순서는 이 화면 날짜로 다시 잡는다**(`repDate`).
묶음(그룹)은 대표일을 **min**으로 잡아 「가장 오래된 줄」이 그룹 위치를 정한다 — 이미 맞게 돼 있다.

→ **정렬 로직은 무변경.** 바꾸는 건 기본값뿐이다.

## 3. 변경 범위 — 4파일, 기본값이 흩어져 있다

| # | 파일 | 지점 |
|---|---|---|
| 1 | `app/actions/packages.ts:132` | 서버 기본값 `sort = 'weight_desc'` |
| 2 | `app/(dashboard)/packages/page.tsx:18` | `parseSort` fallback |
| 3 | `packages/package-search-dialog.tsx` | **5곳** — useState(83) · URL sync(97) · 배지 카운트(108) · handleApply(125) · handleReset(141) |
| 4 | `packages/active-package-filters.tsx:68` | `sortIsCustom` 판정 |

🔴 **같은 리터럴이 4파일 8곳에 흩어져 있다.** 하나라도 빠지면
「기본값인데 URL에 `sort=`가 붙는다」거나 「기본값인데 배지가 뜬다」로 **조용히 어긋난다.**
그래서 **`lib/package-sort.ts`에 기본값 상수 하나를 두고 4파일이 그걸 가져다 쓴다.**
(프로젝트에 이미 있는 단일 원천 패턴 — `lib/package-where.ts`·`lib/production-year.ts`와 같은 방식)

## 4. 부수 효과 — 배지 동작이 뒤집힌다

지금은 「재고량 많은순」이 기본이라 **배지가 안 뜨고**, 「오래된순」을 고르면 뜬다.
바꾸면 **정반대**가 된다 — 「오래된순」이면 조용하고, 「재고량 많은순」을 고르면
활성 필터 배지에 `재고량순`이 뜬다. **의도된 동작이다.**

기존에 `?sort=oldest`가 붙은 북마크·링크는 그대로 동작한다(값이 유효해 그대로 해석된다).

## 5. 단계

1. `lib/package-sort.ts` 신규 — `DEFAULT_PACKAGE_SORT: PackageSort = 'oldest'` + 정렬 옵션 목록
2. 4파일이 상수를 참조하도록 교체 (리터럴 8곳 제거)
3. `tsc --noEmit` · `eslint` 확인
4. 사용자 브라우저 확인 — **벼/잡곡 두 탭 모두** 첫 진입 시 오래된 것부터인지,
   정렬을 바꿨다 되돌렸을 때 URL·배지가 깨끗한지
5. 보고서 · 작업일지 · 커밋

## 6. 확인이 필요한 것

- **잡곡 탭도 함께 바꾸는 게 맞나?** (기본값 공유라 함께 바뀐다. 분리하려면 별도 작업)
- **정렬 선택지 순서**도 「오래된순」을 맨 위로 올릴까? 지금은 `재고량 많은순 / 최신순 / 오래된순`
  순서라 기본값이 목록 맨 아래에 놓인다. 기본을 맨 위로 올리는 게 자연스럽다.
