### 🔴 시안과 실제가 부딪히는 곳 → 결정 필요

**① 채널 배지 색 (A-2)**
- 채널 배지(`CHANNEL_META.badge`)를 쓰는 곳은 **발주서 목록(`sales/upload-table.tsx:106`) 하나**다.
- 그 목록의 **같은 줄**에 처리 상태 배지도 있다: 「완료 N」 = `bg-emerald-50 text-emerald-700` + 점, 「부분 N」 = `bg-amber-50 text-amber-700` + 점(`upload-table.tsx:212-221`).
- 시안대로 하면 **서울급식 배지가 「완료」와 같은 모양**이 된다(emerald-50/700 + 점). 해남급식(amber-50/800)도 「부분」과 거의 같다. 이마트(orange-50/800)는 발주서 상세의 「재고부족」(orange-100/800)과 가깝다.
- 시안은 차트 색만 보고 상태 배지는 보지 않았다.
- **권장**: T1 규칙의 「분류 = 회색 외곽선」(`border-slate-300 text-slate-700 bg-white`)에 **차트 색 점**을 붙인다. 점이 차트와 같은 뜻을 잇고, 배경색이 있는 상태 배지와는 모양이 갈린다.

**② 원물출고 데이터 (A-4)** — 실데이터 16건을 읽기 전용으로 세었다(10/2)

- 시안은 「판매 = 원물판매·판매」다. 이 규칙이면 **씨제이브리딩 「원물출고」 8.29톤이 「판매 아님」으로 빠진다.**

- 시안의 출고처(해남농협 RPC·강진 미곡처리장…)와 월별 숫자는 가짜라서 이 문제가 안 보였다.

**③ 차감 사유 기본값 (B)**
- 요청서에서 B는 철회했다. 사용자가 10/2에 ①(기본값 없음) 대신 **② 「판매」면 거래처 필수**를 골랐고, 이미 반영했다(`df4e137`).
- 그런데 지시서는 ①과 ②를 같이 하라는 판본이다. 시안의 「현재」가 ②를 이미 그리고 있어서, 디자이너는 ②를 보고도 ①을 얹은 것이다.
- B 안에서 ②와 부딪히지 않는 것:
  - ④ 거래처 칸을 늘 자리에 둔다. 판매가 아니면 비활성 + 「판매일 때만 적어요」. 모바일도 발생일과 두 칸
  - ⑤ 값 보존. ⑤는 **이미 그렇다**: 사유를 바꿔도 `customer`를 지우지 않고, 서버로는 판매일 때만 보낸다(`deduct-dialog.tsx:130`)
- 지금 모바일은 거래처 칸이 생겼다 없어졌다 하면서 아래가 밀린다(`grid-cols-1`). ④는 이걸 고친다.

### 시안에만 있고 지시서에 없는 것 → 안 한다 (확인만)
- 빈 상태의 「이번 달로 보기」 버튼: 기본이 이미 이번 달이라 지시서대로 뺀다
- 표 글자 13px(행) · 12px(머리): 지금은 12px. 지시서 목록에 없어서 그대로 둔다
- 시트의 곡종 칩 「쌀·현미·잡곡」은 가짜다. 코드의 「벼·잡곡」을 쓴다. 날짜 「10.01 ~ 10.31」도 가짜다(코드는 오늘까지)

### 지시서 안의 작은 충돌 (지시서대로 하고 적어 둔다)
- 빈 상태의 카드 값 0을 slate-300으로 하라는데, 작업지시 ③ T3는 「밝은 배경 위 글자는 slate-500 이상」이다. 「값 없음」 신호로 보고 지시서대로 한다
- 새 시트는 재고분석 시트(`stock-filter-sheet.tsx:57`)를 **그대로 베끼지 않는다**. 그 시트는 백로그 §36의 「탭바와 12px 겹침」을 안고 있다. 새 시트 바닥은 `calc(60px + 1rem + env(safe-area-inset-bottom) + 8px)`, max-h도 같은 값으로 맞춘다. 기존 두 시트는 손대지 않는다(§36)
