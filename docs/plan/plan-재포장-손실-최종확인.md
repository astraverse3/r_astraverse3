# 재포장 손실 — 최종 확인창 추가

작성 2026-10-01

## 발단

사용자: 「전량을 채우지 않았을 때 손실로 처리되잖아. 확인 과정을 한 번 더 거치면 좋겠어. 경고를 해도 확실히 인식하지 않으면 넘어가는 경우가 있었어.」

오늘 되돌린 재포장 #26(서농22호 4kg 132개 중 57개분만 만들어서 300kg 손실)이 이 경우다.

## 지금 흐름과 문제

1. 「재포장하기」를 누르면 서버가 손실이 1%를 넘는지 본다(`lib/repack.ts` `LOSS_WARN_RATIO`). 넘으면 `needsLossConfirm`으로 되돌려 보낸다.
2. 푸터가 노란 경고로 바뀌고 「300kg을 손실로 기록하고 진행」 버튼이 뜬다(`repack-dialog.tsx:670-737`).
3. 그 버튼을 누르면 곧바로 저장된다.

#26도 2번 버튼까지 누르고 지나갔다. 그러니 확인이 없었던 게 아니라, **확인이 확인처럼 안 보였던 것**이 문제다.
- 경고가 같은 푸터 안에서 색만 바뀐다. 방금 누른 버튼 근처에 진행 버튼이 다시 생겨서 연달아 누르기 쉽다.
- 경고 색이 빨강이 아니라 노랑이다.
- 경고가 kg로만 말한다. 사람은 개수로 센다(「132개 중 75개분이 사라짐」이 더 잘 읽힌다).

→ 같은 모양의 확인을 하나 더 붙이면 똑같이 넘어간다. **모양과 위치가 다른 확인**을 넣는다.

## 목표

「손실로 기록하고 진행」을 누르면 바로 저장하지 않고, 화면 가운데에 **빨간 확인창**을 띄운다. 거기서 한 번 더 눌러야 저장한다.

## 변경 범위

| 파일 | 내용 |
|---|---|
| `lib/repack.ts` | 확인창 문구를 만드는 순수 함수 `lossConfirmText()` 신설 |
| `lib/repack.test.ts` | 위 함수 테스트 |
| `app/(dashboard)/packages/repack-dialog.tsx` | 노란 경고의 진행 버튼 → `confirmDialog()`를 거쳐서 `submit(true)` |

서버(`app/actions/repack.ts`)와 손실 기준(1%)은 그대로 둔다. 화면에서만 한 단계를 더한다.

다이얼로그 파일이 이미 804줄이라, 문구 만드는 로직은 lib로 뺀다(늘어나는 줄 최소화).

## 확인창 설계

공용 `confirmDialog()`(`components/ui/confirm-dialog.tsx`)를 `destructive`로 쓴다. 이미 여러 다이얼로그 안에서 쓰고 있는 방식이다(`add-packaging-dialog.tsx` 등).

- **제목**: 「손실로 기록할까요?」
- **본문 예시** (#26 기준)
  ```
  서농22호 4kg 132개(528kg)를 쓰는데 228kg만 만들어요.
  남는 300kg(4kg 75개분)은 손실로 사라져요.

  재포장은 되돌릴 수 없어요. 실제로 없어진 경우에만 기록하세요.
  ```
- **버튼**: 「돌아가기」 / 「손실로 기록」(빨강). Radix AlertDialog는 처음에 「돌아가기」에 포커스가 가서, Enter를 쳐도 진행되지 않는다.
- 「돌아가기」를 누르면 노란 경고 상태 그대로 남는다. 거기서 「남기기」나 「취소」를 고를 수 있다.

### 문구 규칙 (`lossConfirmText`)

- **쓸 재고가 한 줄일 때**: `품종 규격 N개(Xkg)를 쓰는데 Ykg만 만들어요.`
  - 규격 표기는 다이얼로그의 `formatSpec` 규칙을 따른다(「4kg · 4kg」처럼 겹쳐 쓰지 않음).
- **쓸 재고가 여러 줄일 때**: `쓸 양 Xkg 중 Ykg만 만들어요.`
- **「N개분」**: 쓸 재고의 개당 중량이 모두 같을 때만 붙인다. 손실 ÷ 개당 중량이 정수가 아니면 소수 첫째 자리까지 쓰고 앞에 「약」을 붙인다. 톤백·잔량처럼 개당 중량이 제각각이면 개수분을 빼고 kg만 쓴다.

## 단계

1. `lossConfirmText()` + 테스트: 한 줄 / 여러 줄 / 정수 개수분 / 「약」 / 개당 중량 섞임
2. 다이얼로그: 진행 버튼 `onClick`을 `async`로 바꾼다. `confirmDialog`가 false면 아무것도 안 한다. true면 기존처럼 `setLossConfirmed(true)` + `submit(true)`
3. 검증: `npm test` · `tsc` · `eslint .` → 화면은 사용자 확인
   - 🖐 **모바일 확인 필요**: 확인창 버튼을 눌렀을 때 아래 재포장 다이얼로그까지 닫히지 않는지(중첩 모달 닫힘 순서 이력 있음)

## 안 하는 것

- 손실 kg를 직접 타이핑하게 하는 방식: 과하다고 판단해서 제외
- 손실 기준 1% 변경
- 서버 쪽 추가 확인
