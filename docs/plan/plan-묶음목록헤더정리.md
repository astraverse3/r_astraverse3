## 4. 단계

### P1 — 탭 행에 슬롯 신설
`SalesTabs`에 `rightSlot`을 받아 **모바일 블록에만** 붙인다. 데스크탑 underline 탭 블록은 손대지 않는다.
슬롯이 없으면 래퍼 없이 지금 구조 그대로 렌더한다(시안 `tabs()`가 `extra` 유무로 갈리는 것과 같다).

- 세그먼트: `flex-1 min-w-0` — 🔴 `min-w-0`을 빼면 탭 라벨이 칸의 하한이 돼 버튼이 밀린다([[grid_min_width_zero]]와 같은 원리)
- 구분선은 **회색 세그먼트 밖**에 둔다 — 업로드는 탭이 아니라는 걸 시각으로 가른다(시안 갱신 의도)

### P2 — 업로드 트리거 두 갈래
`UploadDialog`에 `compact` prop 추가.

- `compact` (모바일 탭 행): `h-10 w-10 rounded-lg` 아이콘만 + `aria-label`
- 기본 (데스크탑 목록 위): 지금 트리거 유지
- ⚠️ 분리되면 기본 트리거의 모바일 분기(`px-2.5 sm:px-4`, 라벨 `hidden sm:inline`)는 **닿지 않는 코드**가 된다. 같은 커밋에서 정리한다

### P3 — 데스크탑 행 숨김
`product-sales-section.tsx`의 업로드 행을 `hidden sm:flex`로.

### P4 — 칩 줄 1줄 스크롤
`upload-table.tsx:36` `flex-wrap` → 모바일 `overflow-x-auto` + `sm:flex-wrap sm:overflow-visible`, `Chip`에 `shrink-0`.
칩 줄은 `usedChannels.length > 1`일 때만 렌더되므로 **채널 1종이면 줄 자체가 없다**(현 동작 유지).

## 5. 🔴 짚어 둘 것

**① `scrollbar-hide`는 이 프로젝트에 정의가 없다.**
Tailwind v4 + `@tailwindcss/postcss`, 플러그인 없음. `app/globals.css`의 `@layer utilities` 두 곳(143·184행)에도 없다.
그런데 **9곳이 이미 쓰고 있다**(`active-milling-filters.tsx:45` 등) — 전부 **효과 없는 클래스**다.
터치 기기는 오버레이 스크롤바라 티가 안 나서 여태 드러나지 않았다.
→ 그대로 갖다 쓰면 "숨겼다"고 믿지만 데스크탑 좁은 창에서 스크롤바가 보인다. **§6에서 정한다.**

**② `UploadDialog` 인스턴스가 2개가 된다.**
모바일 슬롯 1개 + 데스크탑 행 1개(서로 `hidden`으로 갈림). 파일 선택 상태가 두 벌이지만
어느 한쪽만 화면에 있으므로 기능상 문제는 없다. 하나로 합치려면 위치가 달라 레이아웃이 꼬인다 — **2개로 간다.**

**③ `SalesTabs` 사용처는 `page.tsx` 한 곳뿐이다.** prop 추가가 다른 화면에 번지지 않는다.

**④ 서버 → 클라이언트 ReactNode 전달.**
`page.tsx`는 서버 컴포넌트, `SalesTabs`는 `'use client'`. `rightSlot`으로 엘리먼트를 넘기는 건
children 패턴과 같아 정상이다. ⚠️ 단 **함수는 못 넘긴다** — 슬롯 안에서 콜백이 필요해지면 구조를 바꿔야 한다.

## 6. 정해진 것 — 스크롤바 숨김 = **(a)** (별도 커밋 `8ddcd51`)

| **(a)** | `globals.css`에 `.scrollbar-hide` 정의를 **실제로 추가** | 이번 칩 줄 + **기존 9곳이 한꺼번에 의도대로 동작**. 그 화면들에서 스크롤바가 사라지는 시각 변화가 생긴다(원래 의도했던 모습) |
