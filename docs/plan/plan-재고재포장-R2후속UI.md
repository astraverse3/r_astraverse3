## 2. 결정

### 결정 #44 — 좌우 2열을 버리고 1열 세로 흐름으로

「쓸 재고」 좌측 패널을 없애고 **상단 한 줄 요약**으로 접는다 (2026-08-27 사용자 확정).

```
┌─ 재포장 ─────────────────────────────────────────┐
│ 하이아미 · 백미 · 8건 79kg을 다시 나눠 담습니다   │
├──────────────────────────────────────────────────┤
│ ▸ 쓸 재고 8건 79kg · 전량 사용            [고치기]│  ← 접힘이 기본
├──────────────────────────────────────────────────┤
│ 만들 규격                                        │
│ [톤백][20kg][10kg][8kg][5kg][4kg][3kg][1kg][잔량]│
│ ──────────────────────────────────────────────── │
│ [20kg] 자연주의▾ ⊖ 3 ⊕  60kg  [윤병옥·391▾]  🗑 │
│ [잔량]    —     ⊖ 1 ⊕  19kg  [윤병옥·391▾]  🗑 │
│ 비고 [                                        ]  │
├──────────────────────────────────────────────────┤
│ 딱 맞음  쓸 79kg − 만들 79kg          0kg  [재포장]│
└──────────────────────────────────────────────────┘
```

- 소스 개수를 줄이는 건 예외 동선이다(기본이 전량 소진). **접힌 요약 한 줄 + 「고치기」로 펼침**
- 펼치면 지금의 소스 카드 목록이 그대로 나온다 — 컴포넌트 재사용, 로직 변경 없음
- 1열이 되므로 `sm:max-w-[940px]` → **`sm:max-w-[720px]`**

### 결정 #45 — 규격 버튼이 곧 「줄 추가」다

포장 입력 다이얼로그(`add-packaging-dialog.tsx:260-300`)의 `addToGroup` 패턴을 그대로 옮긴다.

- 규격 버튼 9개는 **결과 섹션 상단에 한 벌만** 둔다(지금은 줄마다 반복 렌더)
- 버튼 클릭 → 아래에 **1행짜리** 결과 행이 붙는다
- **같은 (규격 + 로트) 행이 이미 있으면 새로 만들지 않고 개수 +1** 하고 그 행 개수칸에 포커스
- 「줄 추가」 버튼은 없어진다
- 톤백·잔량은 자루당 kg이 사람 입력이라 행이 붙은 뒤 kg 칸으로 포커스

`REPACK_SPECS`(`lib/repack.ts:22`)는 그대로 쓴다. 포장 입력의 「기타(직접 입력)」는 이번 범위 밖 —
톤백·잔량 kg 직접 입력으로 이미 커버된다.

### 결정 #46 — 결과 행은 1행 압축 그리드

카드형(세로 2단 + 4열 그리드)을 버리고 **한 행 = 한 줄**로 만든다.

| 열 | 데스크탑 | 모바일 | 내용 |
|---|---:|---:|---|
| 규격 뱃지 | 52px | 46px | `20kg` / `잔량`(노랑) / `톤백` — 클릭 불가, 표시만 |
| 포장지 | 1fr | 1fr | 셀렉트. 잔량=`—`, 톤백=`톤백 고정` |
| 개수 | 84px | 84px | `⊖ 3 ⊕` stepper (지적 #5) |
| 자루당 kg | 62px | 56px | 톤백·잔량만 입력, 나머지는 계산값 표시 (지적 #4) |
| 로트 | 132px | 1fr(2행) | 셀렉트. `lotOptions.length <= 1`이면 **열 자체를 안 그린다** |
| 삭제 | 24px | 24px | 🗑 |

- 모바일은 로트 열을 두 번째 행으로 내린다(폭이 안 나온다)
- **줄 번호(`1번째 줄`)는 없앤다.** 행이 압축되면 번호를 둘 자리가 없고, 오류는 그 행을 붉게
  물들이고 아래 한 줄로 표시하면 충분하다. `blockingReason`의 `N번째 줄:` 접두는 유지(푸터용)

### 결정 #47 — 로트는 행마다 셀렉트를 유지하되 **직전 선택을 물려받는다**

로트별 섹션 분리는 채택하지 않는다 (2026-08-27 사용자 확정).
잔량 병합은 로트가 4~16종이라(상위 계획서 §2.2) 섹션을 나누면 규격 버튼 9개짜리 블록이 16개 쌓인다.

- 행마다 로트 셀렉트 **유지**
- 새 행을 만들 때 **마지막 행의 로트를 기본값으로 복사**한다 → 같은 로트를 연속으로 만들면 한 번만 고른다
- 로트가 1종이면 지금처럼 자동 선택 + 열 미표시
- ⚠️ 상위 계획서 §6 리스크 「기본 선택 없음(무심코 넘어가지 않게)」와 충돌하는가? — **아니다.**
  첫 행은 여전히 빈 선택으로 시작한다. 사람이 한 번 고른 값만 물려받는다

### 결정 #48 — 포장지 기본값은 낙관적으로 채운다

`suggestProductType(varietyId, millingType, packageType)` (`app/actions/product-type.ts:269`)를 재사용한다.

- 행을 **먼저** 그리고, 응답이 오면 그 행의 포장지가 **아직 비어 있을 때만** 채운다
- 사람이 먼저 골랐으면 그 선택이 이긴다
- 서버 왕복이 행 추가를 막지 않으므로 딜레이 체감이 없다 (포장 입력이 이미 이 방식)
- 잔량·톤백은 호출하지 않는다(포장지 미부여·고정)

### 결정 #50 — 로트가 여러 종이면 규격 버튼은 **항상 새 줄**을 만든다

> 「같은 규격으로 다른 로트로 재포장하고 싶을 때 지금은 방법이 없네.」 — 2026-08-27 사용자

**#45 + #47이 물려 만든 설계 결함이었다.** 새 줄이 직전 줄의 로트를 물려받는데(#47),
병합 판정이 (규격 + 로트)라(#45) 20kg 버튼을 다시 눌러도 로트가 같아 기존 줄에 합쳐진다.
→ **「로트 B짜리 20kg 줄」을 만들 진입점이 아예 없다.** §7 검증 시나리오 4번도 성립하지 않았다.

| 로트 종수 | 같은 규격 버튼을 또 누르면 |
|---|---|
| 1종 | 개수 +1 (줄이 갈릴 이유가 없다) |
| 2종 이상 | **새 줄** — 로트는 직전 줄에서 상속, 바꿀 것만 바꾼다 |

- 같은 로트로 여러 개가 필요하면 `⊖ n ⊕` stepper로 올린다. 병합이 사라져도 손이 늘지 않는다
- 로트 다중일 때 규격 버튼 위 안내를 「누를 때마다 줄이 하나씩 생겨요 (줄마다 로트를 고르세요)」로 바꾼다
- 같은 (규격+로트) 줄이 둘 생겨도 막지 않는다 — 결과 행이 둘로 갈릴 뿐 재고는 맞고,
  자루마다 따로 관리하려는 의도일 수 있다

### 결정 #51 — 남는 폭은 포장지가 아니라 로트가 가져간다

> 「포장지 칸이 너무 넓고 폭이 남으면 로트번호에 투자..」 — 2026-08-27 사용자

데스크탑 그리드를 `52 · 1fr · 84 · 62 · 132 · 24` → **`52 · 128 · 84 · 62 · 1fr · 24`**로 바꾼다.

- 포장지 이름은 가장 긴 게 8자(`땅끝에서보냅니다`)라 128px로 족하다
- 로트는 `윤병옥 · 251119-11-15100914-391` 꼴이라 폭이 곧 판독성이다
- 모바일은 로트가 둘째 줄로 내려가 폭 경쟁이 없으므로 그대로 둔다

### 결정 #52 — 일반 규격은 포장지 없이 저장할 수 없다

포장지가 없으면 `productTypeId`(SKU)가 안 붙고(`repack.ts:336-338`),
발주서 판매처리는 **SKU로만 재고를 찾는다**(`purchase-order.ts:53` `where: { productTypeId }`).
→ 실물은 창고에 있는데 발주가 들어오면 「재고 부족」으로 뜨는 **못 파는 재고**가 된다.

| 규격 | SKU | 판정 |
|---|---|---|
| 잔량 | null | 정상 — 자체 판매를 안 한다(`milling.ts:15`) |
| 톤백 | 서버가 `'톤백'` 포장지를 강제(`repack.ts:320-333`) | 정상 |
| 일반 규격 | 미지정이면 **null** | **차단한다** |

`blockingReason`에 `packaging` 필드 오류를 더해 저장을 막는다.
「포장지를 골라주세요. (없으면 팔 수 없어요)」 — 이유를 같이 적어야 관리 화면으로 갈 판단이 선다.

**재포장을 막는 이유**: 재포장의 존재 이유가 「못 팔던 잔량 7톤을 팔 수 있는 규격으로 만드는 것」인데
(상위 계획서 §2.1) 그 결과물이 또 못 파는 재고가 되면 작업이 헛돈다.

⚠️ **이 구멍은 재포장만의 것이 아니다.** 도정 포장 등록도 같다(`milling.ts:482` `if (packagingId !== null)`).
등록 3경로 공통 이슈이며, 이번에는 재포장만 막았다. **백로그**로 남긴다.

**단, 추천을 기다리는 동안에는 판정하지 않는다.** #48이 줄을 먼저 그리고 포장지를 나중에 채우므로,
줄이 생긴 직후엔 언제나 미지정 상태다. 그대로 판정하면 사용자가 아무것도 하지 않았는데
붉은 경고가 번쩍였다 사라진다. → 추천 대기 중인 줄 key를 `pkgPending`에 담고, 그 줄은
**저장은 막되(`quiet`) 붉게 알리지 않는다**. 응답이 오면(성공·실패 무관) 집합에서 빠지고 정상 판정된다.

### 결정 #49 — 목록 선택 바를 내용 폭으로 (지적 #1)

`package-list-client.tsx:194`의 데스크탑 sticky 바를 전폭 → **내용 폭 + 우측 정렬**로 바꾼다.

- `sticky bottom-4` 유지(fixed 중앙 정렬은 사이드바 256px 때문에 어긋난다 — R2에서 확인된 사실)
- 바깥 래퍼에 `flex justify-end`, 안쪽 바는 `w-fit`
- 모바일 floating pill은 그대로(폭이 이미 화면에 맞다)
