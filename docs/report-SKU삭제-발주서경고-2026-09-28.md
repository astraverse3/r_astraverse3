## 1. 변경 요약

| 파일 | 내용 |
|---|---|
| `app/actions/product-type.ts` | `getProductTypeUsage(id)` 신설 — 제품재고 수 + 이 SKU에 붙은 발주서 품목(시트별). `deleteProductType` 감사로그에 `(발주서 n품목 매칭 해제)` |
| `app/(dashboard)/admin/product-types/product-type-page-client.tsx` | 삭제 버튼 → 사용처 조회 → 제품재고 있으면 **확인창 없이** 안내 · 발주서 품목 있으면 확인창에 경고 |

검증: tsc 0 · eslint 0 · test 424/424

## 2. 주요 결정

- **막지 않고 알린다** — SKU 정리는 정상 업무고, 풀린 품목은 재매칭으로 다시 붙는다
- **누르는 순간 조회** — 페이지 로드 때 받은 값은 그 사이 매칭·재매칭으로 낡을 수 있다
- **서버 가드는 그대로** — 클라이언트 사전 조회는 안내일 뿐, 제품재고 판정은 여전히 `deleteProductType`이 한다
- 시트 없는 주문(`PurchaseOrder.upload`가 null)은 스키마상 가능해 `시트 없음`으로 묶는다
