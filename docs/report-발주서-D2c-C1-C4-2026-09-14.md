## 주요 결정 (계획서 결정 A~D 그대로 + 구현에서 정한 것)

- **결정 A — 셀 = 트랜잭션 하나.** `confirmCell`이 `loadCellItems`로 라인을 읽고(한 SKU·한 건인지 검증) `splitAllocationsByLine`으로
  나눈 뒤 라인마다 `applyAllocations`. 가용 재검증·초과 차단은 거기 그대로다. `timeout: 30000` 명시.
- **결정 B — 순수 이동.** 4개 함수 본문은 HEAD와 바이트 단위로 같다(`diff` IDENTICAL). `'use server'` 없는 lib이라 `tx`를 받아도 액션이 안 된다.
- **결정 C — 클라이언트 피벗.** 서버는 `BuildMatrixInput`을 주고 `matrix-client.tsx`가 `useMemo(buildMatrix)`.
  액션은 `CellPatch{productTypeId, allocatedQty: {itemId→n}, availability, availabilityKg}`만 돌려주고 `applyPatch`가 그 자리만 갈아끼운다.
  실패하면 팝오버가 `onFail()` → `router.refresh()`.
  서버 prop이 새로 오면 로컬을 서버 값으로 되돌린다(`serverInput !== seen` 패턴 — effect 대신 렌더 중 setState).
- **결정 D — 막는 셀.** 톤백(`bulk`)·매칭실패(`UNMATCHED`)는 팝오버에 안내문만(D2d·D2e). `getCellAllocation`도 톤백 라인이면 오류로 막는다.
- **완료 판정은 `remainingQty === 0`**(셀 상태가 아니라 서버가 방금 읽은 값). 부분 셀은 「이미 차감」 목록 + 편집기 + 「차감 취소」(전부 되돌림).
- **후보는 `packageId`만으론 못 고른다** → 로트·도정/입고일·생산자·가용을 함께. 날짜는 `todayIsoKst(date)`로 KST(§39 함정 회피).
- **취소는 `confirmDialog`** 경유(공용 규칙). 하드삭제 + 감사로그(`DELETE PackageMovement`).
- `Th`에 `onClick`만 추가. 이름칸은 `<button>`으로 감쌌다(hit-area 오버레이 금지 규칙).
- 팝오버는 Radix `PopoverAnchor virtualRef={{ current: td }}` — 클릭한 셀 요소를 앵커로. 포털이라 `overflow-auto` 표 안에서도 잘리지 않는다.
