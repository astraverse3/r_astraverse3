# 점검 — 포장 다이얼로그 「불러오는 중」 지연

작성 2026-09-22. 내일 아침 **첫 사용 때** 바로 할 것.

## 증상

도정관리에서 포장 다이얼로그를 열면 「기록 저장」 버튼이 **「불러오는 중...」**에 머물고,
그동안 저장이 잠긴다(`writeBlocked`). **처음 켰을 때만** 5초 이상, 데스크탑에서도 난다.

폰에서는 예전에 **「규격 버튼 자체가 안 나온」** 적이 있는데 그건 별개 증상이고
원인(세션 미주입)은 오늘 고쳤다 — 아래 §3 참고.

## 1. 측정 절차 (실서버)

로컬 dev 아님. **millinglog.vercel.app** — 콜드 스타트는 Vercel 서버리스 특성이고
dev 서버는 라우트 컴파일이 껴서 숫자가 오염된다.

1. Chrome에서 실서버 **도정관리** 페이지로 이동
2. `F12` → **Network** 탭 → **Preserve log 체크**, **Disable cache는 끈 채로**
3. **1회차(콜드)**: 아침 첫 사용 상태에서 로그를 🚫로 지우고 → 아무 배치 **상태 배지 클릭** →
   다이얼로그 열기 → 「불러오는 중」이 풀릴 때까지 대기
4. **2회차(웜)**: 닫고 로그 지우고 **바로 다시** 열기

## 2. 기록할 숫자

Name이 **`milling`인 POST**(Type `fetch`) 2개 — `getBatchOutputs`와 `listPackagings`다.

| POST milling (1) | | | | |
| POST milling (2) | | | | |
| GET /api/auth/session | | | | |

TTFB는 요청 클릭 → **Timing 탭 → Waiting**.

## 3. 판정 기준

- **1회차만 느리고 2회차는 빠름** → Vercel 콜드 스타트가 범인. 액션 합치기는 체감 적음
- **둘 다 느림** → 왕복이 범인. **액션 합치기가 바로 약**
- **POST 2개 합이 5초에 한참 못 미침** → 병목이 다른 데 있음. 페이지 로딩부터 다시

## 4. 배경 — 왜 왕복이 4회인가

[auth.ts](../auth.ts) jwt 콜백이 **매 요청마다** `prisma.user.findUnique`로 권한을 다시 읽는다.
그래서 액션 하나당 **세션 조회 1회 + 실제 쿼리 1회 = DB 왕복 2회**.
다이얼로그가 열릴 때 액션 2개가 나가고 Next는 Server Action을 **순차**로 보내므로 **4회가 줄줄이**.
Neon 왕복 250~300ms 기준 약 1.2초. 나머지가 콜드 스타트 몫.

`suggestProductType`은 **규격 버튼을 누를 때** 불린다 — 여는 시점과 무관.

## 5. 오늘 한 것 / 남은 것

**했음 — SessionProvider 초기 세션 주입** ([app/layout.tsx](../app/layout.tsx) · [session-provider.tsx](../components/providers/session-provider.tsx))
서버가 아는 세션을 안 넘겨서 첫 렌더에 `useSession()`이 undefined였다.
그동안 `canManage=false`라 **규격 버튼 블록과 저장 푸터가 통째로 사라진다**.
27개 화면이 `useSession`을 쓰는데 **`status==='loading'`을 보는 곳은 0개** —
「권한 없음」과 「아직 모름」이 같은 화면이었다.
→ 이걸 고쳐야 내일 측정에서 **세션 지연이 숫자에 안 섞인다**.

**남음 ① 액션 합치기** — 열 때 나가는 2개를 1개로. 위 측정 결과 보고 판단.

**남음 ② 실패가 조용히 먹힌다 (별건, 이번 지연과 무관)**
- 클라이언트: [add-packaging-dialog.tsx:277](<../app/(dashboard)/milling/add-packaging-dialog.tsx>) `.then()`에 **`.catch()`가 없다**.
  요청이 reject되면 `setOutputsLoading(false)`가 영영 안 돌아 **진짜로 먹통**이 된다.
  같은 패턴 **10곳**(재포장·잡곡 포장·생산자 등록 등).
- 서버: [milling.ts:454](../app/actions/milling.ts) `getBatchOutputs`의 **`requireSession()`이 `try` 밖**이라
  세션 실패가 throw로 샌다. 🔴 [permission_system_2way]에 같은 교훈이 이미 있다 —
  **가드를 try 밖에 두면 에러가 통째로 뭉개진다**. 액션 파일 28개 전수 확인 필요.
