## 3. 🔴 주요 결정 — 핸드오프를 따르지 않은 지점

구현 전 전수 대조에서 **핸드오프가 현재 코드와 어긋나는 지점 9개**가 나왔다.

### 3.1 삭제 경로 — 그대로 했으면 `883cd43`을 되돌릴 뻔했다

핸드오프 §2.3: 「삭제는 `DeleteVarietyButton`의 `handleDelete`를 그대로 쓴다」

그런데 그 버튼은 **죽은 코드**였다 — `variety-list-client.tsx:7`에서 import만 되고 JSX 사용 0건.
6/4 이후 손대지 않아 **별칭 동반 소멸 경고가 없는** 옛 버전이다.

실제 단건 삭제는 이미 있었다. 위치가 달랐을 뿐 — **수정 다이얼로그 푸터**의 빨간 삭제 버튼이고,
그 `handleDelete`에는 `883cd43`에서 넣은 경고가 붙어 있다.

> 별칭 N개(…)도 함께 사라져, 그 이름으로 오던 발주서 품목이 매칭실패로 돌아갑니다.

지시대로 옛 파일을 되살렸다면 **경고가 조용히 사라졌다.**

→ 확인 로직을 `delete-variety.ts`의 `confirmAndDeleteVariety()`로 **옮겨서**(재작성 아님)
다이얼로그와 ⋯ 메뉴가 같은 함수를 부르게 했다. 경고 문구는 앞으로도 한 벌뿐이다.

📌 **교훈: 「기존 X를 그대로 쓴다」는 지시는 X가 살아 있는지부터 본다.**
죽은 코드가 남아 있으면 핸드오프는 그것을 현행으로 착각한다.

### 3.2 곡종 라벨은 이미 단일 원천이 있었다

핸드오프 §3.2는 `GRAIN_LABEL`을 새로 정의하라고 했지만,
`lib/variety-labels.ts`에 `VARIETY_TYPE_LABELS`(BLACK 포함 7종)가 **이미 있었다.**
품종 관리 화면만 그걸 안 쓰고 삼항 체인을 **2곳**에 중복하고 있었다.

지시대로 했으면 **같은 매핑의 3번째 사본**이 생긴다. 기존 lib를 쓰고, 중복 2곳도 흡수했다.

### 3.3 `typeOrder`는 한 곳이 아니라 두 곳이었다

핸드오프는 「기존 `typeOrder`에 `BLACK: 4`를 넣어라」고 단수로 썼지만
실제로는 `:193`(모바일) · `:252`(데스크탑) **두 벌**이고 **양쪽 다** BLACK이 빠져 있었다.
칩까지 만들면 3번째가 생기므로, 순서도 라벨과 같이 lib로 올렸다.

### 3.4 ⋯ 메뉴는 앱에 이미 7곳 있었다

핸드오프는 생짜 `<button className="h-7 w-7 …">`를 제시했지만
이 앱에는 행 ⋯ 메뉴가 이미 7곳 있고 최신 정본은 `sales/upload-row-menu.tsx`다.
`Button variant="ghost" size="icon" w-8 h-8 text-slate-400` + `sr-only` 패턴을 따랐다.
(시안은 28×28이지만 앱 통일을 택했다 — **의도적 이탈**)

### 3.5 다이얼로그를 메뉴 안에 넣지 않았다

핸드오프 §2.3은 `asMenuItem` + `onSelect preventDefault`로 **트리거를 메뉴 안에** 두라고 했다.
대신 `upload-row-menu.tsx`의 방식 — **메뉴는 상태만 켜고 Dialog는 형제** — 를 택했다.

덤으로 얻은 것: `{editOpen && <VarietyDialog … />}` 조건부 마운트라
**열 때마다 새로 마운트**되어 `useState` 초기값이 늘 최신 품종 값이다.
(메모리 규칙 「다이얼로그는 열 때 상태 리셋」이 구조적으로 보장된다)

### 3.6 핸드오프 내부 모순 2건

- §2.2 표 「열 너비 `w-[52px]`」 ↔ §4 「`w-[8%]`」 → `table-fixed`+`colgroup`이라 px는 안 먹는다. **% 채택**
- 파일표 「`variety-dialog.tsx` 변경 없음」 ↔ §2.3 「`asMenuItem` prop 추가」 → **변경 있음**

### 3.7 시안을 보고 고친 것 — 검색은 등록 버튼과 같은 줄

작업 도중 시안 HTML이 들어와 대조했더니 `topbar`가
`[🔍 검색]  …  [+ 품종 등록]` **한 줄**이었다.
처음엔 검색을 목록 컴포넌트 안에 넣어 두 줄로 갈라져 있었고, 시안대로 합쳤다.

검색 상태는 두 컴포넌트가 나눠 쓰므로 `variety-page-wrapper`로 올렸다.

### 3.8 품종은 36종이 아니라 41종

핸드오프는 「36건」을 전제했지만 실제는 41종이다(테스트 「기존 41종은 …」).
개수는 계산값이라 구현 영향은 없고, 「디바운스 불필요」 판단도 그대로 유효하다.

### 3.9 칩 줄 여백 — 부모 grid의 gap이 이미 4px을 얹고 있었다

사용자가 검색창과 칩 사이 여백을 지적해 시안과 대조했다.
시안은 `topbar → 칩 12px` · `칩 → 표 12px`인데 구현은 **검색줄↔칩이 4px**(부모 grid `gap-1`만),
**칩↔표는 16px**(`pb-3` 12px + gap 4px)로 위아래가 뒤집혀 있었다.

칩 줄을 `pt-2 pb-2`(8px)로 바꿔 양쪽 모두 `8 + 4 = 12px`가 되게 했다.

📌 **부모가 `gap`을 가진 grid/flex 안에서는 자식의 padding만 보고 간격을 맞추면 어긋난다.**
   왜 8px인지 코드에 주석으로 남겼다.

### 3.10 삭제 확인 문구 톤 — 사용자 지적으로 손질

브라우저 확인 중 「경고가 너무 무섭다」는 지적을 받아 문구를 다시 썼다. **정보는 그대로 두고 톤만** 낮췄다.

| | 전 | 후 |
|---|---|---|
| 제목 | `확인` | `품종 삭제` |
| 본문 | `정말 삭제하시겠습니까?` | `「흑미」 품종을 삭제할까요?` |
| 경고 | `…매칭실패로 돌아갑니다.` | `…다음부터 품종을 다시 이어 줘야 해요.` |
| 폴백 토스트 | `삭제에 실패했습니다.` | `삭제하지 못했어요.` |

- 제목 `확인`은 **무엇을 확인하는지가 없어** 불안을 키운다. 화면 이름을 넣었다
- 품종명을 본문에 넣어 **오삭제 방지**에도 도움이 된다(정보가 줄지 않고 늘었다)
- 같은 사실이라도 「사고 통보」가 아니라 「할 일 안내」로 적는다

빨간 확인 버튼은 그대로 뒀다 — `destructive: true`를 쓰는 12곳에 일괄로 먹고,
그 빨강은 「되돌릴 수 없다」는 안전 신호라 약화하면 다른 화면이 손해다.

### 3.11 🔴 알림 다이얼로그 딤만 혼자 80%였다 (공용 수정)

이어서 「배경이 너무 꺼멓다」는 지적을 받아 확인해 보니 **앱 안에서 값이 어긋나 있었다.**

| 컴포넌트 | 딤 |
|---|---|
| `components/ui/alert-dialog.tsx:21` | `bg-black/80` ← **혼자 진함** |
| `components/ui/dialog.tsx:41` | `bg-black/50` |
| `components/ui/sheet.tsx:39` | `bg-black/50` |

같은 화면에서 ⋯ → **수정**을 열면 50%, ⋯ → **삭제**를 열면 80%로 확 어두워졌다.
shadcn이 두 컴포넌트에 다른 기본값을 주는데 맞춘 적이 없었던 것이다.

→ `bg-black/50`으로 통일했다. **임의로 고른 값이 아니라 이 앱이 이미 쓰던 값**이다.
(`bg-black/80` 뒤에 붙어 있던 공백 2칸도 정리)

영향: `confirmDialog` 호출 33곳 + `AlertDialog` 직접 사용 4곳
(생산자·도정·원물재고 일괄삭제, 원물재고 엑셀 버튼). 오버레이 `className`을 덮어쓰는 호출부는 없다.

📌 **교훈: 「너무 무섭다/어둡다」는 취향 진술로 들리지만, 먼저 같은 앱의 같은 종류 값과 대조해 본다.**
   이번엔 취향이 아니라 일관성이 깨진 자리였다.

## 5. 확인이 필요한 사항

### 5.1 브라우저 확인 (필수) — dev 서버에서

1. 체크박스 열 · 상단 삭제 버튼 없음, 칩은 「전체」 선택 상태
2. 검색과 「품종 등록」이 **한 줄**에 있는지
3. ⋯ → 수정 → 다이얼로그가 **열린 채 유지**되는지 (메뉴 닫힘에 같이 사라지지 않는지)
4. 🔴 ⋯ → 삭제 → **별칭 있는 품종은 별칭 경고가 뜨는지** (§3.1 회귀 방지 핵심) — ✅ 확인됨
4-1. 딤이 수정 다이얼로그와 같은 밝기인지 (§3.11) · 다른 화면 알림 다이얼로그도 함께 밝아졌는지
5. 재고·포장·제품유형에 연결된 품종 삭제 → 서버 거부 toast
6. 칩 「흑미 1」 → 1건, 「전체」 복귀
7. 검색 `가바` → 서농22호(별칭 매칭)
8. 칩 「찰벼」 + 검색 `가바` → 0건 → 「조건에 맞는 결과가 없어요」 + 전체 보기
9. 🔴 **흑미가 인디카 다음** — 데스크탑 표 · 모바일 그룹 **양쪽**
10. `SUPPLY_MANAGE` 없는 계정 → ⋯ 열 · 등록 버튼 없음, 목록 · 별칭 · 검색 · 칩은 정상
11. 모바일 — 카드 ⋯ 메뉴 동작, 체크박스 없음, 하단 FAB 없음
