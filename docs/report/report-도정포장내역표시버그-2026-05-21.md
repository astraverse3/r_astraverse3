# 결과보고서 — 도정 포장내역 표시 버그 핫픽스

> 작성일: 2026-05-21
> 분류: 긴급 버그 수정 (회귀)
> 변경 파일: `app/(dashboard)/milling/add-packaging-dialog.tsx` (1파일)

## 증상

도정목록에서 출고중량/상태를 클릭해 포장 다이얼로그를 열면, **포장단위별 포장내역이 안 보이는 배치가 많음**.

## 원인 (확정)

어제 커밋 `6428ba3`(도정 상태 3단계 통일)에서 `getMillingLogs`의 stocks 조회에 정렬이 추가됨:

```js
orderBy: [{ farmer: { name: 'asc' } }, { bagNo: 'asc' }]   // 이전: 정렬 없음(자연순)
```

다이얼로그(`add-packaging-dialog.tsx`)는 포장내역을 다음과 같이 그룹 매칭했음:

```js
const getGroupOutputs = (group) =>
    outputs.filter(o => o.stockId === group.representativeStockId)  // 단일 대표 1개에만 매칭
```

- `representativeStockId`는 `computeLotGroups`가 **정렬된 stocks의 "첫 번째 stock"**을 그룹 대표로 선정한 값.
- 정렬이 `id순` → `농가명+bagNo순`으로 바뀌면서, **같은 lot 그룹에 stock이 2개 이상이면 "첫 stock"이 달라짐** → 대표 ID 변경.
- 과거 포장내역(output)은 **옛 대표 stock id**로 저장돼 있어 새 대표와 매칭 실패 → 화면에서 누락.
- 추가로, lot 통일 마이그레이션(`f031537`)이 `incomingDate`를 바꿔 `generateLotNo` 기반 groupKey에도 영향을 줌(윤영식 IPS 건).

**lot 그룹에 stock이 여러 개인 배치에서만 발생** → "안 나오는 게 많다"와 일치.

## 진단 (데이터 검증, read-only)

| 항목 | 값 |
|---|---|
| 포장내역 있는 배치 | 122개 |
| 어제 정렬 변경으로 새로 깨진 배치 | **67개** |
| 화면에서 사라진 포장내역 | **180건** |
| `output.stockId = null` (다른 원인) | 0건 |

**데이터 손실 아님**: output 레코드는 DB에 그대로 존재. 다이얼로그 그룹 매칭 키만 어긋난 **화면 표시 버그**. 마이그레이션이 데이터를 삭제한 것이 아님.

## 수정

매칭 기준을 "단일 대표 stock" → **"그룹에 속한 모든 stockId 집합"**으로 변경. 정렬·대표가 어떻게 바뀌어도 안 깨짐.

1. `LotGroup` 타입에 `stockIds: number[]` 추가
2. `computeLotGroups`가 각 그룹의 모든 `stock.id`를 `stockIds`에 수집
3. `getGroupOutputs`를 집합 매칭으로 변경 (stockIds가 비면 fallback으로 전체 노출)

```js
const getGroupOutputs = (group) => {
    const ids = new Set(group.stockIds)
    return outputs.map((o, i) => ({ o, i }))
        .filter(({ o }) => ids.size === 0 || ids.has(o.stockId))
}
```

어제 추가된 stocks orderBy(표시 순서 안정화)는 **그대로 유지** — 매칭만 견고하게 만들어 부작용 없음.
