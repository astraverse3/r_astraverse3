## 2. 주요 결정 사항

1. **§52(구 계획서 번호) 대시보드 11/1 건 삭제 — 오탐이었다.** 에이전트는 「토글 보류 근거(내년 10월까지 25년산)가 코드와 다르다」고 짚었다. 사용자에게 확인하니 의도는 **「2026-10-31까지 25년산, 11-01부터 26년산」**이었고, 코드(`DASHBOARD_NEW_CROP_MONTH = 11`)도 그대로였다. 틀린 건 계획서 문구였다 → 계획서·메모리를 정정하고 뒤 번호를 하나씩 당겼다.
   📌 교훈: 문서와 코드가 어긋나면 **어느 쪽이 틀렸는지 사용자 의도부터** 확인한다(메모리 `backlog_single_source`에 기록).
2. **작은 항목은 모음 §로** 묶었다(사용자 승인). 전부 개별 §로 올렸다면 §110 가까이 갔다.
3. **색인 표**를 파일 머리에 넣었다(사용자 승인). 닫으면 색인에서 뺀다.
4. **올리지 않은 것**: 포장 배너 작성자 표시 — 사용자가 「보류·**먼저 꺼내지 말 것**」이라 했다(`4727bef`). 대시보드 연도 토글 — 사용자 결정으로 넣지 않았다(위 1과 별개로 결정은 유효).
5. 메모리 `project_todo_2026_09_29` 삭제 — 파일에 「다 끝나면 삭제」라고 적혀 있었고, 남은 ⏸ 2개(§73·§74)와 사용자 판단은 전부 백로그 본문으로 옮겼다.
