## 1. 증상과 원인

390px에서 다이얼로그 **안쪽 콘텐츠가 11px 넘쳤다.** 페이지 자체는 정상
(`html scrollWidth 390 == clientWidth 390`)이고 **다이얼로그 내부만** 넘쳤다.

```
DIV [dialog-content]     w=358  client=356  scroll=367   ← 11px 넘침
  DIV [grid min-w-0]     w=308  sw=343                   ← 부모 트랙은 308로 정상
    DIV [grid-cols-2]    w=343                           ← 자식이 343으로 부풂
      DIV [space-y-2]    w=163                           ← 146이어야 할 칸이 163
      DIV [space-y-2]    w=163                             (163+163+gap16 = 342)
```

**원인**: `grid` 칸(`div.space-y-2`)에 `min-w-0`이 없었다. grid item의 기본
`min-width: auto`는 **자식의 min-content를 최소폭으로 삼는데**, 그 안의 드롭다운이
`whitespace-nowrap`이라 「재고량 많은순」 글자폭 **163px이 그대로 칸의 하한**이 됐다.
컬럼이 `146×2`로 줄지 못하고 `163×2`로 굳으면서 308px 자리에 343px가 들어간 것이다.

## 2. 진단 과정에서 두 번 헛짚었다 — 기록해 둔다

| 시도 | 가설 | 결과 |
|---|---|---|
| 1차 | `SelectTrigger`의 `w-fit`이 최소폭을 강제한다 | **부분적으로만 맞음.** `w-full min-w-0`으로 고쳤으나 증상 그대로 |
| 2차 | 트랙을 `grid-cols-[minmax(0,1fr)_...]`로 못 박으면 된다 | **틀림.** 클래스는 DOM에 붙었지만 **Tailwind가 CSS를 생성하지 않았다** (콤마 포함 임의값). 실제 트랙은 `auto`로 동작 |
| 3차 | grid 칸에 `min-w-0`(기본 유틸리티) | **해결.** 사용자 실기기 확인 완료 |

🔴 **교훈 1 — 레이아웃 문제는 눈대중으로 두 번 헛짚을 동안 실측 한 번이면 끝났다.**
`clientWidth`/`scrollWidth`와 자식 트리의 `w=`를 찍자마자 범인이 한 줄로 나왔다.
스크린샷 픽셀을 재는 건 스케일·캡처 오차 때문에 신뢰할 수 없다.

🔴 **교훈 2 — 콤마가 든 Tailwind 임의값(`grid-cols-[minmax(0,1fr)]`)은 CSS가 안 만들어진다.**
클래스가 DOM에 보인다고 적용된 게 아니다. `getComputedStyle`로 확인해야 한다.
**기본 유틸리티로 풀 수 있으면 임의값을 쓰지 말 것.**

**코드 5파일**

`SelectTrigger`의 `w-fit`은 shadcn 기본값(툴바용 컴팩트 select 전제)인데,
이 프로젝트는 **전부 `<Label>` 아래 폼 필드**로 쓴다. `w-full`을 명시하지 않은
15곳을 전수 확인해 **일부러 `w-fit`을 쓰는 곳이 없음**을 확인하고 프리미티브를 바꿨다.
이 한 줄로 도정 필터·원물 입고·잡곡 입고·농가 추가 등 15곳이 함께 정렬된다.
