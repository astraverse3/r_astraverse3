## 주요 결정

- **기존 액션을 그대로 불렀다(쿼리를 복사하지 않았다).** `getBatchOutputs`의 select는 「`getMillingLogs`와 정확히 같아야 한다」는 약속이 걸려 있어서, 복사본을 만들면 어긋날 자리가 하나 는다
- **부분 실패를 각자 처리한다.** 결과를 `{ outputs, packagings, specs }`처럼 각자의 `{ success }`째 돌려준다. 포장 내역을 못 받으면 지금처럼 쓰기를 막고 토스트를 띄운다(P3). 포장지를 못 받으면 「불러오지 못함」, 규격을 못 받으면 고정 목록만 보여준다. 호출 자체가 끊기면(`settle` 실패) 셋 다 실패 분기로 간다
- **바깥 가드는 두지 않았다.** 안쪽 셋이 각자 `try` 안 첫 줄에서 세션을 확인한다. 바깥에 하나 더 두면 세션 확인이 병렬 앞에 직렬로 한 번 더 붙는다. 이유는 액션 주석에 적었다
- **예상치는 그룹별 품종으로 계산한다.** 목록 배지는 배치 대표 품종 하나로 판정하지만, 이 다이얼로그는 이미 로트 그룹 단위로 보여 주고 그룹마다 품종 타입이 있다
- **규격 버튼은 열 때만 받는다.** 예전 훅은 품종 구성이 바뀌면 다시 받았지만, 한 배치의 투입 재고는 다이얼로그가 열려 있는 동안 바뀌지 않는다. 규격 때문에 재조회하면 포장 내역까지 다시 받아 입력 중인 값을 덮어쓴다
- `use-sku-spec-buttons.ts`와 재포장 다이얼로그는 건드리지 않았다
