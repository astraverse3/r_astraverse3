## 2. 주요 결정 사항

- **데이터는 건드리지 않았다.** DB를 세어보니 날짜 저장 규칙이 UTC 자정과 KST 자정으로 섞여 있었다.
  KST 하루 `[UTC 전날 15:00, UTC 당일 15:00)` 안에 둘 다 들어가므로 **읽기만 KST로 바꾸면 둘 다 맞는다.**
  - 지금 화면에서 실제로 틀렸던 행: 차감 발생일 **102** · 원물 출고일 **9** · 매입일 **1**
  - 나머지(원물 입고 2,117 · 도정 202 · 발주 76 · 포장 713 …)는 표시가 그대로다.
- **헬퍼는 프로세스 시간대에 기대지 않는다.** +9시간 후 `getUTC*`만 쓴다. 테스트는 `TZ=UTC`와 `TZ=Asia/Seoul`로 두 번 돌렸다.
- **범위 추가 3건** (계획서 밖, 같은 부류라 같이 처리):
  1. 매입 행 생산연도 필터(UTC 1월 1일 → KST): `package-where.ts` 안, 포장일자 범위 바로 옆
  2. 로트번호 YYMMDD: 원물 입고일이 전부 UTC 자정이라 **기존 로트와 결과가 같다**(재발급 없음)
  3. 원물 엑셀 입고일자
- **파일명은 8곳**이었다(계획서엔 7곳으로 적었음).

1. **제품재고(벼) → 차감 이력**: 메모 「기능 오픈 전 일괄차감」 102행(2026-09-28 16:17~16:23 등록, 백옥찰·서농22호·천지향1세·하이아미)이 `26-09-28`로 보이는지 (전엔 `26-09-27`).
   ⚠️ 백로그 §39의 9/8 예시 건은 9/9 차감 데이터 정리 때 지워져 지금 DB에 없다.
2. **발주서 목록과 매트릭스 머리글**: 발주일·상차일이 서로 같은지, 전과 같은지
3. **원물 수정 다이얼로그**: 입고일이 목록과 같은 날짜로 채워지는지
4. **제품재고 포장일자 검색**: 전과 같은 결과가 나오는지
5. ⚠️ 4단계(검색 범위·엑셀 날짜·감사로그 일시)는 **개발 서버에선 달라진 게 안 보이는 게 정상**이다(개발 PC가 KST라서). 실서버에 배포한 뒤 감사로그 엑셀의 「일시」가 한국 시각으로 찍히는지 한 번 보면 된다.
