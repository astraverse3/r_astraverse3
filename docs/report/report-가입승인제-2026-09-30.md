## 주요 결정

- **스키마 안 바꿈**(사용자 합의). 사용자를 만드는 경로가 `profile()` 하나다. `role`은 문자열이라 새 값을 넣을 수 있다. 마이그레이션 위험(9/22 P1002)을 피했다
- **REVOKED도 `/pending`으로.** 로그인 화면으로 보내면 미들웨어와 무한 왕복이 된다
- **거절 = 삭제.** 다시 로그인하면 또 대기로 뜬다(영구 차단 없음)
- **승인은 전용 액션**(`approveUser`), `where role=PENDING` — 기존 `updateUserRole`(ADMIN↔USER)은 안 넓혔다. 다른 탭에서 이미 처리된 사람을 다시 바꾸지 않는다
- **뱃지는 모바일에도.** 시안은 사이드바만이었다. 「관리자 메뉴」가 접혀 있거나 모바일 톱니 안이면 안 보여서 점을 더했다
- **관리자 알림은 2단계에서 헤더 종 아이콘으로**(사용자 9/30) — 디자이너에게 요청. 개인 알림·쪽지는 §90

## 확인이 필요한 사항

1. 🔴 **배포 후 기존 계정(ADMIN·USER)이 평소처럼 들어가지는지** — 11명 전원이 영향권이다. 막히면 이 커밋을 바로 되돌린다
   - 이미 로그인해 있던 사람도 다음 요청 때 jwt 콜백이 DB 역할(USER/ADMIN)을 다시 읽는다 → 재로그인 필요 없음(예상)
2. **새 카카오 계정**(안 쓰는 계정)으로 로그인 → `/pending` · 주소창 `/raw-stocks` → `/pending` · 사이드바·모바일 톱니에 점 → 사용자 관리에서 승인 → 그 계정 새로고침 1회로 대시보드
3. 거절 → 그 계정이 다시 로그인하면 대기 목록에 또 뜨는지
