## 주요 결정

- **원인**: 「같은 규격이면 개수 +1」 병합은 라인별 포장지(`c7b03d5`, 6/17) 전부터 있던 동작인데, 포장지가 생긴 뒤에도 규격만 보고 합쳤다. 서버(행 id diff)·DB(유일 제약 없음)는 원래 막지 않았다 → 화면만 고쳤다
- **겹침 검사는 화면만** — 같은 포장지 두 줄은 SKU가 깨지는 게 아니라(§54와 다르다) 지저분할 뿐
- **이미 저장된 줄끼리 겹친 건 막지 않는다** — 둘 다 차감이 붙어 있으면 합칠 방법이 없어 저장이 영영 막힌다. 새 줄(id 없음)이 섞인 묶음만 막는다
- 톤백·잔량은 원래 누를 때마다 새 줄 — 겹침 검사에서도 뺐다
- 테스트를 쓰다 잡은 것: 처음엔 제외 조건을 `needsPackagingPick`으로 걸어 **톤백이 겹침 검사에 들어갔다**(톤백은 포장지가 있어 false) → 「톤백·잔량은 여러 줄이 정상」 테스트가 잡았고 `picksPackaging`으로 고쳤다

## 확인이 필요한 사항

- 규격 버튼을 **연타해 개수를 세던** 습관이 있으면 이제 빈 줄이 늘어난다(포장지가 비어 저장에서 걸린다). 개수는 줄의 ±·개수칸으로
- 같은 그룹 안 **대표 재고가 아닌 재고**의 옛 줄과는 「같은 규격」으로 안 본다(예전 병합 기준과 같은 `stockId` 기준). 새 줄은 늘 대표 재고로 들어간다
