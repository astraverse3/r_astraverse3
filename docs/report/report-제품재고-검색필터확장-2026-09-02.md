# 결과보고서 — 제품재고(/packages) 검색 필터 확장

작성일: 2026-09-02

## 변경 사항 요약

제품재고 검색이 생산연도·품종·출처·정렬 4개뿐이라 재고를 좁히기 어려웠다.
원물재고 탭을 참조해 3종을 추가하고, 생산연도 기본값 규칙도 맞췄다.

| 추가 필터 | URL 파라미터 | 매칭 | 노출 |
|:---|:---|:---|:---|
| 포장일자 기간 | `packedFrom` · `packedTo` | 시작·종료 각각 선택 가능, **양 끝 포함** | 벼·잡곡 |
| 생산자 / 농가명 | `farmerName` | 부분일치, 콤마 다중(OR) | 벼·잡곡 |
| 인증구분 | `certType` | 멀티선택(유기농/무농약/일반) | **벼 탭만** |

### 신규 `lib/package-where.ts` (+ 테스트 17개)

`getPackages`(목록)와 `exportPackages`(엑셀)가 **where 조립을 두 벌 복붙**해 갖고 있었다.
필터가 6개로 늘면 한쪽만 고치는 사고가 확정적이라 — 화면과 엑셀 결과가 조용히 달라지는,
가장 알아채기 어려운 종류의 어긋남이다 — 순수 함수로 먼저 뽑았다.

- `app/actions/packages.ts`는 `'use server'`라 동기 헬퍼를 export 할 수 없어 `lib/`로 분리해야만 공유된다.
- 필터 타입(`PackageFilterParams`·`PackageSource`·`PackageCategory`)의 단일 원천도 이 파일로 옮겼다.
  `packages.ts`가 별칭으로 재export 하므로 **클라이언트 import 경로는 그대로**다.

### 신규 `lib/production-year.ts` (+ 테스트 10개) — 추가 요청

같은 「11월 기준」 한 줄이 **7곳에 복붙**돼 있었다. 벼와 잡곡은 수확철이 다른데
한 규칙을 쓰고 있던 게 문제의 뿌리였다.

| | 1~5월 | 6~9월 | 10~12월 |
|:---|:---|:---|:---|
| **벼** 검색 | 전년 | 전년 | 올해 + 전년 |
| **잡곡** 검색 | 전년 + 재작년 | 올해 + 전년 | 올해 + 전년 |

- 벼는 가을 한 번 → 수확기에 두 해를 함께 본다(11월 → **10월**로 앞당김)
- 잡곡은 여름·가을 두 번, 6월부터 당해년도분 유입 → **항상 2년분**
- 등록 폼처럼 한 해만 찍는 곳은 `defaultProductionYear()` 별도 (벼 11월 / 잡곡 6월)

적용 7곳 — 값이 실제로 바뀌는 4곳(제품재고 검색, 원물 벼 검색, 원물 잡곡 검색, 잡곡 입고 등록)과
값은 그대로지만 단일 원천으로 묶은 3곳(벼 입고 등록, 작목반 cropYear, 판매 기간 시작).

🔴 **`useMemo` 필수** — 기본값이 문자열에서 **배열**로 바뀌었다. 렌더마다 새 참조가 생겨
URL 동기화 `useEffect` 의존성에 그냥 넣으면 무한 루프에 빠진다. 세 검색 필터 모두 감쌌다.

원물재고 벼 탭은 모바일 자동열림 판정(`val === defaultYear`)에도 기본값 비교가 있어
`defaultYears.join(',')`로 함께 맞췄다 — 안 고쳤으면 기본 상태인데도 필터가 걸린 것으로 오판한다.

## 주요 결정 사항

1. **인증구분은 벼 탭에만 노출** (사용자 확정)
   인증은 `stock → farmer → group.certType` 경로로만 알 수 있다. 잡곡 매입(PURCHASED)은
   `stock`이 없어 인증 정보가 아예 없으므로, 잡곡에 이 필터를 걸면 매입 재고가 통째로 빠져
   **재고가 사라진 것처럼 보인다.** UI에서 아예 뺐다(액션은 파라미터가 들어오면 적용).

2. **생산자 검색 = 목록의 「생산자」 컬럼에 보이는 값 그대로** (사용자 확정)
   도정산은 `farmer.name`·`actualFarmer`, 매입은 `purchaseVendor`까지 OR로 본다.
   화면에 보이는 걸 치면 걸리게 하는 게 원칙.

3. **포장일자도 목록의 「포장일자」 컬럼과 같은 기준**
   MILLED는 `createdAt`, PURCHASED는 `incomingDate`(없으면 `createdAt`) — 3분기 OR.
   이게 어긋나면 "보이는 날짜로 검색했는데 안 나온다"가 된다.
   종료일은 당일 포함(`lt: 종료일+1일`), 로컬 자정 기준(UTC로 만들면 하루씩 밀린다).

4. **잘못된 날짜는 필터를 만들지 않는다**
   `2026-02-31` 같은 값을 `Date`가 조용히 3월로 굴려버리는 걸 되돌려 확인해 막았다.

5. **생산연도 기본값 = 원물재고와 같은 규칙** (추가 요청)
   11월부터 당해년도, 그 전까진 전년도. 원물재고와 마찬가지로 **서버 기본값이 아니라**
   다이얼로그 위젯의 초기 선택값 + 초기화 시 되돌아갈 값이다. 즉 첫 진입(URL 비어 있음)에는
   여전히 전체가 보이고, 「적용하기」나 「초기화」를 눌러야 그 연도가 걸린다.

## 확인이 필요한 사항

1. **잡곡 제품재고에서 「초기화」를 누르면 2026·2025 두 해가 걸린다.**
   잡곡 매입 제품은 생산연도가 **매입일 연도**로 판정된다. 2년분을 보므로 종전보다는
   훨씬 덜 잘리지만, 2024년 이전 매입분은 여전히 기본 화면에서 빠진다.

2. **생산자 검색은 부분일치**라 "김"만 쳐도 다 걸린다(원물재고와 동일).

3. 브라우저 확인 부탁 —
   - 벼 탭에 인증칸 있고 잡곡엔 없는지
   - 기간이 「포장일자」 컬럼과 어긋나지 않는지(종료일 당일 포함)
   - 매입 잡곡이 매입처명으로 걸리는지 / 엑셀이 화면과 같은 범위로 나오는지
   - **검색을 열었을 때 생산연도에 두 해가 찍혀 있는지** (오늘 9월 기준: 벼 = 2025 한 해,
     잡곡 = 2026·2025 두 해). 10월이 되면 벼도 두 해가 된다
   - 모바일에서 원물재고 벼 탭 자동열림이 종전처럼 동작하는지
