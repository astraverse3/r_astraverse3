### 남은 것 (의도적으로)

- **`rematchUpload` · `loadMatchPatch` · `applyMatchPatches`** — 재매칭이 계속 쓴다.
  🔴 매칭실패를 푸는 **유일한 경로**가 됐다.
- **`hasMillingToken` + 테스트 4건** — 안내가 「이 이름은 별칭으로 등록할 수 없다」를 미리
  알려 주는 데 쓰고, 앞으로 품종 별칭 관리 화면의 검증(`lib/variety-alias.ts`)이 이어받는다.

### 새 안내 (결정 Z)

사유마다 **갈 곳이 다르다는 걸 명시**한다. 「매칭 실패」 한 줄로 뭉개면 품종 관리와 제품유형 관리 중
어디로 가야 할지 알 수 없다.

| 실패 사유 | 문구 | 갈 곳 |
|---|---|---|
| `variety_unresolved` | 「가바현미」가 어느 품종인지 몰라요 | **품종 관리** — 별칭 등록 (또는 품종 신규 등록) |
| `packaging_unresolved` | 서농22호 현미 2kg에 맞는 포장지 「PET」 제품유형이 없어요 | **관리자 메뉴 › 제품유형 관리** |
| `sku_unresolved` | 서농22호 백미 800g 제품유형이 등록돼 있지 않아요 | **관리자 메뉴 › 제품유형 관리** |

- 공통 꼬리: 「등록한 뒤 위의 **재매칭**을 눌러 주세요」
- 범위 표시 유지: 「이 품목 열 **3수령인 · 7라인** (120개)이 같이 막혀 있어요」 —
  셀 하나가 아니라 열 전체가 막혀 있다는 걸 보여 줘야 마스터를 고칠 값어치가 보인다
- 도정 단어가 섞인 이름이면 한 줄 덧붙인다 — 품종 관리에 가서 거절당하는 헛걸음을 미리 막는다
- 🔴 **링크로 새 탭을 열지 않는다**(D2e 2026-09-15 판단 유지). 메뉴 이름만 일러 준다

## 2. 주요 결정 사항

### ① 수동지정을 UI·액션까지 통째로 제거 (사용자 결정)

「초기 안정화되면 거의 발생하지 않을 일. 굳이 이 기능을 안 써도 된다.」

**D2e 실측이 이미 말해 주고 있었다** — 매칭실패 18건 중 지정으로 풀리는 건 2건뿐이었고
(#16 천지향5세 10kg · #17 가바현미 PET) 나머지는 SKU 카탈로그 빈칸이라 어차피 마스터 화면에
가야 했다. **팝오버가 풀어 주는 척만 하고 있었다.**

### ② 🔴 별칭 편집 권한 `OPERATION_MANAGE` → `SUPPLY_MANAGE` (사용자 결정)

「품종관리 메뉴 권한자가 수정하는 걸로 하자. 별칭을 중구난방으로 관리하면 안 될 것 같아.」

별칭 계획서 결정 V는 `OPERATION_MANAGE`를 주장했고 근거가 「학습이 이미 그 권한으로 열려 있으니
보기·지우기도 같아야 앞뒤가 맞는다」였다. **그 학습 경로가 사라져 근거가 통째로 무너졌다.**
계획서 §2.2가 문제 삼던 「만들 수는 있는데 되돌릴 수는 없는 상태」도 **만들 수도 없어져서**
자연 해소됐다. → 별칭 계획서에 결정 V′로 반영.

### ③ 사용자 지적 2번(「SKU 없는데 품종 셀렉트박스가 나온다」)의 정체

단순한 UI 군더더기가 아니었다. 기존 코드는 **서버가 이미 아는 실패 사유를 사용자에게 다시
물어보고 있었다** — `varietyId === null`일 때만 「품종 관리에서 등록하세요」를 띄우고, 품종을
골라야 비로소 「이 품종에 제품유형이 없어요」가 나왔다. 안내 전용은 사유를 곧바로 말한다.

### ④ 철회하되 지우지 않는다

D2e 계획서의 결정 N·O·P·S·T는 **취소선 + 철회 사유**로 남겼다. 왜 만들었다 없앴는지가
기록으로 남아야 한다. 결정 Q·R(갱신 방식·재매칭)은 그대로 유효.

## 4. 확인이 필요한 사항

### 브라우저 확인 (사용자)

1. 매트릭스에서 **매칭실패(빨간) 셀** 클릭 → 안내만 뜨는지, 「지정 저장」이 없는지
2. **사유 3종이 실제로 구분돼 보이는지** — 현재 데이터에 `variety_unresolved`와 SKU 없음이 둘 다 있다
3. 도정 단어가 섞인 이름(`백미 천지향5세`)에 추가 안내가 붙는지
4. 🔴 **「재매칭」 버튼이 여전히 동작하는지** — 매칭실패를 푸는 **유일한 경로**가 됐으므로 필수

### 남은 작업

- **품종 별칭 관리 화면** — 계획서 `plan-품종별칭-관리화면.md`가 승인 대기 중이다.
  결정 V′는 반영했고, **§8 ②(별칭 열을 목록에 항상 보일지)가 아직 미결**이다.
  🔴 이 화면이 없으면 **별칭을 만들 수단이 아예 없다**(학습 경로를 없앴으므로). 우선순위가 올라갔다.
- 그 뒤 **D3 행 일괄**.

### 감수한 비용

`OPERATION_MANAGE`만 가진 3명(임승원·민채·이영명)은 매칭이 막혀도 **스스로 풀 수 없다.**
`SUPPLY_MANAGE` 보유자에게 요청해야 한다. 안내가 「품종 관리에서 별칭 등록」이라고 정확히
말해 주므로 요청 내용은 분명하다.
