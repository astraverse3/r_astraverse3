## 3. 계획서에 없던 발견 3건 (실파일 대조 중)

### 3.1 이마트 시트 하단의 별도 표 — 과잉 적재 위험이었음

`이마트_260819`는 발주 데이터(6~8행) 아래 빈 행 2줄을 두고 **박스 환산표**가 이어진다.

```
r5~r7  이마트 | 여주지점 | … 112  ← 실제 발주
r8·r9  (빈 행)
r10    · | · | 현미1kg | 가바4kg …   ← 별도 표의 헤더
r11~13 이마트 | 여주지점 | … 7박스   ← A열이 채워져 있어 발주로 오인됨
```

구 파서 로직이면 r11~13이 발주로 들어가 **같은 수령처가 2배로 적재**된다.

- **빈 행을 종료 신호로 쓸 수 없다** — `택배_260818`은 빈 행 2줄(72·73행) 뒤에 실제 발주(해남로컬푸드)가 이어진다.
- → 판정 규칙: **A·B가 비었는데 규격 열에 「텍스트」가 있으면** 그 아래는 별도 표로 보고 종료 + 경고. 수량은 숫자이므로 발주 데이터와 구분된다.

### 3.2 소계 검증은 「열」 단위여야 함

같은 품목명+규격이 여러 열에 나뉜 시트가 있다(택배 하이아미 5kg = I·K열, 시아스 톤백 = B·C열). 품목 기준으로 합계를 내면 열별 소계와 어긋나 **가짜 경고**가 뜬다. `extractOrders()`가 열별 합계(`sumsByCol`)를 함께 반환하도록 바꿔 해소했다.

### 3.3 포장지 줄바꿈 (조치 불필요)

택배 시트 포장지 셀이 `자연⏎주의`라 정규화하면 `자연 주의`가 되어 이마트의 `자연주의`와 달라진다. 확인해보니 **매처가 이미 `stripSpaces` 비교**를 하고 있어 매칭에는 영향이 없다. 파서는 원본을 보존한다. 단, 톤백 판정은 공백 제거 후 비교하도록 맞췄다.

- 최초 파싱 때 `서울급식_060818` 시트명이 2006년으로 읽혀 경고가 떴고, **사용자가 템플릿을 `서울급식_260818`로 수정**(2026-08-20). 위 표는 수정 후 기준이며, 오타 감지 자체는 `suggestOrderDate` 단위 테스트가 계속 지킨다.

## 5. 확인이 필요한 사항

1. ~~**이마트 하단 박스 환산표**~~ ✅ **해소 → 결정 #35** — 엑셀에 없어도 **시스템이 만들어 준다**. 입수는 SKU 속성(`ProductType.unitsPerBox Int?`, D1a 마이그레이션에 동반), 박스 수 = `ceil(수량 / 입수)`, 파렛은 자동화하지 않고 비고에 수기, 낱개 없음. 파서는 계속 이 표를 읽지 않는다. 상세는 계획서 §2 #35.
2. ~~**`서울급식_060818` 시트명 오타**~~ ✅ **해소** — 파서는 계획서 #31대로 시트명 날짜를 채택하고 경고만 남기는 방식을 유지하기로 확정(사용자: "경고해주면 바꾸는 건 어렵지 않다"). 템플릿 시트명도 `서울급식_260818`로 수정됨.
3. **채널 추측 범위** — 계획서는 「고정 prefix 4종 외에는 드롭다운 선택」이지만, `거래처명_YYMMDD` 형식이면 `CORPORATE`로 추측하도록 했다(시아스 사례). 화면에서 바꿀 수 있으니 정보 손실은 없다.
