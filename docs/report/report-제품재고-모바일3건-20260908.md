## 1. 🔴 모바일 체크박스가 아예 눌리지 않았다 (가장 무거운 건)

**증상**: 벼·잡곡 제품재고에서 재포장·차감 모드에 들어가도 **목록 체크박스가 체크되지 않는다.**
데스크탑은 정상.

**원인**: hit-area를 44px로 넓히려고 둔 투명 오버레이가 **체크박스를 덮고 있었다.**

```jsx
<span aria-hidden className="absolute -inset-2.5" />   // ← positioned
<input type="checkbox" ... />                          // ← static
```

CSS에서 **positioned 요소는 static 형제 위에 그려진다.** 오버레이엔 핸들러가 없으니
터치가 거기서 죽고 `<input>`까지 닿지 않았다. 데스크탑은 `package-row.tsx`의 다른
체크박스를 써서 멀쩡했다.

**처방**: 오버레이를 없애고 **`<label>`의 패딩**으로 hit-area를 만든다(음수 마진으로 자리 상쇄).
label은 클릭이 네이티브로 input에 전달돼 **터치 영역과 동작을 함께** 얻는다.

### 전수 대조 — 같은 패턴 4곳 중 2곳이 결함

| 위치 | 판정 |
|---|---|
| `mobile-package-card.tsx` 행 체크박스 | 🔴 결함 → label 패딩으로 교체 |
| `raw-stocks/stock-list-client.tsx:546` 원물재고 선택 | 🔴 결함 → 부모 패딩 + 토글로 교체 |
| `mobile-package-card.tsx:93` ⋮ 메뉴 | ✅ 정상 |
| `stock-list-client.tsx:578` ⋮ 메뉴 | ✅ 정상 |

🔴 **판별 기준 — 오버레이가 「핸들러를 가진 조상 안」이면 정상, 「형제」로 놓이면 클릭을 삼킨다.**
⋮ 메뉴 둘은 오버레이가 `<Button>` **안쪽**이라 버블링으로 버튼이 클릭을 받는다. 결함 둘은 형제였다.

⚠️ **원물재고는 왜 아무도 신고하지 않았나** — 그 화면은 **카드 본문 클릭으로도 선택**이 되어
체크박스가 죽어 있어도 티가 나지 않았다(사용자 증언). 대체 경로가 결함을 가리고 있었다.

## 2. 잡곡 툴바가 화면 밖으로 밀렸다

**원인**: 액션 바가 `flex ... justify-end`인데 **넘치면 `justify-end`는 왼쪽 항목을
컨테이너 밖으로 밀어낸다.** 스크롤도 안 되므로 **엑셀 버튼에 아예 손이 닿지 않았다.**
잡곡만 버튼이 6개(`+포장`·`+매입` 추가)라 걸렸고 벼는 4개라 여유가 있었다.

**폭 실계산 (390px, 가용 382px)**

| 요소 | 폭 |
|---|---|
| 엑셀 32 · 재포장 96 · 차감 96 · 필터 30 · 구분선 9 · `+포장` 64 · `+매입` 64 · gap 48 | **439** |

`min-w-[96px]`가 두 버튼에서 34px를 그냥 버리고 있었다(차감의 실제 필요폭은 72).

**처방** (사용자 선택 = 라벨을 살리는 안)
- 엑셀 버튼 **모바일 숨김**(`hidden sm:inline-flex`) — 폰에서 엑셀을 받는 일은 드물다
- 재포장·차감 `min-w-[96px]` → **`sm:min-w-[96px]`** (고정폭은 데스크탑만)
- → **365px**. 라벨은 전부 유지된다.

**그런데 작업 모드에서 다시 넘쳤다** — 활성 토글이 `차감 중 | ✕`로 길어진다(약 120px).
→ **모드 중에는 나머지 버튼을 모바일에서 숨긴다.** 어차피 전부 `disabled`라 못 누르던 것들이고,
화면엔 `차감 중 ✕`만 남아 오히려 명확하다. 데스크탑은 공간이 넉넉해 그대로 둔다.
래퍼는 `contents`를 써서 레이아웃에 끼어들지 않게 했다(버튼이 그대로 flex 항목으로 남는다).
`flex-wrap`도 안전판으로 남겨 두었다 — 예상 못 한 조합에서 잘리는 대신 접히게.

## 3. 그룹 헤더 「N종」이 행 수를 세고 있었다

`item.rows.length`는 **행 수**지 규격 종류가 아니다. **작업 단위로 행을 나누는 게 원칙**이라
(재포장할 때마다 행이 생긴다) 같은 규격이 여러 행으로 갈리면 그대로 어긋난다.

실제 사례 — 찰보리: `1kg × 90`과 `1kg × 8`이 별도 행이라 **「2종」**으로 표시됐다. 규격은 1종뿐이다.

→ `specCount = new Set(item.rows.map(r => r.spec)).size` (데스크탑 `package-row` · 모바일 카드 2곳)

### 왜 두 행인지도 확인했다 (결함 아님)

DB 조회 결과 **재포장을 두 번** 했다 — 08-28 08:40:57에 `1kg×98` → `1kg×90 + 4kg×2`,
08:41:30에 `4kg×2` → `1kg×8`. 1분 사이에 묶었다 되돌린 것이다.
**데이터는 정확하다**(같은 SKU·같은 로트, 각각 다른 `repackId`에 묶여 추적됨).

🔴 **사용자 결정: 행은 지금처럼 작업 단위로 나눈다.** 같은 SKU를 합치면 화면은 깔끔해지지만
차감 시 어느 레코드에서 뺄지 시스템이 정해야 하고 재포장 이력 추적이 흐려진다. **표기만 고친다.**
