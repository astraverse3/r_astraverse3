## 2. 주요 결정 사항

### A1 — 사용자가 0으로 만든 벼 11행은 0을 유지

실측 중 발견: 9/28 16:17~16:23 사용자가 「기능 오픈 전 일괄차감」 103건을 걸었고, 그중 15건이
**테스트 판매가 걸린 행**이었다. 테스트가 빼 간 나머지를 일괄차감으로 0으로 만든 것이다.

판매만 지우면 **17행 3,308kg이 목록에 되살아난다.** 사용자가 이미 「비었다」고 판단한 ★ 11행은
테스트 판매분 153개(888kg)를 같은 사유의 일괄차감으로 **추가**해 0을 유지했다.
기존 기록은 고치지 않았다 — 롤백 때 11건만 지우면 된다. 발생일·작업자는 그 행의 최근 일괄차감을 따랐다.

### B1 — 재포장은 #16·#17만 되돌림

13건 전부 판매 테스트 기간(9/14~9/28)에 생겼다. #16·#17은 새청무 톤백 10개를 쪼갰다가
**실물에 없는 10,050kg 톤백 1개**로 합친 것이고, 결과 행에 차감이 하나도 없어 깨끗하게 되돌릴 수 있었다.
나머지 11건은 결과 행 대부분에 사용자 일괄차감이 걸려 있어 남겼다(중량 보존됨).

### C1 — 마스터 데이터는 남김

매입 등록이 만든 `PURCHASED` 품종 5종·잡곡 SKU 20개는 카탈로그라 실제 매입·발주 때 다시 쓴다.

### 실행 안전장치

- 지운 개수를 **단계마다 트랜잭션 안에서 스냅샷과 대조** — 다르면 throw해 전부 롤백
- 삭제 대상은 전건 조건이 아니라 **스냅샷의 id 목록**으로 지정
- 중단은 `process.exit` 대신 throw — `$disconnect()`가 항상 불린다(9/22 P1002 교훈)
