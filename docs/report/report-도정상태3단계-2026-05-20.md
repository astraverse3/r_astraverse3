## 1. 변경 요약

기존 코드에서 혼용되던 도정 작업 상태 라벨을 3단계로 통일했다. 데이터 모델 변경 없이 `isClosed` + `outputs.length` 조합으로 3단계를 도출한다.

| 구분 | 변경 전 | 변경 후 |
|---|---|---|
| `isClosed === true` | "완료"(대시보드) / "마감"(목록·다이얼로그·엑셀) | **마감됨** (emerald) |
| `!isClosed && outputs.length > 0` | "포장" | **포장중** (amber + pulse) |
| `!isClosed && outputs.length === 0` | "포장" | **도정중** (sky) |

판정 규칙은 `components/ui/milling-status-badge.tsx` 의 `getMillingStatus()` 에 집약. UI 어디서든 `<MillingStatusBadge isClosed hasOutputs />` 만 호출하면 자동으로 3가지 배지가 렌더링된다.

## 3. 주요 결정 사항

### 3.1 배지 색상 — 시안 그대로 채택
[docs/handoff/components/status-system.jsx](./handoff/components/status-system.jsx) 시안의 조합:
- `milling`: sky-50 / sky-700 / sky-200 / sky-500 dot (static)
- `packaging`: amber-50 / amber-700 / amber-200 / amber-500 dot **+ `animate-pulse`** (일하는 중임을 시각화)
- `closed`: emerald-50 / emerald-700 / emerald-200 / emerald-500 dot (static)

### 3.2 URL 호환 — Legacy alias 유지
북마크된 `?status=open` / 외부 링크가 깨지지 않도록 다음 매핑을 유지:
- `open` (legacy) → `isClosed: false` (도정중 + 포장중 묶음, 기존 의미와 동일)
- `active` (legacy alias of `open`) → 동일
- `closed` → `isClosed: true`
- `completed` (legacy alias of `closed`) → 동일

`active-milling-filters.tsx` 의 라벨은 `open` 일 때 "진행중"으로 표시되어 사용자가 legacy 링크를 알아볼 수 있게 함.

### 3.3 엑셀 컬럼명 변경 — `진행상태` → `도정상태`
값도 3분기로 세분화 (`도정중 / 포장중 / 마감됨`). 외부 양식에서 컬럼명으로 파싱하는 경우가 있다면 한 차례 공지 필요. (영향 받는 외부 양식이 있는지는 사용자 측 확인 필요)

### 3.4 동사형 라벨은 그대로 유지
액션 버튼의 "마감완료", "마감 해제", "작업 마감", "포장하기" 등은 동작 표현이라 변경하지 않음. 상태 명사("완료"/"마감"/"포장")만 배지로 통일.

## 4. 작업 중 발견 사항

### 4.1 ⚠️ 기존 status 필터 버그 발견 및 동시 수정
- **URL 쿼리**: `?status=open` / `?status=closed` ([milling-filters.tsx:246-247](../app/(dashboard)/milling/milling-filters.tsx))
- **서버 액션 분기**: `params.status === 'active' / 'completed'` ([milling.ts:184-188](../app/actions/milling.ts))
- **page.tsx**: URL 값을 변환 없이 그대로 액션에 전달 ([milling/page.tsx:22](../app/(dashboard)/milling/page.tsx))

→ 키 불일치로 인해 **기존 status 필터가 실제로는 동작하지 않고 있었음**. 이번 작업에서 legacy alias(`open`/`closed`/`active`/`completed`) 모두 매칭되도록 분기에 추가해 함께 수정됨.

### 4.2 milling-filters.tsx 다이얼로그 fallback 수정
다이얼로그 열 때 URL에 `status`가 없으면 `'open'`으로 폴백되던 코드(L81) → `'ALL'`로 수정. L62 초기값과 일관되게.

### 4.3 hasOutputs 안전 접근
`log.outputs?.length ?? 0` 패턴으로 일관 적용. 일부 로그 객체에서 outputs가 누락된 케이스 방어.

> **실서버 QA 미실시 항목** (사용자 확인 필요):
> 1. `?status=milling` 으로 직접 접근 시 outputs 없는 도정만 필터링되는지
> 2. 도정 시작 → 포장 등록 시 배지가 도정중(sky) → 포장중(amber pulse) 자동 전환되는지
> 3. 마감 후 마감 해제 시 outputs 유무에 따라 적절한 배지로 복귀하는지
> 4. 엑셀 다운로드 `도정상태` 컬럼 값 3분기 확인

## 6. 확인이 필요한 사항

1. **외부 엑셀 양식 호환**: `진행상태` 컬럼명으로 외부에서 자동 파싱하는 경우가 있는지. 있다면 사용자에게 공지 필요.
2. **audit log 표기**: 기존 `auditLog` 테이블에 저장된 `"진행중"` 표기는 그대로 두었음. 추후 신규 변경분도 `"도정중"`/`"포장중"` 으로 세분화할지 후속 작업 결정 필요.
3. **모바일 카드 hover/click 영역**: 모바일 카드의 상태 클릭으로 마감 해제 → 포장 다이얼로그 자동 오픈 흐름은 그대로 유지. 사용자 테스트 시 자연스러운지 확인.
