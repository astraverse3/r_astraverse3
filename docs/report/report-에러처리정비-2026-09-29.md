## 2. 주요 결정 사항

1. **가드 이동 전 catch 108개를 전부 분류했다** — 가드를 `try` 안에 넣으면 권한 오류가 catch로 간다.
   catch가 `return []`이면 「권한 없음」이 「데이터 0건」으로 둔갑한다. 결과: 빈 값 반환 **0곳**이라 안전.
2. **「가드 뒤 첫 `try`」가 함수 최상위 `try`가 아닐 수 있다** — 루프 안이나 안쪽 헬퍼의 `try`면 가드가 엉뚱한 데로 간다.
   가드와 `try`의 들여쓰기가 같은 것만 자동 이동했고, 가드와 `try` 사이에 코드가 있던 2개(엑셀 가져오기)는 수작업.
3. **고정 문구 65곳은 권한·세션 오류만 갈라냈다**(사용자 선택) — `guardErrorMessage(error, '고정 문구')`. 그 밖의 오류 메시지 노출 정책은 그대로.
4. **클라이언트는 자리마다 catch를 짜지 않고 `settle()`로 감쌌다** — reject를 `{ success:false, error }`로 바꾸면 각 자리의 기존 `!res.success` 분기가 그대로 받는다.
5. **통계·설정은 `useSafeTransition`** — React 19는 transition 안의 throw를 에러 경계로 올리는데 `(dashboard)`엔 경계가 없다. 선언 한 줄만 바꿔 20곳을 덮었다.
6. **이미 쌓인 중복 감사로그는 안 지웠다** — 감사로그는 지우는 쪽이 더 나쁘다.
7. **계획서 밖 1건**: `lib/statistics-utils.ts` `resolveQuickPeriod` — 통계 첫 화면은 서버(UTC)에서 기간을 만든다. `setHours(23,59,59)`가 KST로 다음 날 08:59가 되어, 새 KST 경계와 만나면 **월말 오후에 다음 달 빈 칸이 생기는 회귀**를 이번 변경이 만들 뻔했다. 같이 고쳤다.
8. **`getPackages`·`getPurchaseVendors` catch가 `error.message`를 그대로 내보내고 있었다**(Prisma 원문이 화면에 샐 수 있던 두 곳) → `sanitizeErrorMessage`로. 가드를 안으로 넣으면 영문 `Unauthorized`가 뜨게 되는 자리라 같이 손댔다.

## 4. 확인이 필요한 사항

### 🖐 브라우저 (개발 서버, 개발자도구 Network → **Offline**)

1. **도정관리 → 포장 다이얼로그 열기** → 멈추지 않고 「포장 내역을 불러오지 못했습니다…」 토스트
2. **발주서 매트릭스 → 셀 누르기** → 팝오버가 「불러오는 중…」에 멈추지 않고 문구가 뜬다
3. **통계(도정·재고·판매·도정구분) → 기간 버튼** → 에러 화면으로 안 바뀌고 토스트

5. 통계 도정 탭 **주별 툴팁** `MM/dd ~ MM/dd`가 전과 같은지

### 문구

- 연결 문구 「서버와 연결이 끊겼어요…」는 **서버 쪽 throw(DB 오류 등)에도** 뜬다. 프로덕션 Next가 throw 메시지를 가려서 클라이언트가 원인을 구분할 수 없다. 대부분은 실제로 연결 문제(세션 만료 리다이렉트·배포 직후·네트워크)라 그대로 뒀다.
