## 3. 주요 결정 사항

| # | 결정 | 이유 |
| --- | --- | --- |
| D1 | **행 밀도는 3곳에서 손대지 않았다** | `recent-logs-list`는 카드 하나에 10건을 담는 대시보드 위젯. `upload-dialog`·`deduct-dialog`는 체크박스·select·date·number **입력 컨트롤이 들어간 편집형 행** — 44px를 강제하면 컨트롤 크기가 연쇄로 끌려오고 다이얼로그에 보이는 행 수가 준다 |
| D2 | **§32에 없던 2곳을 포함** | 백로그가 「전수로 잡아라」고 못 박았다. 지금 빼면 네 번째 누락이 된다 |
| D3 | 섹션 라벨 12곳은 **별건** → 백로그 §33 신설 | 목록 헤더(40px)와 규격이 다르다. 소제목의 크기·색을 먼저 정해야 한다 |
| D4 | **`recent-logs-list`는 `rounded-lg`를 유지**했다 (계획서와 다름) | 계획서엔 `border-b`를 넣는다고 적었으나, 부모가 `rounded-[24px]` + `px-3 sm:p-6` 카드였다. 카드 안에서는 **pill 형태가 컨테이너에 맞다**. 바꾼 것은 타이포·높이·배경톤 |

  (훑을 대상 5종 검색 명령 표 + 「판정 기준은 마크업이 아니라 화면」 + 편집형 행·위젯 예외)

## 7. 이번 작업이 남긴 교훈

**§32는 자기가 경고한 함정에 자기가 빠졌다.**
「`ui/table`을 쓰는 파일로 범위를 잡으면 계속 새는 구조」라고 적어 놓고,
정작 자신의 대상 목록은 `grep "uppercase tracking-wider"` **한 줄로만** 잡았다.
그래서 `uppercase`를 안 쓰는 목록(`upload-dialog`)이 통째로 빠졌고,
목록 헤더를 「섹션 라벨」로 오분류(`deduct-dialog:294`)했다.

→ 기준서 §4.2에 **검색 명령 5종을 표로** 박아 두었다. 다음엔 grep 한 줄로 범위를 잡지 않는다.
