## 2. S3 — 등록 모달 배송 블록

### 추천 조회를 5채널 전부로 (계획서 §6 수정)
계획서는 「파일에 등장하는 채널만」이었으나 **전 채널**을 조회한다.
사용자가 화면에서 채널을 바꿀 수 있어서(#31) 등장 채널만 조회하면 **바꾼 채널의 추천이 비어버린다**.
계획서가 든 비용 근거가 「시트 5장·5채널이라도 15행」인데, 채널당 `take: 3`이라 전부 조회해도 최대 15행으로 같다.
S1에서 깐 `channel+createdAt` 인덱스를 그대로 쓴다.

### 추천 판정은 순수함수로
`pickRecommendedVendor(recentVendorIds)` — **최빈값이 유일할 때만** 추천하고 동률·이력없음이면 null.
계획서 §6의 예시 3줄이 그대로 테스트 케이스다. 「동률이 뒤에서 깨지는」 경우(`[1,2,2] → 2`)도
`tied` 플래그가 남지 않는지 따로 검증했다.

**비활성 업체가 추천되면 걸러낸다** — 드롭다운에 없는 값이 선택된 것처럼 보이면 안 된다.

### 채널을 바꾸면 배송업체가 따라오되, 손댄 뒤에는 놔둔다
`SheetDraft.vendorTouched`로 구분한다. 사용자가 한 번이라도 직접 고르면 그 뒤로 채널을 바꿔도 건드리지 않는다.
고쳐놓은 값이 채널 변경으로 되돌아가면 안 된다.

추천으로 채워진 값(`vendorTouched === false`이고 값이 있는 상태)은 **파란 테두리**로 구분한다(시안 `.sel.auto`).

### 「직접 입력」인데 시각이 비면 등록 버튼을 막는다
처음엔 제출 직전에 조용히 `null`로 되돌리려 했는데, 그러면 **slot은 EXACT인 채 시각만 사라져** 서버 refine에 걸린다.
사용자가 그 토글을 고른 건 의도가 있으므로, 채널 미선택과 같은 결로 **버튼 비활성 + 하단 안내**로 막는다.

### `SheetRow` 분리 (계획서 §5 리스크 대응)
`upload-dialog.tsx`가 508줄이라 배송 블록을 그대로 넣으면 800줄 상한에 근접했다.
`sheet-row.tsx`(291줄)로 빼면서 `SheetDraft` 타입·`Warn`·`NOTE_MAX`를 함께 옮겼다. 모달은 400줄로 줄었다.

## 3. S4 — 목록 「상차」 열

### 정렬은 DB가 아니라 순수함수로
시안이 요구하는 순서는 **오늘 이후(임박순) → 배차 미정 → 지난 상차(최근 것부터)** 3그룹이다.
`ORDER BY loadingDate ASC NULLS LAST` 한 줄로는 지난 상차가 맨 위로 올라온다.
`compareLoading`으로 정렬키 `[그룹, 일수, 시각]`을 만들어 조회 후 JS에서 정렬한다(묶음 목록은 페이지네이션이 없다).

`findMany`는 그대로 `createdAt desc`로 두고 **`Array.sort`가 안정 정렬**인 점을 이용해 동순위를 업로드 최신순으로 잇는다.
→ 상차 정보가 전부 비어 있는 **기존 묶음은 지금과 같은 순서로 보인다**(계획서 §5 리스크 대응).

같은 날짜 안에서는 시각 순인데, 정렬용 대표 시각으로 오전=09:00 · 오후=14:00 · 미정=맨 뒤로 근사했다.
표시가 아니라 순서를 정하는 값이라 근사가 정당하다.

### 상차 완료는 플래그 없이 날짜로만
`loadingDate < 오늘(KST)`이면 완료로 본다. 필드를 늘리지 않는다(계획서 §5).
오늘 판정이 KST라 **서버에서 라벨을 만들어 내려보낸다** — `createdAt`과 같은 이유(hydration 불일치 회피).

### 완료된 줄에는 업체명을 붙이지 않는다
`describeLoading`이 `tone === 'done'`일 때 `vendorName`을 null로 돌려준다.
끝난 줄이 오히려 도드라지면 목록의 목적(다음에 나갈 것 찾기)이 흐려진다.

### 상차 셀은 미정뿐 아니라 채워진 것도 눌러 수정
시안은 「배차 미정」만 버튼이지만, 배차는 바뀌는 일이 잦아 채워진 셀도 같은 Popover로 열리게 했다.
겉모습은 시안대로 구분한다 — 미정은 점선 버튼, 오늘은 빨강 배지, 예정은 텍스트, 완료는 흐린 체크.

행 강조도 시안대로: 오늘 상차 행은 `bg-red-50/40`, 지난 상차 행은 `opacity-60`.

### 배송업체 목록은 미리 내려보낸다
`product-sales-section`에서 `listPurchaseUploads`와 **병렬로** 조회해 `UploadTable`에 넘긴다.
셀을 열 때마다 왕복하지 않는다.

### zod 스키마 재사용
`updateUploadLoading`의 입력은 등록 선택값의 부분집합이라 `UploadSelectionBase.pick(...)`으로 뽑았다.
`.refine()`이 붙은 스키마에는 `.pick()`이 없어 **base 객체와 refine을 분리**하고,
「직접 입력이면 시각 필수」 규칙을 술어·메시지 상수로 양쪽에 같이 건다.

## 4. 실왕복에서 드러난 기존 버그 — 적재 트랜잭션 타임아웃

브라우저에서 처음 올려보자 **「N건 등록」에서 실패**했다. 파싱·조회는 멀쩡했고(실파일로 확인),
실패는 적재 트랜잭션이었다.

**원인**: 적재가 건·라인마다 INSERT를 하나씩 순차로 돌린다. DB가 Neon 클라우드라 왕복 1회가 250~300ms이고,
Prisma 인터랙티브 트랜잭션 기본 타임아웃은 **5초**다.

진단은 실제 적재 경로를 트랜잭션 안에서 돌리고 **강제 롤백**하는 스크립트로 했다(DB에 남기지 않고 실측):

| 시트 | 건/라인 | 결과 |
|---|---|---|
| 이마트_260819 | 3건 / 9라인 | ✅ 3,917ms (아슬아슬) |
| 택배_260818 | 67건 / 79라인 | ❌ INSERT 22회 · **5,033ms 타임아웃** |
| 서울급식_260818 | 3건 / 24라인 | ❌ INSERT 20회 · **5,112ms 타임아웃** |

**S3·S4가 만든 버그가 아니다.** D1b 적재 로직 그대로이고, 배송 필드는 컬럼 4개 추가라 왕복 수를 늘리지 않는다.
이 경로는 「실왕복 검증」이 D1b → D1c로 계속 이월되다가 이번에 처음 실제로 돌아본 것이다.

**수정 — 왕복 수를 줄인다(근본)**
`createManyAndReturn` + `createMany`로 **묶음 1 + 건 전체 1 + 라인 전체 1 = 왕복 3회**.
타임아웃을 늘리는 건 대증요법이다(67건이면 20초, 더 큰 파일이면 또 터진다).

**타임아웃도 30초로(안전마진)**
시트를 여러 장 고르면 왕복이 시트 수만큼 늘어난다 — 5시트면 6초라 근본 수정만으로는 기본 5초를 여전히 넘겼다.
둘 다 필요했다.

**⚠️ 순서 전제**: 건과 라인을 잇는 근거가 `createManyAndReturn`의 **반환 순서 = 입력 순서**다.
PostgreSQL의 `INSERT ... RETURNING`이 VALUES 순서를 따르므로 성립하지만, 깨지면 라인이 엉뚱한 건에 붙는다.
개수 검증을 넣어 안 맞으면 트랜잭션을 되돌린다. 실업로드 뒤 **「라인이 하나도 없는 발주 건 0건」**으로 67건 시트에서도 실증했다.

**수정 후 실측**: 5시트 전부(76건/126라인) **6,077ms**에 완료.

## 6. 확인이 필요한 사항 (브라우저)

**S3 — 발주서 등록 모달**

1. 시트를 체크하면 아래에 배송 블록이 펼쳐지는가 (배송업체 · 상차일 · 시각 토글 · 비고)
2. 배송업체 드롭다운에 S2에서 등록한 업체가 관리화면 순서대로 뜨는가
3. 상차 시각 기본 선택이 **「시간 미정」**인가
4. 「직접 입력」을 고르면 시각 입력칸이 나오고, 비워두면 등록 버튼이 비활성 + 하단에 안내가 뜨는가
5. 상차일·업체를 다 비워도 등록되는가 (결정 #37)
6. 등록 후 목록에 배송업체·상차가 반영되는가

**추천 자동 채움** — 이력이 쌓여야 보인다. 같은 채널로 같은 업체를 **2건 이상** 등록한 뒤 새로 올리면
배송업체가 미리 채워지고 **파란 테두리**로 표시돼야 한다. 채널을 바꾸면 그 채널 추천으로 따라가고,
직접 고른 뒤에는 채널을 바꿔도 그대로여야 한다.

**S4 — 묶음 목록**

7. 「상차」 열이 보이고 기본 정렬이 임박순인가 (오늘 → 내일 → 미정 → 완료)
8. 「배차 미정」을 누르면 팝오버가 열리고, 채우면 그 자리에서 반영되는가
9. 오늘 상차 행이 붉게, 지난 상차 행이 흐리게 보이는가
10. 모바일 폭에서 상차 배지가 접힌 요약줄에 나오는가
