## 1. 변경 사항 요약

### 1.1 신규 [app/actions/purchase-order-upload.ts](../../app/actions/purchase-order-upload.ts) (365줄)

| 액션 | 내용 |
|---|---|
| `previewPurchaseOrder(formData)` | **신규.** 파싱만 하고 DB에 아무것도 쓰지 않는다. 인식 시트 + 미인식 시트를 `SheetPreview[]` 한 배열로 반환(`recognized`·`reason`으로 구분). 시트별 `suggestedChannel`·`suggestedOrderDate`·`orderCount`·`itemCount`·`warnings`·`alreadyUploaded` |
| `uploadPurchaseOrder(formData, selections)` | **개정.** `selections: [{ sheetName, channel, orderDate, note }]`만 받는다. 파일을 다시 받아 **서버에서 재파싱**하고, 선택된 시트만 사용자가 확정한 채널·발주일로 적재 |
| `updateUploadNote(uploadId, note)` | **신규.** 묶음 비고 사후 수정(500자, 빈 문자열은 null로 저장) |

- 파싱 결과를 클라이언트로 왕복시키지 않는다(#31 조작 방지). 클라이언트가 보내는 건 「어떤 시트를 어떤 채널·발주일로」뿐이고, 품목·수량은 서버 재파싱 결과만 쓴다.
- `selections`는 zod로 검증(채널 enum 5종·발주일 `yyyy-mm-dd`·비고 500자). 그 위에 `validateSelections()`가 **같은 시트 두 번 선택 / 파일에 없는 시트 / 발주 데이터가 없는 시트**를 사용자용 문구로 걸러낸다.
- 중복 감지는 D1a에서 만든 묶음 키(`bundleDuplicateKey`)로 preview·upload **양쪽에서** 확인한다. preview는 `alreadyUploaded` 플래그로 미리 알려주고, upload는 실제로 차단한다.

## 2. 주요 결정 사항

1. **반환 필드명은 `bundles`로 유지.** 계획서 §3.3은 `uploads`였지만 D1a에서 이미 `bundles`(묶음)로 만들었고, 도메인 용어와 일치해 그대로 뒀다. 계획서 표기를 코드에 맞춰 정정했다.
2. **미인식 시트도 미리보기에 싣는다.** 시트명 오타로 조용히 빠지는 걸 막기 위해(작성안내 5번) `recognized: false` + `reason`으로 함께 반환한다. 목록 순서는 「인식된 시트 → 미인식 시트」이고 원본 시트 순서는 복원하지 않는다(파서 DTO에 순서 정보가 없다).
3. **`suggestedChannel`이 null이어도 미리보기는 성공한다.** 채널을 못 뽑은 시트는 화면에서 사람이 고르면 된다(#31 — 시트명 규칙은 강제에서 힌트로 완화). 적재 시점에는 zod enum이 채널을 요구하므로 미선택 상태로는 들어갈 수 없다.
4. **묶음 중복은 여전히 강제진행 없음**(D1a 결정 유지). DB unique와 같은 키라 force가 성립하지 않는다.

## 4. 확인이 필요한 사항

1. 🔴 **실왕복 검증은 아직 못 했다.** 계획서의 D1b 검증 기준은 「실파일로 다채널 2시트 선택 → 묶음 2건」인데, 이 액션들을 부르는 화면이 없어 실행 경로가 없다(액션은 세션·권한을 요구해 스크립트로 대신 호출할 수 없다). **D1c 업로드 모달을 붙이는 즉시 이 검증을 한다.** 그때까지 D1b는 「타입·정적검사까지만 확인됨」으로 본다.
2. **`validateSelections`는 액션 파일 내부 함수라 단위테스트가 없다.** 순수 로직이라 테스트 가치는 있지만, 파일을 더 쪼개는 것보다 D1c 실왕복에서 케이스를 확인하는 편이 낫다고 판단했다.
3. 🔴 **미결 유지 — 재고 분할 차감.** D2 착수 전 결정 필요.
