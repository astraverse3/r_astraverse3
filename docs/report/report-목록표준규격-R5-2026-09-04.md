## 2. 🔴 시안 값이 아니라 「실제 코드 값」으로 썼다

어제 작업 중 **사용자 확인으로 시안에서 벗어난 결정이 3건** 있었다.
문서를 시안대로 썼다면 오늘 만든 기준서가 처음부터 코드와 어긋난다.

| | 시안·지시서 | **실제 코드(확정)** | 근거 |
| --- | --- | --- | --- |
| 펼친 묶음톤 | `bg-slate-50/75` | **`bg-slate-100`** | 흰 배경과 밝기차 2%라 묶음으로 안 보였다 → 5.5% |
| 묶음 호버 | `hover:bg-slate-100/85` | **`hover:bg-slate-200/70`** | 위와 같은 이유 |
| 헤더 색 | `text-slate-900` | **`text-foreground` 유지** | 같은 값(#0f172a)이지만 토큰 방향(§22) 보존 |
| 서브행 | (없음) | **반복 컬럼 비우기** | 사용자 제안. 색보다 묶음 인지에 효과적이라 원칙으로 승격 |

전부 대조해서 **실제 값**으로 기술하고, 왜 그렇게 정해졌는지를 문서 안에 각주로 남겼다.
같은 값을 다음에 또 `slate-50/75`로 되돌리지 않게 하는 것이 목적이다.

## 3. §4.2 개정 내용

- **도입부 신설** — 「값의 단일 정본은 `components/ui/table.tsx` 프리미티브」임을 명시. 화면에서 헤더·셀 클래스를 덧붙이지 않는다. 표준값 요약표(헤더 40px / 본문 44px / 14px / `px-3` / 로트 ≥24%) 추가
- **§4.2.2 시각 원칙** — 행 44px 고정, 묶음톤 `bg-slate-100` + `border-t border-slate-200/80` + 내부 `border-b-0`, 접힌 그룹 흰 배경 금지, 단일건 낱개, **서브행 반복 컬럼 비우기**
- **§4.2.3 컬럼 헤더** — `text-[10.5px] uppercase tracking-wider text-slate-400 font-bold px-4 py-2 bg-slate-50/60`
  → `h-10 px-3 text-sm font-medium text-foreground bg-slate-50 border-b border-slate-200`
  옛 값이 Typography의 **Micro Bold(영문 라벨용)** 토큰이었다는 경위를 각주로 남겼다
- **§4.2.4 / §4.2.5** — `text-[12.5px] px-4 py-2.5` → `text-sm px-3 h-11`, 로트 `text-[11px]` → `text-[12.5px]`. 그룹 헤더에 접힘/펼침 배경 분기 추가
- **§4.2.6** — `ring-1 ring-inset ring-slate-200/70` → `border-t border-slate-200/80`. 마지막 서브행만 아래 경계
- **§4.2.6 NOTE** — 생산자관리에 `#00a2e8`이 잔존했다가 R3에서 제거된 경위 + **의미색 29건은 손대지 않았다**는 한정
- **§4.2.7 모바일** — 표준규격 **범위 밖**임을 명시하고 「카드 폰트를 키우지 않는다」를 못 박음
- **부록 체크리스트** — `#00a2e8` → `bg-primary` 치환 지시를 **「그룹 표현에서만 slate로 제거, 의미색은 그대로」**로 개정
- **§1.1 Foundations** — 「발견 시 모두 `--brand`로 교체」와 위 결정이 충돌해 각주 1줄 추가

동작 변경 없음(주석만).

## 5. 🔴 §30(제품재고)의 「판단 필요」에 지시서가 이미 답을 주고 있었다

§4.2는 `<table>` 문서가 아니라 **CSS Grid 문서** — 즉 **제품재고 화면(`PKG_GRID`)의 근거 문서**다.
그런데 지시서 R5의 「함께 개정할 것」이 그 §4.2의 **타이포 값을 콕 집어 지정**했다:

```
text-[12.5px] → text-sm · px-4 py-2.5 → px-3 h-11 · 로트 text-[11px] → text-[12.5px]
ring-1 ring-inset → border-t border-slate-200/80
```

어제 §30에 「'grid 마크업 유지'가 구조를 뜻하는지 타이포까지인지 불분명」이라고 적었는데,
**지시서 자신의 문면으로는 「구조는 유지, 타이포·밀도는 표준으로」가 맞다.**
문서 쪽 불분명은 해소됐고, **남은 것은 코드에 언제 적용할지의 결정**이다.

작업하며 대상도 정확히 특정됐다 — 개정 전 §4.2의 값이 **그대로 두 줄에 남아 있다**:

| 위치 | 현행 | = 개정 전 |
| --- | --- | --- |
| `package-row.tsx:95` | `text-[10.5px] uppercase tracking-wider text-slate-400 font-bold px-4 py-2.5 bg-slate-50/60` | §4.2.3 |
| `package-row.tsx:332` | `bg-slate-50/60 ring-1 ring-inset ring-slate-200/70` | §4.2.6 |

백로그 §30에 위 내용을 갱신했다.

## 7. 확인이 필요한 사항

1. **§30 코드 적용 여부** — 5절대로 「타이포·밀도는 표준으로」가 지시서의 문면이다.
   그대로 진행할지, 디자이너에게 한 번 더 확인받을지 판단 필요. 착수 시 `/plan` 선행(범위가 작지 않다)
2. **잡곡 사본은 저장소에 없었다** — 지시서(와 어제 계획서)가 「`handoff.md`가 2벌」이라고 했지만,
   `docs/handoff/잡곡재고관리/`는 **`.gitignore:61`로 통째로 제외**돼 있다. 저장소는 이미 정본 1벌이다.
   로컬 사본에 넣은 「사본」 안내 1줄은 **커밋되지 않는다** — 내 로컬에서만 보인다.
   지시서의 「1벌만 개정한다」는 결론 자체는 그대로 지켜졌다. 로컬 사본을 지울지는 판단 필요
3. **§4.2.7 모바일 값** — 개정 범위 밖이라 원안 그대로다. 모바일 카드 통일 때 함께 봐야 한다
