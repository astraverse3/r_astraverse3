## 2. 주요 결정 사항

### 권한을 `requireAdmin`으로 (계획서 §4-S2 그대로)
`product-type.ts`는 `requirePermission('OPERATION_MANAGE')`를 쓰지만, 배송업체는 `/admin/settings` 안에 있고
이 경로는 [middleware.ts:14](../../middleware.ts#L14)에서 이미 **ADMIN 전용**(`permission: null`)이다.
경로 자체가 막혀 있으므로 화면에서 role을 다시 가리지 않는다 — 기존 수율 섹션(`settings-client.tsx`)과 같은 방침.

### 순서는 숫자 입력이 아니라 ↑↓ swap
시드가 10단위(`sortOrder: 10, 20, …`)라 인접 항목과 값을 맞바꾸면 그만이다. 사용자가 숫자를 신경 쓸 일이 없다.

**동순위 처리에서 한 번 고쳤다.** 처음엔 `findFirst`에 `sortOrder: { lte }` / `{ gte }`로 이웃을 찾았는데,
그 쿼리의 tie-break(`id`)가 목록 정렬의 tie-break(`name`)와 달라 `sortOrder`가 같은 업체가 생기면
화면에서 보이는 이웃과 실제로 맞바꾸는 대상이 어긋날 수 있었다. → **목록과 같은 정렬로 형제 전체를 뽑아
`findIndex`로 인접 항목을 고르는 방식**으로 교체(7행짜리 테이블이라 비용 무시 가능).
`sortOrder`가 같을 때는 맞바꿔도 순서가 안 변하므로 이동 방향으로 1칸 벌린다.

### 순서 조정은 사용중 목록에서만
미사용 업체는 등록 화면 드롭다운에 안 뜨므로 순서를 매길 이유가 없다. ↑↓ 버튼 자체를 렌더하지 않는다.

### 이름 수정은 인라인
행을 클릭하면 그 자리가 입력칸이 된다(Enter 저장 / Esc 취소 / blur 저장). 다이얼로그를 새로 만들지 않았다.
값이 그대로면 액션을 호출하지 않고 편집만 닫는다.

### 미사용 업체는 숨기지 않고 아래로
`목록에서만 숨긴다`(결정 #39)는 **등록 화면 드롭다운** 이야기다. 관리화면에서까지 사라지면 되돌릴 방법이 없어서,
구분선 아래에 흐리게 두고 「다시 사용」 버튼을 남겼다.

## 3. 레이아웃 A안 적용 (Claude Design 핸드오프)

구현 직후 사용자가 **관리자 설정 A안(2단 컬럼) 가이드**를 전달해 이어서 적용했다.
(시안 `관리자설정-컴팩트-시안.html`은 `docs/handoff/`에 저장돼 있지 않다 — 가이드 문서만으로 구현했다.)

- **2단 컬럼 흐름** — 컨테이너를 `space-y-4` → `columns-1 xl:columns-2 gap-4`. 카드 높이가 달라도
  짧은 카드 밑에 다음 카드가 바로 붙어 빈 구멍이 없다. 모바일은 `columns-1`로 그대로 1열.
  `columns-*`와 `space-y-*`는 같이 못 쓴다(컬럼 경계에서 마진이 어긋난다) → 세로 간격은 카드의 `mb-4`가 담당.
- **긴 카드를 앞에** — 배송업체 → 수율 순. 컬럼 균형이 자동으로 맞는다.
- **`SettingSection` 분리** — `page.tsx` 안의 로컬 함수를 파일로 빼고 헤더 우측 `action` 슬롯을 추가.
  훅이 없어 서버·클라이언트 양쪽에서 import된다(수율 카드는 저장 버튼 때문에 클라이언트에서 렌더).
- **저장 버튼을 카드 하단 → 헤더 우측**, 「저장되었습니다」 → 「저장됨」. 하단 공백이 사라진다.
  전역 「모두 저장」은 만들지 않았다 — 수율만 섹션 저장이고 배송업체는 즉시 반영이라 액션 구조가 다르다.
- **행 높이 축소** — 수율 입력 `py-2` → `h-[30px]`, 배송업체 행 `py-2` → `h-8`.
  배송업체 행에 **순번(1·2·3…)** 표시가 붙고, 테두리 대신 hover 배경으로 바뀌었다.
  토글 버튼 문구도 「미사용으로」 → 「미사용」.

`break-inside-avoid`는 Tailwind v4 기본 유틸이라 그대로 쓴다(프로젝트 `tailwindcss ^4` 확인).
**서버 액션과 섹션의 로직(`run`·`handleAdd`·`startEdit`·`commitEdit`)은 손대지 않았다** — 스타일만 교체.

## 4. 순서 이동을 낙관적 처리로 (사용자 지적)

사용자가 **「↑↓ 누를 때마다 쿼리를 하는 것 같다」**고 짚었다. 맞다 — `sortOrder`를 DB에 즉시 확정하고
`router.refresh()`로 페이지를 다시 읽는 구조라, 클릭 한 번에 쿼리가 6번 돌았다.

| | 이전 | 이후 |
|---|---|---|
| 대상 조회 `findUnique` | 1 | — (목록 조회에 흡수) |
| 형제 목록 `findMany` | 1 | 1 |
| `$transaction` update | 2 | 2 |
| `router.refresh()` → 페이지 재실행 (수율 + 배송업체) | 2 | 0 |
| **합계** | **6** | **3** |

**클라이언트** — 목록을 로컬 상태(`rows`)로 들고, ↑↓를 누르면 배열에서 두 항목을 맞바꿔 **즉시** 반영한다.
저장은 뒤에서 돌고 화면은 기다리지 않는다.

- **연타 직렬화** — `saveQueue` ref에 프로미스를 이어 붙여 서버에는 누른 순서대로 하나씩 간다.
  병렬로 나가면 `sortOrder` 맞바꾸기가 서로를 덮어쓴다.
- **실패 시 `router.refresh()`로 되돌린다.** 여러 칸 옮긴 뒤라면 부분 롤백은 꼬이므로 서버 상태를 다시 읽는다.
- **props 재동기화** — 추가·이름수정·토글은 여전히 `router.refresh()`를 타므로 새 `vendors`가 내려온다.
  `useEffect` 대신 **렌더 중 동기화**(`vendors !== syncedFrom`이면 `setRows`)로 처리 — 옛 목록이 한 프레임 비치지 않는다.
- **이동 버튼에서 `isPending` 제거** — 저장을 기다리지 않으니 막을 이유가 없다. 끝단에서만 비활성.

**서버** — `findUnique`를 없애고 목록 조회 1회로 대상과 이웃을 함께 찾는다(7행짜리 테이블).
`revalidatePath`는 남겼다 — 화면은 이미 바뀌었지만, 다른 경로로 들어올 때 옛 순서가 보이면 안 된다.

> 이름 수정·사용 토글은 그대로 즉시 반영 + refresh다. 「순서 저장」 버튼을 따로 두는 안(B안)은
> 같은 카드 안에서 저장 방식이 둘로 갈리고 저장 안 누르고 나가면 유실돼서 택하지 않았다.

## 6. 확인이 필요한 사항 (브라우저)

`/admin/settings` 하단 배송업체 섹션에서:

1. 시드 7종이 순서대로 보이는가 (경동 → 대신 → 전국 → 해남원형 → 롯데택배 → 직접배송 → 방문수령)
2. ↑↓로 순서가 **즉시** 바뀌는가(깜빡임·지연 없이). 새로고침해도 유지되는가. 맨 위/맨 아래에서 버튼이 비활성인가
2-1. **연타**로 여러 칸 옮긴 뒤 새로고침했을 때 화면 순서와 일치하는가
3. 업체명 클릭 → 인라인 수정 → Enter 저장 / Esc 취소
4. 중복 이름 등록·수정 시 「이미 등록된 업체입니다.」 토스트
5. 「미사용으로」 → 구분선 아래로 내려가고, 「다시 사용」으로 복귀
6. 새 업체 추가가 맨 뒤에 붙는가
7. 모바일 폭에서 행이 깨지지 않는가

레이아웃(A안):

8. `xl` 이상에서 **2단**, 그 아래에서 **1단**으로 접히는가
9. 카드가 컬럼 경계에서 잘리지 않는가(`break-inside-avoid`)
10. 수율 카드 저장 버튼이 헤더 우측에 있고, 저장 후 「저장됨」이 뜨는가
