## 4. 🔴 실측으로 걸러낸 결함 3건

**이 작업의 진짜 내용은 이것이다.** 셋 다 코드만 봐서는 안 나왔고, 실제 기록을 보고서야 드러났다.

### ① 의심 배지 오탐 — 경로만 보고 판정했다
사용자가 '도정관리'를 **직접 눌러** `/raw-stocks → /milling`으로 가도 같은 경로라 빨간 배지가 붙었다. 그러면 정상 이동이 전부 빨개져 진짜 튐이 파묻힌다.
→ 판정을 **원인** 기준으로 바꿨다: `원인 불명`·`뒤로가기`만 의심, `클릭`·`코드 이동`은 정상.

### ② 뒤로가기가 화면 갱신보다 **늦게** 찍혔다
```
20:53:03.239 route    /milling → /raw-stocks
20:53:03.350 popstate 현재 /raw-stocks      ← 원인인데 결과보다 111ms 늦다
```
Next가 `popstate`를 먼저 처리해 화면 갱신이 앞섰다. 「경로 변경 줄 위에 원인이 있다」는 전제가 깨진다.
→ `popstate`를 **capture로 등록**해 먼저 잡고, 그래도 늦으면 **변경 직후 1초까지 같은 묶음**(`after`)에 넣는다.

### ③ 🔴 「직전 행동 없음」이 거짓말이었다 — 모듈 전역 변수가 초기화된다
```
20:59:57.711 pointer <a> 도정관리        ← 직전에 분명히 있는데
21:00:00.596 route / → /milling · 직전 행동 없음
```
직전 신호를 **모듈 전역 변수**에 들고 있었는데, Next가 페이지를 옮기며 그 모듈을 다시 평가하면 변수가 초기화된다.
→ **이미 저장된 기록에서** 직전 신호를 찾도록 바꿨다. 저장소는 초기화되지 않는다.
📌 **교훈: 라우팅을 가로지르는 상태를 모듈 전역 변수에 두면 안 된다.**

### 그 밖에 판정 규칙 하나 더 교정
`popstate`를 무조건 우선하면 **3초 전 뒤로가기가 그 뒤의 클릭을 이겨버린다**. → **가장 가까운 신호 하나**가 원인. 예외는 `after`의 `popstate`(늦게 도착한 진짜 원인)뿐.

## 5. 설계 결정

- 🔴 **입력값은 기록하지 않는다.** `input`/`textarea`/`select`/`contenteditable`은 값 대신 종류만 남긴다. 테스트 3개로 고정(생산자명을 넣고 로그에 안 나오는지 확인).
- 🔴 **이벤트를 삼키지 않는다.** 전부 `passive`+capture, 읽기만. 덫이 증상을 가리면 잡을 게 없어진다.
- 🔴 **조용히 실패한다.** localStorage 접근은 전부 try/catch.
- **시간 창으로 자르지 않는다.** dev에서 클릭→이동이 24초 걸리기도 했다(컴파일). 직전 행동과 경과 시간을 그대로 적고 판단은 사람이 한다.
- **경로 변경은 별도 슬롯에 20건 따로 보관** — 일반 버퍼(200건)에서 밀려나도 남는다. 그래서 **경로 변경 줄 자체에 원인을 박았다**.
- `reloadOnOnline`(기본 켜짐) 때문에 앱이 통째로 새로고침될 수 있어 **localStorage가 필수**다.

1. 🔴 **배포해야 작동한다** — dev는 PWA가 꺼져 있고, 증상 자체가 실기기 PWA에서만 나온다.
2. **다음에 튀면 `/admin/trace`에서 「텍스트로 복사」** 후 보내주면 원인이 확정된다.
3. 🔴 **용의자 A가 맞다면 데이터가 이미 바뀌었을 수 있다** — 그 버튼은 확인창 없이 도정 배치의 투입 톤백을 덮어쓴다. 감사로그의 `updateMillingBatchStocks` 기록으로 오발 여부를 확인할 수 있다(미실시).
4. **제거 조건** — 원인 확정 즉시 걷어낸다(계획서 §7). 설치 커밋 1개로 묶어 `git revert` 한 번에 걷히게 했다.

## 8. 함께 발견된 별건 (범위 밖 · 판단 필요)

조사 중 드러난 **실제 결함**. 이번 증상과는 무관하나 실사용 영향이 있다.

- 🔴 **`reloadOnOnline` 기본 켜짐** — `online` 이벤트마다 앱 전체 새로고침. 지하에서 나오거나 WiFi↔LTE 전환 시 발동하고 **입력 중이면 날아간다**. 현장 폰 사용 앱에 위험.
- **`others` NetworkFirst가 모든 페이지 요청을 가로챔** — 10초 내 응답 없으면 최대 24시간 된 캐시를 내준다. 슬롯 32개 LRU.
- **`next-pwa` 5.6은 2022년 이후 배포 중단** — Next 16 + App Router 지원 범위 밖. 후속은 Serwist.
- 남은 308 리다이렉트 4개(`/stocks`·`/releases`) — 위생 차원 정리 대상.
- **포장내역 다이얼로그가 Server Action을 3번 순차 왕복** — Next는 Server Action을 병렬로 안 보낸다. DB가 느린 순간 지연이 3배로 곱해진다. 하나로 합치면 왕복 1회.
