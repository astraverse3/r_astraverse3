## 3. 변경 사항

### 3.1 스키마 ([prisma/schema.prisma](../../prisma/schema.prisma))
- **신규 모델 4개** (§11 발주서 도메인 섹션):
  - `PurchaseOrderUpload` — 업로드 묶음 헤더(중복감지 #16·묶음목록·감사 앵커)
  - `PurchaseOrder` — 주문 1건 = 발주처+수령인 = 엑셀 한 행(결정 #11)
  - `PurchaseOrderItem` — 품목 라인 = 엑셀 셀. `productTypeId` 1:1 매칭(구 4키 조립 폐기), 매칭실패 대비 `rawItemName`/`packageType`/`rawPackaging` 스냅샷 보존
  - `PackageMovement` — 제품재고 차감 통합 모델(결정 #19, 세 경로 단일 테이블). 금액 필드 없음(결정 #25)
- **enum 3개**: `PurchaseChannel`(DELIVERY/EMART) · `OrderStatus`(PENDING/PARTIAL/COMPLETED) · `MovementType`(SALE/GIFT/LOST/DAMAGED/OTHER)
- **역참조 2개**: `ProductType.orderItems`(주석 예고분 이행) · `MillingOutputPackage.movements`

### 3.2 마이그레이션
- [20260622000000_add_purchase_order_domain/migration.sql](../../prisma/migrations/20260622000000_add_purchase_order_domain/migration.sql)
- `prisma migrate diff --from-schema-datasource --to-schema-datamodel --script`로 생성(실 DB 현재상태 introspect 기준). shadow DB 불필요·읽기 전용.
- 내용: `CREATE TYPE` 3 + `CREATE TABLE` 4 + `CREATE INDEX` 7 + `ADD FOREIGN KEY` 5. **기존 테이블/컬럼/데이터 변경 0건.**

### 3.3 설계 문서 갱신

## 5. 주요 결정 사항
- **마이그레이션 생성 방식**: 기존 프로젝트가 수동 SQL 파일 + `migrate deploy` 패턴이라(shadow DB URL 없음), `migrate diff`(from-datasource)로 SQL 추출해 동일 패턴 유지.
- **실 DB 즉시 적용**: 로컬 `.env`가 Neon 클라우드를 직접 가리켜 로컬 검증(단계2~)에도 테이블 필요 → 사용자 승인 후 즉시 적용.
