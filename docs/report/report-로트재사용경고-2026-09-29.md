## 2. 주요 결정 사항

1. **A안 — 입고일을 첫 로트 날짜로 맞춘다**(1차안 B 「로트 기준일 칸 신설」을 사용자 지적으로 교체).
   칸 이름이 이미 「입고일자 (Lot 기준)」이고 입력 시각은 `createdAt`에 남는다. 벼 `incomingDate`는 통계·검색 조건에 안 쓰인다 → **DB 변경 없음, 로트 계산 7곳 무변경.**
2. **안내 방식 = 자동으로 채우고 문구로 알린다**(사용자). 톤백을 한 개씩 저장하는 화면이라 저장 때 경고창은 톤백마다 뜬다 — 그래서 창 대신 칸을 채워 둔다.
3. **「같은 로트」 판정은 로트 뒷자리(품목코드-인증번호-개인번호)** — 작목반이 바뀌었거나 옛 품목코드로 저장된 로트는 후보에서 빠진다. 오늘 정정한 13건이 바로 그 예라, 정정 전이었다면 다온누리큰눈은 첫 로트로 안 잡혔다.
4. **첫 로트보다 이른 날짜(소급)는 새 로트** — 기존 원물을 옮기는 건 범위 밖.
5. **잡곡은 담당자 협의 후**(사용자).

## 3. 확인이 필요한 사항

### 🖐 브라우저

1. 로트가 이미 있는 농가·품종으로 **벼 입고 등록** → 입고일자가 첫 로트 날짜로 바뀌고 「첫 로트와 같은 로트로 들어가요 — 첫 입고 ○/○ · 이미 N건」
2. 입고일자를 다른 날로 바꾸면 노란 안내 + **[○/○로 맞추기]** → 누르면 돌아온다
3. 저장 후 목록의 로트번호가 첫 로트와 같다
4. **관행(일반)** 농가·처음 들어오는 조합은 안내 없음 · 창을 닫았다 열면 품종·입고일 초기화
5. 엑셀 가져오기 미리보기에 「첫 로트 날짜로 입고일자를 맞춤: N건」(해당 행이 있을 때만)

### 알고 가는 것

- 등록 화면의 품종·입고일 칸을 **제어 컴포넌트로 바꿨다**(자동으로 채우려면 필요). 창을 닫을 때 `resetForm`에서 둘 다 초기화한다 — 예전엔 창이 닫히며 저절로 초기화됐다
- 맞춘 행의 **실제 도착일은 `createdAt`(입력 시각)으로만** 남는다. 엑셀 가져오기·늦은 입력은 둘이 다르다
- 정정한 로트는 **이미 나간 실물 라벨과 다를 수 있다**(5/20 윤영식 건과 같은 성격 — 사용자: 실제 문제 없음)
- 재발: 품종 곡종·코드 규칙이 바뀌어도 저장된 로트는 다시 계산하지 않는 구조는 그대로다. 곡종 변경 때 「로트 품목코드 변경 경고」(`2ca3ed6`)는 뜬다
