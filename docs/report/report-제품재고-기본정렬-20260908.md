# 결과보고서 — 제품재고 기본 정렬을 「오래된순」으로

- 날짜: 2026-09-08
- 요청: **오래된 재고부터 처리해야 하니 목록도 오래된 것부터** 나오게 한다
- 계획서: `docs/plan/plan-제품재고-기본정렬-오래된순.md`

## 1. 한 일

기본 정렬 `weight_desc`(재고량 많은순) → **`oldest`(오래된순)**. 벼·잡곡 두 탭 모두.
정렬 드롭다운 선택지 순서도 **기본값이 맨 위**로 오게 바꿨다(오래된순 / 최신순 / 재고량 많은순).

**정렬 로직 자체는 무변경.** 이미 제대로 구현돼 있었다 —
그룹의 대표일을 `oldest`일 때 **min**으로 잡아 「가장 오래된 줄이 그룹 위치를 정한다」(`repDate`).
기준 날짜는 **매입 = 입고일 / 도정산 = 포장 등록일**이며(`packages.ts:179`),
DB `orderBy`는 1차 정렬일 뿐 최종 순서는 이 화면 날짜로 다시 잡힌다.

## 2. 🔴 기본값이 4파일 8곳에 흩어져 있었다

`'weight_desc'` 리터럴이 서버 액션·페이지·검색 다이얼로그·활성 필터 배지에 각각 박혀 있었다.
하나라도 어긋나면 **「기본값인데 URL에 `sort=`가 붙는다」·「기본값인데 배지가 뜬다」**로
**조용히** 틀어진다 — 화면은 정상으로 보이므로 발견이 늦다.

→ **`lib/package-sort.ts` 신설**(`package-where.ts`·`production-year.ts`와 같은 단일 원천 패턴)

| export | 용도 |
|---|---|
| `DEFAULT_PACKAGE_SORT` | 기본값 = `'oldest'` |
| `PACKAGE_SORT_OPTIONS` | 선택지 + 라벨 (기본값이 맨 위) |
| `PACKAGE_SORT_VALUES` | URL 파싱 검증용 |
| `isDefaultPackageSort()` | URL·배지에 실을지 판정 |

## 3. 변경 파일

| 파일 | 내용 |
|---|---|
| `lib/package-sort.ts` | **신규** — 위 4개 |
| `app/actions/packages.ts` | 서버 기본값 |
| `packages/page.tsx` | `parseSort` fallback · `SORT_VALUES` 제거 |
| `packages/package-search-dialog.tsx` | 5곳 · `SORT_OPTIONS` 제거 |
| `packages/active-package-filters.tsx` | 배지 판정 → `isDefaultPackageSort()` |

남은 `'weight_desc'` 리터럴은 전부 정당하다 — **타입 정의**(`packages.ts:103`)와
**「무게순으로 정렬하라」는 동작 분기**(`:142`·`:271`), 그리고 원물재고(`stock.ts`·`misc-stock.ts`)는 별개 기능.

## 4. 부수 효과 — 배지가 반대로 뜬다

전에는 「오래된순」을 고르면 배지가 떴다. 이제는 **「재고량 많은순」을 골라야** 배지가 뜬다.
기본값이 바뀌었으니 의도된 동작이다. 기존 `?sort=oldest` 링크는 그대로 열린다.
