## 3. 주요 결정 사항

### 3.1 사전조사 vs 계획서 표기 충돌 → 계획서 우선
- 매입 필드: 사전조사 `purchaseFrom`/`purchaseDate` ↔ 계획서 `purchaseVendor`/`incomingDate` → **계획서 채택**
- CHECK `pkg_milled_has_source` 조건: 사전조사 `batchId AND stockId` ↔ 계획서 `batchId OR stockId` → **계획서 채택** (기존 데이터 호환성 확보)
- 계획서 §11 "충돌 시 계획서·CLAUDE.md > 번들·리서치" 원칙 적용

### 3.2 `ON DELETE SET NULL`로 자동 변경된 batchId FK
- `batchId`가 NOT NULL → NULL 허용으로 바뀌면서 Prisma가 FK 삭제 정책을 SET NULL로 자동 설정
- 의도와 일치 (배치 삭제는 거의 발생하지 않고, 발생 시 outputPackage가 고아로 남는 것보다 batchId만 null화가 안전)
- 단, 이 경우 `pkg_milled_has_source` 제약상 `stockId`가 살아있어야 함 — 기존 데이터는 모두 stockId 있는지 추가 확인 필요할 수 있음 (이번 단계에서는 미확인, 후속 검증 가능)

### 3.3 `output-statistics.ts`는 의도적으로 매입품 자동 제외 유지
- 현재 `where: { batch: { ... } }` 형식이 batch=null인 매입품을 자동 제외 → **그대로 둠**
- 판매관리 단계에서 OR 분기로 매입품 포함 재설계 예정 (참고: [research-판매관리-참고사항.md §2.1](../research/research-판매관리-참고사항.md))

### 3.4 호출부 수정 범위 — 일단 하드코딩
- 모든 RICE 필터를 `params`로 override 가능하게 만들지는 다음 단계(#4 라우팅 분리)에서 결정
- 현 시점에서는 "벼 전용 액션은 RICE만 본다" 원칙으로 단순화
