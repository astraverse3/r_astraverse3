## 2. 주요 결정 사항

1. **서버 액션까지 지웠다** — 화면 버튼만 없애면 `restoreBackup`이 export된 엔드포인트로 남는다(§56과 같은 교훈).
2. **백업 만들기는 화면에 남겼다** — 되돌릴 수 없는 동작이 아니다.
3. **복원 직전 자동 백업** — `--apply`여도 지금 DB를 `backup_…_before-restore.sql`로 먼저 떠 둔다. 끝나면 되돌리는 명령을 출력한다.
4. 🔴 **스크립트는 `.env.local`을 직접 읽는다** — 처음엔 `Invalid URL`로 멈췄다. 값을 찍지 않고 형식만 검사해 보니 `@prisma/client`가 import 순간 `.env`를 `process.env`에 넣는데, **`.env`의 `DIRECT_URL`이 불완전한 값**(62자, 스킴 없음)이었다. 실제 값은 `.env.local`에 있다(Next가 먼저 읽는 파일). psql·Prisma 둘 다 고른 주소 하나로 붙인다.
5. 복원 접속은 `DIRECT_URL`(직결) 우선 — 덤프의 세션 `SET`이 pooler(PgBouncer)에서는 이어지지 않는다. 화면의 백업 생성은 기존대로 `DATABASE_URL`.
