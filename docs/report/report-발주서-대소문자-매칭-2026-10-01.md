# 결과보고서 — 발주서 매칭 대소문자 무시 (규격·품종명)

날짜: 2026-10-01

## 발단

사용자: 「발주서 하나 등록했는데 "유기농 IPS"가 매칭 실패했어. 원인 확인 좀」
→ 원인 보고 후 「제안대로 해줘」, 이어서 「품종명도 같은 방법으로 하면 되나? 영문 품종명이 있어서」 → 「진행해줘」.

## 원인 (실서버 DB 읽기 전용 실측)

- 실패한 줄: `PurchaseOrderItem` #332 — 이강바이오 / `유기농 IPS` / 규격 **`10KG`** / 포장지 빈칸 / 30개
  (업로드 #23 `발주서-통일양식-템플릿.xlsx` · 시트 `이강바이오_261006`)
- 품종 해석은 정상(`유기농` 접두 제거 → `IPS` id 7 정확일치)
- IPS SKU `백미 · 10kg · 땅끝에서보냅니다`(#87, 기본)가 있다 — **규격 표기 대소문자만** 달랐다
- 파서 `normalizeSpec`은 공백·콤마만 지우고 대소문자는 그대로 저장, 매처는 대소문자 구분 비교 → `sku_unresolved`
- 🔴 kg 환산 `specWeightKg`는 `/i`라 대문자도 읽는다 → 「단위 없음」 경고도 안 떠 **조용한 실패**였다

## 변경 사항

| 파일 | 내용 |
|---|---|
| `lib/purchase-order-parser.ts` | `normalizeSpec`이 단위를 소문자로 맞춤(`10KG`→`10kg`, `907G`→`907g`) — 앞으로 저장값을 깨끗하게 |
| `lib/purchase-order-matcher.ts` | `matchKey`(공백·대소문자 무시) 신설·export. 규격 비교와 품종명·별칭 해석에 사용 — 이미 `10KG`로 저장된 줄도 재매칭으로 붙는다 |
| `lib/variety-alias.ts` | 별칭·품종명 검증을 `stripSpaces` → `matchKey`로 — 매처와 같은 규칙 유지 |
| 테스트 3파일 | parser 2줄 · matcher 2개 · variety-alias 1개 (**옛 코드에서 실패하는 것 먼저 확인**) |

## 주요 결정

- **파서·매처 둘 다 고쳤다.** 파서만 고치면 이미 저장된 `10KG` 줄은 재매칭해도 실패한다.
- **품종명도 대소문자 무시.** 실측: 영문 든 품종 7개(`IPS`·`IPSA`·`CJ1`·`CJ3`·`CJ4`·`CJ5`·`CJ6`), 대소문자만 다른 이름·별칭 충돌 **0건**. 정확일치라 `IPS`↔`IPSA`는 안 섞인다.
- **별칭 검증도 같이 바꿨다.** 매처만 바꾸면 다른 품종에 별칭 `ips`를 받아 주는데, 매칭 땐 이름 `IPS`가 먼저 가져가 죽은 별칭이 된다(`efdbeb7` 때와 같은 꼴).
- **포장지명 비교는 그대로**(`stripSpaces`) — 한글뿐이라 대소문자 의미 없음.
