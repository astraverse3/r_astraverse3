## 2. 주요 결정 사항

### 🔴 결정 1 — 표시값을 식별자로 겸용하지 않는다

**상황**: 실기기 ④ 확인 중 콘솔에 `Encountered two children with the same key, 관행`.

**판단**: 콘솔 에러는 **증상**이고 진짜 결함은 따로 있었다. `LotGroup.lotNo`가
표시값(관행이면 전부 `'관행'`)과 식별자를 겸하고 있어서, `customWeights[group.lotNo]`·
`customInputs[group.lotNo]`가 같은 키를 봤다 → **관행 농가가 둘이면 한쪽에서 「기타」(직접 입력)를
열었을 때 다른 쪽 칸도 같이 열리고 값까지 공유됐다.**

**처방**: 표시와 식별을 분리(`groupKey` 신설). 그룹핑 자체는 처음부터 고유키로 제대로 나뉘고
있었으므로 **담을 때 덮어쓴 것만** 되돌린 셈이다. 데이터는 안 섞였다 —
`getGroupOutputs`는 `stockIds` 기반이라 무사했다.

> **원칙**: 화면에 뿌리는 값은 사람이 읽기 좋게 뭉개지므로(관행 → 전부 `관행`) 유일성이 깨진다.
> 식별자로 겸용하지 말 것.

### 🔴 결정 2 — §38은 처방 B(조건부 삭제). 근거는 추측이 아니라 이력이다

**상황**: 백로그 §38이 「지우기 전에 git blame으로 이유를 확인할 것」을 지시.

**확인 결과** (`git log -L 68,68:<파일>`):

1. `7522644`(모바일 UI 개선)가 `md:`를 붙이면서 조건부를 같이 넣었는데
   **`\${...}`로 이스케이프**돼 문자열이 그대로 박혔다 → **처음부터 죽은 코드.**
2. 살아난 건 `1e9a6f6`(**fix: 모바일 P0 버그 일괄 처리 (escape**, pb, 이모지)) —
   「className에 `${}`가 찍히는 것」을 걷어내는 일괄 수정에 **딸려 살아났다.**

**판단**: 그 커밋은 이 조건의 타당성을 본 적이 없다. **작성자는 흰 배경이 적용된 화면을
한 번도 보지 못했다** — 「좋다고 확인한 적 없는 코드」다. 잡곡에 같은 조건부가 없다는 사실과 합쳐
설계가 아니라 사고로 확정. **B(삭제) 채택.**

> **원칙**: 「왜 이렇게 돼 있지?」에 답이 안 나오면 **그 줄이 언제부터 실제로 동작했는지**를 본다.
> 일괄 수정에 딸려 살아난 코드에는 의도가 없다. `git log -L <행>,<행>:<파일>`이 한 번에 보여준다.

### 결정 3 — 죽은 조건부(121행)도 함께 정리 (사용자 승인)

동작 변화는 0이다(양쪽 다 투명 + 필터 없으면 자식이 `null`). 그럼에도 지운 이유는
**읽는 사람에게 「필터에 따라 배경이 갈린다」고 거짓말을 하기 때문** — 이번 조사에서 실제로 한 번 속았다.
수술적 변경 원칙과 부딪히는 지점이라 **사용자에게 물어 승인받고** 진행했다.

## 3. 스스로 정정한 것

- **조사 중 설명 오류**: 「평소엔 카드가 맞닿아 있어서 흰 배경이 안 보였다」고 말했으나 틀렸다.
  실제 이유는 122행의 `MOBILE VIEW (Search First Strategy)` — `filters.length === 0 ? null : ...`이라
  **모바일은 필터가 없으면 목록을 아예 안 그린다.** 따라서 §38은 간헐적 결함이 아니라
  **모바일에 카드가 보이는 모든 경우의 상시 결함**이었다. 백로그 §38 본문에 정정해 두었다.
