## 2. 주요 결정

1. **시트냐 팝오버냐는 진입점이 정한다** — 셀 탭 = 팝오버, 카드 탭 = 시트. 화면 폭을 JS로 재지 않는다.
   부수효과로 **데스크탑 건상세 패널의 카드도 눌린다** — 시트는 `sm:`에서 패널 폭(468px)으로 오른쪽 아래에 붙는다.
2. **카드는 라인 하나를 연다**(`[itemId]`). 셀은 같은 규격 라인을 합치므로(`buildRow`) 셀 전체를 열면
   카드 숫자와 시트 숫자가 달라진다. 서버 액션은 원래 `itemIds[]`라 변경 없음.
3. **닫기 지연(`setTimeout 0`) + key 비교** — 게이트 `onJump`와 같은 한 쌍.
   🔴 지연만 넣으면 **새 결함이 생긴다**: 팝오버가 열린 채 옆 셀을 탭하면(터치 태블릿) 바깥 판정(닫기)과
   그 셀의 onClick(열기)이 같은 click에서 나고, 미룬 닫기가 **방금 연 새 팝오버**를 닫는다.
   그래서 「닫으려던 그 셀일 때만 닫는다」.
4. **시안에서 안 따른 것** — 「다른 로트 추가」(현 코드는 후보를 전부 보여 준다) · 로트번호 말줄임
   (현 코드가 일부러 줄바꿈) · 부족 안내 상단 띠(현행 유지 — 버튼 바로 위가 결정하는 자리).
5. 시트 입력칸은 `text-[16px]` — 16px 미만이면 iOS가 누르는 순간 화면을 확대한다.

⏸ 5~8(택배 펼침 · 후보 많은 라인 스크롤 · 데스크탑 팝오버/패널 시트 · 매칭실패 시트)은 미확인 — 실기기 M1-7에서 같이 본다.
⚠️ 곁관찰: 시트를 닫은 뒤 눌렀던 카드(또는 그 자리의 완료 줄)에 파란 포커스 테두리가 남는다 — Radix가 포커스를 되돌려서다. 기능 영향 없음.

1. 폰 건상세 → 일반 라인 탭 → 시트, `−/+` 44px, 확정 → **패널은 열린 채** 숫자 갱신
2. 폰 건상세 → **톤백** 라인(시아스) → 자루 선택 → 확정
3. 폰 완료 라인 → 「차감 취소」 → 확인창 → 복원 · 🔴 **확인창에서 「취소」를 눌렀을 때 시트·패널이 닫히지 않는지**(세 번째 층)
4. 시트 **X / 딤 탭 / ESC** — 셋 다 시트만 닫히고 건상세는 남는지(「닫는 방법에 따라 다르다」가 이 결함의 지문)
5. 택배 펼침 카드 탭 → 시트(패널 없이)
6. 후보 많은 라인 — 시트 안에서 **목록만** 스크롤되고 확정 버튼이 늘 보이는지 · 아이폰 하단 홈 바에 버튼이 안 깔리는지
7. 데스크탑: 셀 팝오버 그대로 · 팝오버 열린 채 옆 셀 클릭 → 새 팝오버가 뜨는지 · 패널 카드 클릭 → 패널 폭 시트
8. 매칭실패 라인 탭 → 안내 시트
