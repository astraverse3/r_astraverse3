## 2. 🔴 계획서와 달랐던 것 — 전수 대조에서 나온 5건

계획서가 지목한 자리가 아니라 **「묶음·FIFO·라인」을 쓰는 전부**를 grep한 결과다.

### ① 동어반복 4건 — 단순 치환이 불가능했다
「묶음 = 시트 1장」을 **설명하던** 문장들이다. 용어를 통일하면 "시트 1개 = 시트 1건"이
되어 말이 안 된다. 📌 **용어를 합치면 그 둘의 관계를 설명하던 문장은 설명할 게 없어진다** —
치환이 아니라 걷어내야 하는 자리다.

| 자리 | 전 | 후 |
|---|---|---|
| `upload-dialog:210` | 체크한 시트마다 **묶음 1건**이 생성됩니다 | 체크한 시트마다 **1건씩 등록**됩니다 |
| `upload-dialog:211` | **시트 1개 = 묶음 1건** · 파일을 올리면… | 파일을 올리면… (앞부분 삭제) |
| `upload-dialog:281` | {n}개 시트 → 묶음 {n}건 · 라인 {t} | 시트 {n}개 · 품목 {t}개 |
| `upload-table:192` | **묶음 1건 = 시트 1장** · 상차 임박순… | 상차 임박순… (앞부분 삭제) |

`upload-dialog:281`은 **같은 값(`checkedSheets.length`)을 「시트」와 「묶음」이라는 두 이름으로
두 번 세고 있었다.** 이름이 하나가 되자 중복이 드러나 한 번만 센다(3줄 → 2줄).

### ② 🔴 조사가 바뀐다 — 묶음(받침 ㅁ) ≠ 시트(받침 없음)
`묶음이 없어요` → `시트**가** 없어요` · `묶음을 삭제` → `시트**를** 삭제` ·
`묶음과 그 안의` → `시트**와** 그 안의`. 기계적 치환이면 「시트이 없어요」가 됐다.
**라인 → 품목은 둘 다 받침이 있어 조사가 안 바뀐다.**

### ③ 누락 — review-gate-dialog 「라인」 8곳 → **9곳**
계획서에 없던 `:361` `` `라인 ${r.itemId}` `` (이름을 못 찾았을 때의 대체 표기).

### ④ 누락 — 액션 에러 11곳 → **15곳**
계획서 목록에 없던 파일 2개: `lib/purchase-order-cell.ts:76` ·
`lib/purchase-order-db.ts:100`. **`lib/` 아래에도 화면에 뜨는 `throw` 문구가 있다.**

### ⑤ 오탐 6건 — 「인라인」
`라인`으로 grep하면 **「인라인」**이 걸린다(statistics 3곳 · add-packaging-dialog ·
deduct-dialog · misc-package-dialog). 전부 주석이고 발주서와 무관 → 제외.

## 3. §3 선결 과제 — 푸터 버튼: **A안 채택**

```
전    31라인 FIFO 일괄차감     14자
후    31품목 일괄차감           8자   ← A안
```
계획서 제안대로 **순서 단서는 다른 자리**로 옮겼다 — 게이트 상단 요약의 로트 개수 바로 뒤다.

```
포장 59개 · 로트 8개              →  포장 59개 · 로트 8개 · 오래된 것부터
```
게이트는 「이만큼 이렇게 나갑니다」를 보여주는 자리라 로트 수 뒤가 자연스럽다.
셀 팝오버는 `FIFO 추천 · 오래된 로트부터` → `오래된 로트부터 추천`.
