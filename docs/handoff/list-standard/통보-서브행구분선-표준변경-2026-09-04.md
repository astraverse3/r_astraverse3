# 표준 변경 통보 — 펼친 묶음의 「내부 구분선 제거」를 되돌립니다

**보내는 쪽**: 구현 (2026-09-04)
**대상**: `handoff.md` §4.2.2 · §4.2.6 / 지시서 R3
**성격**: 확인 요청이 아니라 **결정 통보**입니다. 이견 있으시면 되돌리겠습니다 (CSS 한 줄 수준).

---

## 무엇을 바꿨나

| | 초안 (R3 / §4.2.6) | **변경 후** |
| --- | --- | --- |
| 펼친 묶음 배경 | `bg-slate-100` (헤더+서브행 동일) | **그대로** |
| 묶음 위쪽 경계 | `border-t border-slate-200/80` | **그대로** |
| **묶음 내부 행 경계** | **`border-b-0`으로 지움** | **`border-b border-slate-200/70`로 유지** |

묶음톤 위에서는 기본 `border-slate-100`이 보이지 않으므로 **색을 한 단 올려서** 줍니다.

## 왜

초안의 근거는 「가로선이 남으면 묶음이 다시 잘려 보인다」였습니다.
실화면에서는 **반대 문제가 더 컸습니다** — 선을 지우자 **행을 셀 수 없는 회색 덩어리**가 됐습니다.

- 제품재고에서 먼저 드러났습니다. 한 품종(IPS)에 서브행이 **9줄**이고,
  그중 `백미`·`윤영식`·같은 로트가 9행 내내 반복돼 리듬을 만들 요소가 하나도 없었습니다.
- R6 적용 직후 사용자 확인에서 바로 지적됐고, 그때는 **제품재고만 예외**로 처리했습니다.
- 이후 원물재고·생산자관리를 다시 보니 같은 문제였습니다. **예외가 아니라 원칙이 틀렸다**고 판단해
  세 화면 모두 되돌렸습니다.

**정리하면**: 묶음은 **배경색**이 표현하고, 행 구분은 **선**이 합니다.
하나(배경)로 두 가지를 다 하려다 둘 다 잃었습니다.
배경톤은 그대로 두었으므로 **묶음 일체감은 유지됩니다** — 선만 돌려놓은 것입니다.

## 부수 발견 — 벼는 원래부터 선이 남아 있었습니다

R3에서 세 화면을 통일했다고 기록했지만, 실제로는 **벼 원물재고 서브행에만 `border-b-0`이 걸리지 않아**
기본 구분선이 남아 있었습니다. 결과적으로 **의도한 모습이 벼에 이미 있었던 셈**입니다.
이번 변경으로 네 화면의 상태가 처음으로 실제로 일치했습니다.
