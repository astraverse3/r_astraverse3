# 디자이너 확인 요청 — 제품재고 목록에 목록 표준규격을 적용할까요?

**보내는 쪽**: 구현 (2026-09-04)
**관련**: `list-spec-instructions.md` R5 · 백로그 §30 · `report-목록표준규격-R5-2026-09-04.md`

---

## 한 줄 요약

목록 표준규격을 표 10곳에 적용했는데, **가장 많이 쓰는 제품재고 목록만 표준 밖에 남아
오히려 격차가 벌어졌습니다.** 여기에도 타이포·밀도를 적용해도 될지 확인 부탁드립니다.

---

## 1. 무슨 일이 있었나

지시서대로 R1~R4b를 적용해 **`<table>` 기반 목록 10곳**이 표준값(헤더 40px / 본문 44px / 14px)이 됐습니다.

그런데 **제품재고 목록은 `<table>`이 아니라 CSS Grid**(`package-row.tsx`의 `PKG_GRID`)입니다.
이번 작업은 전부 `components/ui/table.tsx` 프리미티브를 통해 이뤄졌으므로 **여기엔 아무 영향이 없었습니다.**
시안이 지목한 「목록 11곳」도 전부 `<table>` 기반이었습니다.

🔴 **문제는 이 작업의 출발점이 「화면을 옮기면 밀도가 튄다」였다는 것입니다.**
표 10곳을 14px로 올린 결과, **가장 사용 빈도가 높은 목록 하나만 혼자 작아졌습니다.**

| | 표준화된 표 10곳 | 제품재고 (grid) |
| --- | --- | --- |
| 헤더 | 40px · 14px · `font-medium` · `text-foreground` | `text-[10.5px] uppercase tracking-wider text-slate-400 font-bold` · `py-2.5` |
| 본문 | 44px · 14px | `text-[13px]` · 보조값 `text-[12px]`/`[11.5px]`/`[11px]`/`[10px]` 혼재 |
| 좌우 패딩 | `px-3` | `px-4` |
| 펼친 묶음 | `bg-slate-100` + `border-t border-slate-200/80` | `bg-slate-50/60` + `ring-1 ring-inset ring-slate-200/70` |
| 로트 컬럼 | ≥24% | `1.4fr` ≈ 23% (거의 근접) |

## 2. 저희 쪽 해석 — 지시서 문면으로는 「적용」이 맞아 보입니다

처음에는 지시서 R5의

> §4.2의 **CSS grid 마크업 자체는 유지**한다 (펼침 포장재고는 `<table>`로 표현하기 어렵다)

를 보고 **「제품재고는 현행 유지」**로 읽었습니다. 그런데 R5 문서 개정을 진행하면서 다시 보니:

- **§4.2는 `<table>` 문서가 아니라 CSS Grid 문서** — 즉 **바로 이 제품재고 화면의 근거 문서**입니다.
- 그런데 지시서 R5의 「함께 개정할 것」이 그 §4.2의 **타이포 값을 콕 집어 지정**했습니다:

  ```
  §4.2.4/4.2.5/4.2.6 — text-[12.5px] → text-sm · px-4 py-2.5 → px-3 h-11
                       로트 text-[11px] → text-[12.5px]
  §4.2.6 묶음 — ring-1 ring-inset ring-slate-200/70 → border-t border-slate-200/80
  ```

즉 **「grid 마크업 유지」는 마크업 구조를 뜻하고, 타이포·밀도는 표준으로 올리라는 것**이
지시서 자신의 문면으로 읽힙니다. 둘은 실제로 분리 가능합니다 — `<table>`로 바꾸지 않고도
헤더 40px · 본문 44px · 14px은 그대로 줄 수 있습니다.

**이 해석이 맞는지 확인 부탁드립니다.**

## 3. 적용하면 이렇게 바뀝니다

`package-row.tsx` 두 줄이 출발점입니다 (개정 전 §4.2의 값이 그대로 남아 있습니다).

| 위치 | 현행 | 표준 적용 시 |
| --- | --- | --- |
| `:95` 컬럼 헤더 | `text-[10.5px] uppercase tracking-wider text-slate-400 font-bold px-4 py-2.5 bg-slate-50/60` | `h-10 px-3 text-sm font-medium text-foreground bg-slate-50 border-b border-slate-200` |
| `:332` 펼친 묶음 | `bg-slate-50/60 ring-1 ring-inset ring-slate-200/70` | `bg-slate-100` + `border-t border-slate-200/80` |
| `:219 / :276 / :336` 행 | `text-[13px] px-4 py-3` (또는 `py-2.5`) | `text-sm px-3 h-11` |

> 참고 — 헤더의 `uppercase`·`tracking-wider`는 **한글에는 아무 효과가 없고** 글자만 10.5px로 작아집니다.
> 원래 Typography의 **Micro Bold(영문 섹션 라벨, "MAIN MENU")** 토큰인데 한글 헤더에 쓰이고 있었습니다.

**부수 결정이 필요한 것**
1. **행이 세로로 길어집니다** — `text-[13px]` → 14px, 높이 44px 고정. 한 화면에 보이는 행 수가 줄어듭니다.
   제품재고는 목록이 길어 이 영향이 표 10곳보다 큽니다. **그대로 진행할지, 여기만 예외로 둘지** 판단이 필요합니다.
2. **보조값 폰트 계단** — 현재 `[12px]`/`[11.5px]`/`[11px]`/`[10px]`이 섞여 있습니다.
   표준은 로트 `[12.5px]`, 칩 `[11.5px]`만 규정합니다. 나머지를 어디로 모을지 기준이 필요합니다.
3. **모바일 카드**(`mobile-package-card.tsx`)는 표준규격 범위 밖입니다.
   데스크탑만 올리면 **같은 화면의 모바일/데스크탑 밀도가 갈립니다.** 같이 볼지 확인 부탁드립니다.
   (🔴 카드 폰트를 키우는 건 이미 「하지 않는다」로 정해져 있습니다 — 줄 넘침이 더 큰 문제였습니다.)

## 4. 여쭙는 것 — 셋 중 하나로 답 주시면 됩니다

| | |
| --- | --- |
| **A. 전면 적용** | grid 구조는 유지하고 타이포·밀도를 표준으로. 위 2절 해석대로 |
| **B. 헤더만** | 가장 눈에 띄는 컬럼 헤더(10.5px → 14px/40px)만 먼저. 본문 밀도는 현행 유지 |
| **C. 현행 유지** | 제품재고는 밀도가 높은 것이 맞다. 표준을 이 화면에는 적용하지 않는다 (그러면 §30을 닫습니다) |

**B·C를 고르실 경우**, 「화면마다 밀도가 다른 것」이 이 작업에서 의도된 예외임을
기준서에 명시해 두겠습니다 — 다음에 또 같은 질문이 반복되지 않도록.

## 5. 참고 — 이미 처리한 것

- **R5 기준서 개정 완료**: `docs/handoff/디자인시스템/handoff.md` §4.2를 표준값으로 개정했고,
  「**현재 제품재고 화면은 아직 옛 값**」이라고 명시해 뒀습니다. 지금은 **문서가 앞서 있고 코드가 뒤에 있는** 상태입니다.
- 지시서가 지정한 값 중 **실화면에서 조정된 것이 있습니다**(이미 확인받은 사항):
  묶음톤 `bg-slate-50/75`는 흰 배경과 밝기차가 2%뿐이라 묶음으로 보이지 않아 **`bg-slate-100`**(5.5%)으로 확정했습니다.
- **범위 주의**: 재포장 선택 모드(`PKG_GRID_SELECT`)·펼침 그룹·모바일 카드가 얽혀 있어
  작업 자체는 작지 않습니다. 방향이 정해지면 계획서를 먼저 쓰겠습니다.
