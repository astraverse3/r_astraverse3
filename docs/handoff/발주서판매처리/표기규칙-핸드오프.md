## 0. 한 줄 요약

이름 열은 **`굵은 값 ｜ 세로선 ｜ 연한 값`** 한 가지 형태만 쓴다. 채널마다 바뀌는 것은 **두 값의 순서**와 **열 머리 라벨**뿐이다. 색 스트라이프·컨텍스트 바·조건부 표기는 쓰지 않는다.

기준: **행마다 변하는 값이 앞에 굵게.**

## 1. 실측 시트 구조

모든 시트가 같은 골격이다.

행 | 내용
---|---
1 | 날짜·채널명(A) + 품목명(D열~)
2 | `포장지` + 포장지명(자연주의 / PET / 톤백 …)

4 | `소계` + 규격별 합계(개)
5 | `(발주처)`(A) · `(수령인)`(B) — **라벨 행**
6~ | 데이터. A = 발주처, B = 수령인, C열~ = 주문 수량

## 3. 실데이터에서 드러난 세 가지 (설계 영향)

### ① 발주처 블록이 연속되지 않는다 — 기본 정렬을 발주처로

시트 원본 순서에서 같은 발주처가 **떨어져 나타난다.**

- `서대문마을생협` → 22~25행, 그리고 **60행**
- `우리아이행복밥상` → 20~21행, 그리고 **69~70행**
- `일반판매` → 26행, 그리고 **68행**
- `네이버스토어` → 34~59행, 그리고 **71행**

따라서 「발주처가 블록으로 반복되니 이름이 바뀌는 지점이 곧 경계」라는 전제가 **원본 순서에서는 성립하지 않는다.** 대응:

- 택배 매트릭스의 **기본 정렬을 `발주처별`로** 둔다(정렬하면 블록이 실제로 뭉친다).
- 또는 `③ 발주처 그룹 행`으로 전환한다 — 발주처가 10곳이고 최대 27행이므로 **그룹별 규격 소계의 값이 크다.** (시안: `card-layouts/매트릭스-발주처-수령인-표기-3안.html` ③)

### ② 발주처 = 수령인인 행이 실제로 있다 (3건)

`서대문마을생협`(25행) · `예은농산`(67행) · `해남로컬푸드`(74행). §4의 동일명 한 줄 처리는 **반드시 필요**하다.

### ③ 발주처 자리에 거래처가 아닌 값이 온다

- `일반판매` (택배 26·68행) — 자사 직접 판매. **그대로 표시한다** — 발주 경로가 맞고, 치환하면 시트 값과 화면이 서로 다른 말을 한다.
- `여유` (서울급식 8행) — 여분으로 2개정도 더 보내는 물량. **주문은 아니지만 재고는 실제로 나간다.** → §4-b

## 4-b. `여유` 행 — 화면에선 특별 처리 없음

**다른 발주처 행과 동일하게 렌더한다.** 사용자가 이미 시트에서 「여유」를 A열에 쓰며 일하고 있으므로, 화면이 달라질 이유가 없다. 칩·별도 배경·맨 아래 고정 같은 장식은 모두 버렸다.

- 이름 칸: `여유 ｜ 행복플러스` — 다른 행과 같은 2단 표기
- 상태: `대기`/`부분`/`완료` 일반 상태를 그대로 쓴다(전용 배지 없음)
- 체크박스 **있다** — 여분도 차감 대상이므로 일괄 차감에 포함되어야 한다
- 정렬·집계 모두 일반 행과 동일

**단 한 곳에서만 다르다 — §6 발주처 상수 검증.** 상수가 발주처인 채널(이마트·해남급식)에 `여유` 행이 섞이면 **상수 검사에서 제외**한다 — 여분은 발주처가 바뀌었다는 뜻이 아니다. (서울급식은 수령인이 상수이므로 이 검사와 무관하다.)

```js
const SPARE = ['여유', '여분'];
// 렌더·집계·정렬: 일반 행과 동일
// 상수 검증만: rows.filter(r => !SPARE.includes(r.vendor))
```

## 4. 이름 셀 구현

```js
const [head, tail] = decl.primary === 'vendor'
  ? [row.vendor, row.recipient]
  : [row.recipient, row.vendor];

// 동일명이면 한 줄만 — 실데이터에 3건 있다
const twoTier = decl.primary !== 'single' && tail && tail !== head;
```

```html
<!-- 2단 -->
<td class="nm">
  <div class="flex items-center">
    <span class="text-[12.5px] font-bold text-slate-900 truncate" style="width:104px;flex:none">{head}</span>
    <span class="text-[10.5px] font-medium truncate"
          style="flex:none;padding-left:10px;border-left:1px solid #cbd5e1;color:#64748b">{tail}</span>
  </div>
</td>

<!-- 한 줄 (시아스 · 동일명 행) -->
<td class="nm"><div class="text-[12.5px] font-bold text-slate-900">{head}</div></td>
```

값 | 스펙
---|---
앞 값 폭 | `104px` 고정 (`truncate`) — 구분선이 모든 행에서 같은 x에 선다
구분선 | `1px solid #cbd5e1`, 왼쪽 `padding 10px`
뒤 값 | `10.5px` / `font-medium` / `#64748b` (4.76:1)
행 높이 | `44px` (변경 없음)

`104px`는 실데이터 최장값 기준 재검토 대상이다 — `이마트본사 김보훈`, `울림생협 북가좌점`, `롯데백화점 평촌점`은 잘린다.

**하지 않을 것**

- 색 스트라이프 / 해시 색 — 실데이터에 올려 보고 **기각**(너무 강함).
- 발주처 약칭(2~3자) — 별칭 마스터가 없고 `땅끝황토친환경`/`땅끝농협`이 충돌한다.
- `←` 화살표 표기 — 이름 길이마다 위치가 흔들려 정렬선이 없다.
- 컨텍스트 바(고정값을 표 위로) — 행 단위 완결성을 택했다.
- 조건부 2단(`다를 때만`) — 동일명 예외만 남기고 나머지는 전 행 2단.

## 5. 헤더 집계 강조

`규격별 소계` 행이 이 화면에서 가장 먼저 읽혀야 한다. 시트 4행이 그대로 이 줄이 된다.

```css
.mx thead tr.sumrow th,
.mx thead tr.sumrow th.sumcell,
.mx thead tr.sumrow th.sumkg { height:40px; font-size:15px; font-weight:800; }
.mx thead tr.sumrow th.sumlabel { font-size:12.5px; }
.mx thead tr.sumrow2 th,
.mx thead tr.sumrow2 th.sumcell { height:28px; font-size:11.5px; }
```

- 소계 숫자 `11.5px → 15px`, `font-weight 800` — **본문 행보다 크게.** 행 높이 `30 → 40px`.
- **가용 재고 행은 올리지 않는다.** 소계는 「할 일」, 가용은 「조건」 — 주·보조 관계 유지.
- 부라벨 `(개)`는 `#475569`.
- **주의 — 특성도:** 강조 규칙에 `color`를 넣으면 `.short`(재고부족 앰버 `#b45309`)를 이겨 경고가 사라진다. 강조 규칙은 `height/font-size/font-weight`만 지정한다. 선택자는 `tr.sumrow th.sumcell`(0,4,2) 형태로 써서 기존 `.sumcell{font-weight:700}`을 소스 순서와 무관하게 이긴다.
- sticky `top` 재계산: `sumrow2.top = sumrow.top + 40`.

## 6. 업로드 검증 — 선언 위반은 막는다

파싱 직후, **매트릭스 진입 전에** 검사한다. 매트릭스 본체에는 분기 로직을 두지 않는다.

```ts
type ChannelDecl = {
  channel: '이마트' | '해남급식' | '서울급식' | '택배' | '시아스';
  primary: 'recipient' | 'vendor' | 'single';
  constantSide: 'vendor' | 'recipient' | null;
  columnLabel: string; // '수령인' | '발주처' | '거래처'
};

if (decl.constantSide) {
  const vals = new Set(rows.map(r => decl.constantSide === 'vendor' ? r.vendor : r.recipient));
  if (vals.size > 1) blockUpload({ channel: decl.channel, found: [...vals] });
}
```

위반 시 화면:

- 제목 「**발주처가 2곳 섞여 있어 진행할 수 없어요**」 + 읽힌 값과 건수 목록
- 액션 2개: `어떤 행인지 보기` / `시트 고치고 다시 올리기`
- **진행 버튼 없음. 자동 폴백 없음. 「이번만 예외」 없음.**

이유: 차감은 되돌릴 수 없다. 예외를 통과시키면 그 예외가 기록으로 남지 않아, 나중에 재고가 틀어졌을 때 원인을 추적할 수 없다.

**상수 채널 주의:** 이마트·해남급식에 `여유` 행이 섞이면 이 검사가 발주처 2곳으로 읽어 정상 시트를 막는다. `SPARE` 필터가 검사보다 먼저다(§4-b).

## 7. 용어

`수령인` · `발주처` · `거래처`만 쓴다. **`받는사람`, `수령점포`, `발주구청`은 쓰지 않는다.** 열 머리, 검색 placeholder, 정렬 라벨, 상세 패널 제목, 일괄 차감 문구 전부 동일.

택배 정렬 토글: `발주처별`(기본) → `수령인 가나다` → `최신 업로드순` → `작업 필요 우선`

긴 이름은 `truncate`로 자른다 — 전체는 이름 클릭 시 상세 패널에서 보여준다. 열 폭은 늘리지 않는다(규겍 열 우선).

## 9. 확정된 결정 (2026-09-11)

1. **그룹화 제외.** 택배는 `발주처별` 기본 정렬로 간다. ③ 그룹 행은 나중에 필요해지면 재검토.
2. **기업별 발주처 = 파일명/시트명.** 시트 안에 수령인 열이 없음 — 한 값만 표기.
3. **명칭은 시트 원본 그대로** (`이마트` · `해남급식` · `행복플러스`).
4. **`일반판매` 그대로 표시.** 발주 경로가 맞고, 치환하면 시트 값과 화면이 서로 다른 말을 한다.
5. **`여유`는 일반 발주처 행과 동일하게** — 상수 검증에서만 제외 (§4-b).
6. **긴 이름은 `truncate`.** 열 폭 유지.

### 남은 항목

- **채널 선언 설정 UI** — 관리자 화면에 노출할지, 코드 상수로 둘지.
- **시아스 톤백 거래** — 규격이 `1,000kg`/`200kg` 톤백이라 「개수」 집계가 다른 의미다. 재포장 화면과 어떻게 물릴지 확인 필요.
