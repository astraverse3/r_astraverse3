보류 4건 → 스키마 확인 후 확정
  1. 미차감·실패 라인 포함 → 포함(기본 켜짐). 데이터는 이미 있고, 발주처에 "왜 이건 안 나갔나"를 설명하는 것이 시트의 주 용도라 회색 행으로 함께 출력합니다.
  2. 도정일 → 있음. 단 「도정/매입일」로 통합. 도정품은 MillingBatch.date, 외부매입 잡곡은 batch가 없어 MillingOutputPackage.incomingDate(매입일).
  3. 보관위치 → 열 삭제. 스키마에 위치·창고 필드가 없습니다(Stock.bagNo는 벼 원물 톤백 번호로 제품 포장 단위와 다릅니다). 대신 인쇄용 「피킹 확인」 빈 칸.
  4. 로트번호 → 전체 노출. 화면(팝오버)은 좁아 뒤 4자리만 쓰지만, 시트는 증빙용이므로 lotNo 전체. 매입품은 null이므로 「매입 · {매입처}」로 대체 표기합니다.
개발 주의
  • lotNo는 nullable + 매입품은 항상 null. 로트번호를 그룹 키나 정렬 키로 그냥 쓰면 매입 잡곡이 한 덩어리로 뭉칩니다 — 그룹 키는 packageId로, 표시만 로트번호/매입처로 하세요.
  • 입고일도 출처가 갈립니다 — 도정품은 Stock.incomingDate(원물 입고일), 매입품은 incomingDate(매입일). FIFO 정렬은 실제 배분에 쓰는 기준과 동일한 키를 쓰세요.
  • 처리자는 createdName 스냅샷(relation 없음) — 사용자명이 나중에 바뀌어도 시트는 당시 이름을 보여줍니다. 의도된 동작.
  • 금액·단가 필드는 스키마에 없습니다(수량 차감만). 시트에 단가·매출 열을 넣을 수 없습니다.
인쇄 시

B안은 그대로 공장 피킹 리스트가 됩니다 — 그룹 헤더 반복 + 「피킹 확인」 칸이 이미 있어 A4 세로 1~2장. 필요하면 별도 인쇄 시안으로 뽑겠습니다.
