# Handoff: 발주서 판매처리 (제품판매 탭)

거래처 발주서(엑셀)를 업로드해 제품재고를 차감하기까지의 전 흐름. 데스크탑 9화면 + 모바일 6화면.

## 이 폴더의 파일은 "디자인 참조"입니다
번들의 HTML은 **의도한 화면과 동작을 보여주는 프로토타입**이며 그대로 가져다 쓰는 프로덕션 코드가 아닙니다.
작업은 이 화면들을 **`milling-log` 기존 환경(Next.js 16 App Router · React 19 · Tailwind v4 · shadcn/ui · lucide-react)에서 재현**하는 것입니다.
Tailwind 임의값(`text-[12.5px]`, `bg-[#2563eb]`)은 **shadcn 시맨틱 토큰**(`bg-primary`, `text-muted-foreground`)으로 치환하세요. 자세한 변환 원칙은 `../README.md`.

## 충실도
**High-fidelity.** 색·타이포·간격·상호작용이 확정값입니다. 레이아웃과 수치를 그대로 재현하되, 컴포넌트는 코드베이스의 shadcn 기본형을 사용하세요.

## 코드 기준 사실 (구현 전 반드시 읽기)
`prisma/schema.prisma`, `app/actions/purchase-order.ts` 확인 완료.

- **차감은 명시적 확정 시에만** — `confirmOrderItem(itemId, allocations)` / `confirmOrder(orderId)`. 업로드·매칭만으로는 재고가 빠지지 않습니다(전부 대기).
- **상태는 파생값** — 라인 차감량 vs `orderedQty` → `recalcOrderStatus`로 `PurchaseOrder.status` 집계. **승인·마감 상태는 없고, 만들지 않습니다.**
- **매칭실패**(`productTypeId == null`)는 차감 자체가 불가 → `confirmOrder`가 `continue`로 건너뜁니다. **재고부족**은 가능한 만큼 차감하고 부분으로 남습니다.
- **롤백은 제한적** — `cancelOrderItemMovements(itemId)`는 **라인 단위**로만 동작하고 해당 라인의 SALE movement를 **전량 하드삭제**합니다(부분 취소 없음). 건·묶음 단위 일괄 취소 함수는 **없습니다**. 재고 수치는 복원되지만 이력은 감사로그에만 남습니다.
- 차감된 movement가 있으면 `deletePurchaseUpload`가 **삭제를 차단**합니다.
- **외부매입 잡곡은 `lotNo`가 항상 null** (`source=PURCHASED`). 로트번호를 그룹/정렬 키로 쓰면 매입품이 한 덩어리로 뭉칩니다 → 키는 **`packageId`**, 표시만 「매입 · {purchaseVendor}」.
- 금액·단가 필드는 스키마에 **없습니다**(수량 차감만). 화면·시트에 매출 열을 넣을 수 없습니다.
- 권한: 전부 `OPERATION_MANAGE`.

## 현재 코드 상태
- `app/(dashboard)/sales/product-sales-section.tsx` — 묶음 목록만 `listPurchaseUploads`로 표시. 업로드 버튼은 비활성 placeholder.
- 서버 액션은 대부분 존재: `listPurchaseUploads` / `listPurchaseOrders` / `setOrderItemProductType` / `confirmOrderItem` / `confirmOrder` / `cancelOrderItemMovements` / `deletePurchaseUpload`.
- **없는 것**: 매트릭스 화면, FIFO 배분 UI, 검토 게이트용 dry-run 조회, 엑셀 업로드/내보내기 UI, 로트 배분 시트 생성.

## 확정된 설계 결정
1. **모든 채널이 하나의 매트릭스 문법** — 행=수령처, 열=제품규격. 발주서 원본이 모두 이 피벗 구조라서 사용자가 엑셀에서 보던 화면 그대로 작업합니다.
2. **모바일은 데이터 모양으로 3모드 자동 판정** (채널 이름 분기 아님 — 같은 채널도 파일마다 모양이 다름):
   - **카드 모드**: `수령처 ≤ 2 && 규격 ≤ 2` (기업별 1×1) → 표 없이 규격별 카드 n장
   - **전치 매트릭스**: `수령처 ≤ 3 && 규격 ≥ 6` (급식 13×2) → 행=규격, 열=수령처. 가로 스크롤 제거
   - **표준 매트릭스**: 그 외 (택배 14×20+, 이마트 5×3) → 좌우 고정 + 가로 스크롤
   경계값은 잠정 — 실제 파일이 늘어나면 재조정.
3. **검토 게이트는 필수, 단일 셀 차감은 예외.** 상태를 추가하지 않고 `confirmOrder` 호출 직전 프리플라이트 화면으로 처리. 걸릴 게 없으면 축약 모달 1클릭 통과. 이상 집합은 **차단 사유 2종만** — 매칭실패(제외) / 재고부족(부분). 수량 이상치·로트 소진 예정은 노이즈로 판단해 제외.
4. **페이지 이동 최소화** — 건 목록+상세 통합 폐기, 배분·수동지정·확정 전부 인라인 또는 오버레이.
5. **비고 수정 진입점 = ⋮ 메뉴** (데스크탑 드롭다운 / 모바일 액션시트 → 편집 시트).

## 신규로 필요한 조회
- **미매칭 라인 목록** — `productTypeId == null`. 기존 데이터로 즉시 산출.
- **부족 예상 (dry-run)** — 라인별 `suggestAllocation` 결과를 **커밋 없이** 미리 계산. `confirmOrder`가 실제로 도는 로직과 **동일한 함수를 dry-run 모드로 재사용**해야 검토 결과와 실제 차감이 일치합니다.
- **동시성** — 검토 화면을 띄운 사이 다른 사용자가 같은 재고를 차감할 수 있습니다. 확정 시 서버에서 **재계산**하고 검토 때와 결과가 다르면 **확정을 멈추고 재검토**를 띄우세요(조용히 부분 차감 금지).

## 구현 순서 제안
1. 엑셀 업로드 → 묶음 목록(기존 섹션 확장) — 파서·`listPurchaseUploads` 이미 있음
2. 표준 매트릭스 1개(택배) + 셀 FIFO 배분 팝오버 → `confirmOrderItem`
3. 행 선택 일괄 차감 + **검토 게이트**(dry-run) → `confirmOrder`
4. 나머지 채널 매트릭스(같은 컴포넌트에 데이터만 교체) + 모바일 3모드
5. 엑셀 내보내기 + 로트 배분 시트
