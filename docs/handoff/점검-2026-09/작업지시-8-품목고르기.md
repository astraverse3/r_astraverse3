## P1. `SkuPicker` — 공통 부품
새 props:
```ts
value: AddableSku | null                     // id → 객체 (고른 줄 표시용)
onChange: (sku: AddableSku | null) => void   // null = 「바꾸기」
taken?: number[]                             // 이미 주문에 있는 productTypeId
qty / onQty                                  // 수량 칸을 부품 안으로
action?: ReactNode                           // 수량 옆 버튼(건 상세의 「추가」)
autoFocus?: boolean
```

**1) 고르기 전 — 검색칸**
- 검색칸: `h-10 sm:h-9`, 왼쪽에 `Search` 15 slate-500, 14px
- 결과는 **검색칸에 들어가거나(focus) 글자가 있을 때만** 펼친다. 처음 열었을 땐 목록이 안 보인다.
- 결과 상자
  - 모양: `rounded-md border border-slate-200 bg-card`
  - 높이: **최대 5줄**(`max-h-[200px] overflow-y-auto`). 줄 높이 `h-10`
  - 줄 내용: 이름+규격 13 semibold slate-800 · 오른쪽 포장지 12 slate-500
  - 키보드: ↑↓로 이동, Enter로 고름. 첫 줄은 미리 강조(`bg-slate-50`)
- **이미 있는 품목**(`taken`에 포함)
  - 이름 slate-500
  - 오른쪽 포장지 자리에 `rounded bg-slate-100 px-1.5 py-0.5 text-[12px] text-slate-500` 「이미 있음 · 수량에서 고치기」
  - 눌러도 **아무 반응 없음**(`aria-disabled`, `cursor-default`). 키보드 이동에서도 건너뛴다.
  - 서버 거부(같은 SKU 줄 있음)는 그대로 둔다(이중 안전장치).
- 결과 없음, 불러오는 중, 오류 문구는 지금 그대로 둔다.

**2) 고른 뒤 — 한 줄**
- 결과를 닫고 `[✓ 품목 · 포장지 …… 바꾸기] [− n +] [action]` 한 줄로 바꾼다.
- 고른 칸
  - 모양: `flex-1 min-w-0 h-10 rounded-md border border-blue-200 bg-blue-50 pl-3 pr-1`
  - `Check` 14 primary
  - 글자: 품목 13 semibold slate-900, 「· 포장지」 slate-600, `truncate`
- 「바꾸기」: `h-8 px-2 text-[12px] font-semibold text-blue-700 hover:bg-blue-100`. 누르면 `onChange(null)`이 불리고, 검색칸으로 돌아가 포커스된다(지난 검색어 유지).
- 수량 칸: ⑦의 −/+ 수량 칸과 같은 모양
  - 최소 1, 최대 `MAX_ORDER_QTY`, 기본값 1
  - 가운데는 입력칸(직접 입력 가능)
- 지금의 `QtyRow`와 `AddItemForm` 안 수량 줄(「위에서 제품을 골라 주세요」 + 「1 개」)은 **삭제**한다.

## P2. 주문 추가 창 (`add-order-dialog.tsx`)
- 설명: 「주문 한 건을 첫 품목과 함께 넣어요. 품목은 건 상세에서 더 넣을 수 있어요.」
- **필수가 아닌 이름 칸**
  - 라벨 옆 「(비우면 위와 같게)」를 **삭제**한다.
  - 칸 안 placeholder로 「비우면 발주처와 같음」(수령인 칸) / 「비우면 수령인과 같음」(발주처 칸)을 넣는다.
  - 미리 채우는 기본값(`mostCommon`)은 지금처럼 **값으로** 넣는다. placeholder와는 다른 것이다.
- 「첫 품목」: `<SkuPicker value qty onQty />`. `taken`은 없다(새 건).
- 푸터 「취소 · 주문 추가」는 그대로. 품목을 고르기 전엔 주문 추가가 비활성이다.

## P3. 건 상세 · 품목 추가 (`AddItemForm`)
- **접힘:** 점선 상자를 없앤다. 대신 ⑦ 목록 카드의 **마지막 줄**로 둔다(`divide-y` 안).
  - 모양: `w-full h-12 pl-4 flex items-center gap-1.5 text-[13px] font-semibold text-blue-700 hover:bg-blue-50`
  - 아이콘: `Plus` 15
- **펼침:** 같은 자리에 `bg-slate-50 px-4 pt-3 pb-4` 영역을 연다.
  - 위 줄: 「품목 추가」 12 semibold slate-700 · 오른쪽 `X` 버튼 32(누르면 접고 비운다)
  - 그 아래: `<SkuPicker autoFocus taken={lines.map(l => l.productTypeId)} action={<Button h-8>추가</Button>} />`
  - 「추가」는 품목을 고르기 전엔 비활성이다. 성공하면 접고 비운다. 실패하면 입력을 남긴다(지금 그대로).
- 지금의 「닫기 · 추가」 버튼 줄은 **삭제**한다.
- 펼치면 패널 본문을 아래로 스크롤해 영역이 보이게 한다. 이때 `scrollIntoView`는 쓰지 말고 컨테이너의 `scrollTop`으로 맞춘다.

## P4. 헤더 「고치는 중」
⑦ E1과 같다. 파랑 글자 링크처럼 보이던 것을 연한 파랑 바탕의 표시로 바꾼다.
- 모양: `h-6 px-2 rounded-md bg-blue-50 text-[12px] font-semibold text-blue-700`
- 내용: `Pencil` 12 + 「고치는 중」
- 누를 수 없는 표시다(`<span>`).

## 완료 기준
- [ ] 두 화면 모두 처음 열면 품목 목록이 안 보이고, 검색칸에 들어가면 최대 5줄 펼쳐짐
- [ ] 패널·창 안에 스크롤바가 두 겹으로 생기지 않음
- [ ] 고르면 한 줄 + 수량 칸으로 바뀌고, 「바꾸기」로 다시 검색 상태가 됨
- [ ] 건 상세: 이미 있는 품목은 「이미 있음 · 수량에서 고치기」로 보이고, 눌러도 반응 없음
- [ ] 건 상세: 품목 추가는 목록 맨 아래 한 줄이고, 펼친 뒤 닫는 곳은 ✕ 하나
- [ ] 주문 추가 창: 비워도 되는 칸은 placeholder로만 안내함
- [ ] 수량 칸 모양이 ⑦ 고치기 목록과 같음
- [ ] 11px 미만 · slate-400 이하 텍스트 없음(placeholder 제외)
