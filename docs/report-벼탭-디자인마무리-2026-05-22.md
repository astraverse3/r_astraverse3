## 1. 요약

벼탭 디자인 점검의 "남은 것" 1~3번을 마무리. **착수 전 실측 결과 2·3번 대부분은 이미 완료 상태**여서 실제 작업은 2건으로 축소됐다.

| 커밋 | 내용 | 파일 |
|---|---|---|
| `5c1eed3` | statistics UI 강조색 → primary | 4 |
| `95f08f9` | 그룹체크 lazy-load 두번클릭 해소 | 1 |

## 2. 변경 사항

### 작업 A — statistics UI 강조색 → primary (`5c1eed3`)
- **stock-stats / output-stats / milling-stats-client**: 모바일 필터 활성칩(`bg-[#00a2e8]/10 text-[#00a2e8] border-[#00a2e8]/30`)·카운트뱃지(`text-[#008cc9]`) → `primary`
- **MillingTable** UI 요소: 도정종류 뱃지, 투입량 링크 hover, 행 hover → `primary`
- **MillingTable** 데이터 강조(생산량 링크·수율 뱃지)는 데이터색 `#0080c8`/`#006097`로 통일 — 차트와 같은 지표색, UI 액션과 의미 구분

### 작업 B — 그룹체크 lazy-load 두번클릭 해소 (`95f08f9`)
- `stock-list-client.tsx`에 `pendingSelect` 대기열 + `useEffect` 자동선택 도입
- 미로드 그룹 체크 1회 → 펼침+로드 → 로드 완료 시 자동 전체선택 (기존엔 재클릭 필요)
- 데스크탑·모바일 두 컴포넌트 동일 적용

## 3. 주요 결정 사항

1. **MillingTable 생산량/수율 = 데이터색 유지** (사용자 위임 → 옵션 A 채택). 차트가 이미 `#0080c8`를 쓰므로 "같은 지표"의 시각적 일관성 + UI(primary)/데이터(코발트) 의미 구분.
2. **다이얼로그·§3.4 헤더 액션 작업 제외** — 실측 결과 어제 PR1 색상 토큰화 때 이미 `primary`로 정렬 완료. 메모리의 "미적용"은 옛 정보였음.
3. **lazy-load는 별도 커밋 분리** — 디자인 문서가 "기능 변경이라 별도 PR" 권고한 대로.
4. **replace-colors.js 미사용** — 역방향 도구라 색상 치환에 부적합. 전부 수기 Edit.

## 4. 검증

- 작업 A: `next build` 통과(TypeScript OK, 19페이지 생성). statistics `#00a2e8`/`#008cc9`/`#007ab3` 잔존 0건. 데이터색 `#0080c8`/`#006097` 유지 확인.
- 작업 B: `next build` 통과.
- ⚠️ `npm run build`(=`prisma migrate deploy && next build`)는 Neon DB idle 타임아웃(P1002)으로 prisma 단계에서 실패 → `next build`만 단독 실행해 코드 검증. **코드 무관, DB 연결 이슈.**

## 5. 확인 필요 사항

- **작업 B 실동작 확인 권장**: 그룹 선택은 로그인+재고 데이터가 있어야 재현돼 빌드만으로는 런타임(자동선택/무한루프 없음) 100% 보장 불가. 원물재고 화면에서 미펼침 그룹 체크 1회로 펼침+선택 되는지 직접 확인 권장.
- `public/sw.js`는 빌드가 자동 갱신하는 PWA 산출물 → 커밋에서 제외함.
