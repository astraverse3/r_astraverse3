# 결과보고서 — 발주서 판매처리 D0 (파서 통일양식 대응)

_2026-08-18 · 계획서: `docs/plan/plan-발주서판매처리-단계6.md` §D0_

## 요약

발주서 파서가 구 양식·2채널 기준에 머물러 있어 통일양식(결정 #26) 발주서를 파싱하지 못하던 문제를 해소했다.
5채널 판별·3줄 헤더·발주일 추출까지 동작하며, 단위테스트 31건 전부 통과.

## 변경 사항

### 1. `lib/purchase-order-parser.ts` — 통일양식 대응

| 항목 | 이전 | 이후 |
|---|---|---|
| 채널 판별 | 시트명에 `이마트` 포함 → EMART, 나머지 전부 DELIVERY | `parseSheetName()` 신규. `채널_YYMMDD` 해석 → 고정 prefix 4종(이마트/택배/서울급식/해남급식) + 그 외 = 기업별 |
| 헤더 탐지 | `농가명`/`포장지`/`중량` 4줄, 소계·`(발주처)` 행 분기 | `포장지`/`중량`/`발주처` 라벨 앵커, 품목명 = 포장지 행 −1 |
| 수령인 빈칸 | 빈 문자열 유지 | 발주처 복사(택배·기업별 #26) |
| 발주일 | 없음 | 시트명 끝 `YYMMDD` → `yyyy-mm-dd` (존재하지 않는 날짜는 null) |
| 미인식 시트 | 조용히 skip | `skipped[]`에 사유와 함께 반환 |
| 파일 대표 채널 | 없음 | `channel`(혼합이면 null) · `channels[]` |

### 2. `app/actions/purchase-order.ts`

- `OrderRow.channel` / `OrderDetail.channel` → Prisma `PurchaseChannel`(5종). 기존엔 `'DELIVERY' | 'EMART'` 하드코딩
- **채널 혼합 파일 업로드 거부** — 파일 1개 = 채널 1개(사용자 확정)
- `orderDate`를 `PurchaseOrderUpload`·`PurchaseOrder`에 저장. 중복감지 키(`orderDuplicateKey`)에도 전달
- `UploadResult`에 `skipped[]` 추가(업로드 모달 경고용)

### 3. `prisma/migrations/20260818000000_purchase_channel_5types`

`PurchaseChannel` enum에 `MEAL_SEOUL`·`MEAL_HAENAM`·`CORPORATE` 추가(값 append만, 비파괴).
**Neon 실DB 적용 완료** — `prisma migrate deploy` 성공, `pg_enum` 조회로 5종 반영 확인.

### 4. 테스트

- `lib/purchase-order-parser.test.ts` — 통일양식 템플릿 기준으로 교체(14건). 채널 5종 판별·미인식 시트·수령인 복사·병합 펼치기·단일/혼합 채널 파일
- `lib/purchase-order-matcher.test.ts` — 구 양식 파일(`발주서.xlsx`) 의존 제거. 품목 목록을 기대표 키에서 순회(검증 내용 동일, 18종 전수)

## 주요 결정 사항

1. **구 양식 지원 폐기.** 통일양식이 실무 표준(#26)이고 구 양식은 파싱 경로가 완전히 달라, 두 양식 동시 지원은 복잡도만 늘린다. 구 양식 파일 `docs/resources/발주서.xlsx`는 자료로 남기되 테스트에서 뺐다.
2. **채널 혼합은 파서가 아니라 액션이 거부.** 파서는 순수 DTO 반환이 책임이므로 `channel: null`로 신호만 주고, 거부는 호출측(액션)에서 한다.
3. **매처 검증을 파일에서 분리.** 파서 양식이 바뀌어도 매처 회귀는 계속 잡아야 한다.

## ⚠️ 미결: 표준 양식 협의 중 (2026-08-18)

D0 작업 후 확인 과정에서 **표준 양식이 확정되지 않았음**이 드러났다. 사용자가 표준으로 지목한
`해남급식_20260619.xlsx`의 **`공장동06.19` 시트**는 D0에서 맞춘 통일양식 템플릿과 구조가 다르다.

| | `공장동06.19` (표준 후보) | `발주서-통일양식-템플릿.xlsx` (D0 기준) |
|---|---|---|
| A열 라벨 | 농가명 / 포장지 / 중량 / **소계** / **(발주처)** | 포장지 / 중량 / **발주처** |
| 품목명 행 | 농가명 행 −1 | 포장지 행 −1 |
| 품목명 내용 | `유기농 백미 천지향5세 (박태일)` — 농가명 괄호 포함 | `유기농 백미 천지향5세` |
| 소계·단가 행 | 있음(r4 소계, r13~16 단가·금액) | 없음 |

현재 `detectHeaderLayout`은 `발주처`를 정확 비교하므로 `(발주처)`인 공장동 양식을 **미인식으로 버린다**.
공교롭게도 D0 이전 파서가 읽던 양식이 공장동 쪽이다.

**사용자 결정(2026-08-18): 양식은 다시 협의해서 알려주기로 함.** 협의 결과에 따라
`detectHeaderLayout`과 파서 테스트만 재조정하면 되고, D0의 나머지(시트명 5채널 판별·발주일 추출·
수령인 복사·채널 혼합 거부·enum 마이그레이션·타입 확장)는 **양식과 무관하게 유효**하다.

### 음수 수량 — 일단 무시(현행 유지)

공장동 양식 r11에 `해남고등학교 | 보관요청 | -50`처럼 음수 수량 행이 있다. 현재 파서는 `qty > 0`만
수집하고 zod도 `positive()`라 이 행은 적재되지 않는다. **사용자 결정: 일단 무시.** 반품·보관요청을
재고에 반영하려면 차감 로직 설계가 별도로 필요해 범위를 키우지 않는다.

## 확인이 필요한 사항

1. **품목명의 농가명 괄호.** 공장동 양식은 `유기농 귀리 (박태일)`처럼 농가명이 품목명에 붙는다.
   매처가 괄호를 떼고 품종을 잡는지 미검증 — 못 떼면 전부 매칭실패가 된다. 양식 확정 후 확인.
2. **통일양식 품목명 23종 vs 매처 기대표 18종.** 신규 등장 품목(렌틸콩·율무·혼합곡·칼슘기장·새청무·
   귀리쌀·찹쌀현미 등)이 품종 마스터에 매칭될지 미검증. **D1 실업로드에서 확인**하고, 실패분은
   별칭 학습(#22)·SKU 마스터 보완으로 해소한다.
