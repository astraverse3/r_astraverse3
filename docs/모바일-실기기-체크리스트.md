### 실기기에서 나온 조치 (2026-09-08) — 넘침이 아니라 **동선** 문제였다

**① 「일부만 쓰기」를 화면이 안 알려줬다 → 백로그 §37 해소**
- 사용자 제보: 「일부만 재포장하는 기능이 없네」. **기능은 있었다**(재포장은 1→N이라
  남길 몫도 결과 줄로 만들면 된다). 화면이 침묵했을 뿐이다.
- 푸터에 **「남는 N kg ○○으로 남기기」** 상시 제안(잔여>0일 때). 누르면 규격·개수 1·중량=잔여
  줄이 자동 추가되고 그 줄은 앰버로 한 번 물든다(손대면 흰색).
- 🔴 **규격 판정을 두 번 고쳤다.** 처음엔 소스 규격을 그대로 물려받게 했다가
  「20kg인데 중량 630kg인 자루 1개」라는 **모순된 줄**이 나왔다. 지금 규칙:
  - 톤백·잔량(`weight=null`) → 소스 규격 그대로, 중량만 잔여
  - 고정 규격이고 잔여 < 자루 하나 → **잔량**
  - 고정 규격이고 잔여 ≥ 자루 하나 → **제안 안 함**. 「고치기」로 쓸 개수를 줄이는 게 정답
    (뭉쳐서 잔량으로 만들면 실물 자루 수와 장부가 어긋난다)

**② 손실 경고가 푸터를 대체한다**
- 경고를 본문에 얹었더니 푸터의 「남기기」가 아래 남아 **같은 버튼이 상하로 중복**됐고,
  이미 막힌 「재포장하기」도 활성처럼 보였다.
- `lossPrompt`가 열리면 기본 액션 셋을 렌더하지 않고 같은 앰버 푸터에
  계기판 + 문구 + 출구 2개로 갈아끼운다. 결과 목록은 `opacity-45 pointer-events-none`.
- 「취소」는 다이얼로그를 닫지 않고 **편집 상태로 되돌린다**(`lossPrompt=null`).
- 문구를 「그대로 진행할까요?」 → 「남는 몫도 줄로 만들어야」(또는 「고치기에서 개수를 줄여야」).

**③ `balance` warn 톤이 중립 회색이었다** → 앰버. ok=emerald / warn=amber / bad=red 3단.

**④ 🔴 쓸 재고를 기본 펼침으로 — 결정 #44를 뒤집었다**
- 「개수를 줄이는 건 예외 동선」이라 접어뒀는데, **접혀 있으면 개수를 줄일 수 있다는 사실
  자체가 안 보인다.** ①의 고정 규격 케이스에서 올바른 길이 화면 밖에 있게 된다.

**⑤ `available === 1` 안내** — 접힌 헤더에 「톤백 1개는 개수로 못 줄여요」(헛클릭 방지),
펼친 소스 행에 「아래에서 남길 몫을 줄로」.

> 🔴 **다음에 같은 증상이 보이면** 눈대중 말고 콘솔에서 바로 재라:
> ```js
> const d = document.querySelector('[data-slot="dialog-content"]')
> console.log(d.clientWidth, d.scrollWidth)   // 다르면 내부 넘침
> ```
> `scroll > client`면 넘침이고, 자식 트리의 `w=`를 훑으면 어느 칸이 부풀었는지 바로 나온다.

**⑥ 종결 (2026-09-08)** — ⑥-1~⑥-6 전부 실기기 확인 완료. 농가 관리 필터도 같은 결함이라 함께 고쳤다.

`min-w-0`은 칸이 부풀 때만 작동해 **현재 화면은 바뀌지 않는다.**

> ⚠️ **함께 나왔지만 결함은 아니었던 것 — 세로 제한(`max-h`) 없음**
> 검색·필터 다이얼로그 **12곳 전부 `max-h`가 없다.** 차감·재포장·이력은

> 입력행이 6~7개라 700px 안팎으로 **경계선**이었는데, 실기기(도정 필터)에서
> **하단 버튼이 잘 보였다 → 현시점 결함 아님.** 입력이 더 늘거나 가로 화면이면
> 다시 볼 것. 지금 고치지 않은 이유는 구조 변경이라 비용이 증상보다 크기 때문.
